# pbrain v0.4.1

A maintenance release. Search, sync and index formats are unchanged from v0.4.0, and upgrading does not rebuild any index.

## Install

Same archives as v0.4.0. The standard Linux amd64 archive includes CUDA (NVIDIA) and Vulkan (discrete AMD), and the Linux arm64 archive includes CUDA alone. Both link the fast fp16 CUDA kernels. The archives ending in `_cpu.tar.gz` contain an untagged CPU-only binary, the same as `go install`. The macOS archives are CPU-only, untested and unsupported for now.

To build the GPU binary yourself on Linux amd64, use
`go install -tags cuda,vulkan,eg2_combined,eg2_fp16 github.com/pkieltyka/pbrain/cmd/pbrain@v0.4.1`. On Linux arm64, use `-tags cuda,eg2_combined,eg2_fp16`.

## Changes

- **Release dependency audit.** CI now checks every release build (Linux amd64 and arm64, GPU and CPU, and macOS) for environment reads and direct output across every linked module, not only pbrain's own code. The check also covers standard-library helpers that consult the environment (`os.TempDir`, the user directory lookups, default HTTP clients and their proxies). A new matching source site fails CI. This is a best-effort Go-source audit, and its scope is documented in the spec. Reads that pbrain never reaches are pinned to their exact version and site. Two documented platform-runtime exceptions remain: Go's own `GODEBUG` CPU-feature handling, and the SQLite driver's C ABI environment snapshot on Linux. SQLite uses that snapshot for platform initialization; on Linux this includes `MODERNC_SQLITE_OFD_LOCK`, which affects only database-file locks. pbrain's databases are private and in memory, with in-memory temporary storage and journal, so they don't depend on it. pbrain publishes indexes under its own locks, and tests confirm this. ([#55](https://github.com/pkieltyka/pbrain/issues/55))
- **Direct downloads stated explicitly.** `pbrain import` fetches URLs without consulting `HTTP_PROXY`/`HTTPS_PROXY`. This was already the behavior, and it is now set explicitly and tested.

## Known issue

- **goinfer reads eight `GOINFER_*` debug variables at startup in the Linux GPU archives.** Linking goinfer's CUDA backend pulls in its decoder package, whose initializers read `GOINFER_DELTANET_TIMING`, `GOINFER_FAKEQUANT`, `GOINFER_FAKEQUANT_ACT`, `GOINFER_FAKEQUANT_EXPERTS`, `GOINFER_DECODE_TIMING`, `GOINFER_W4A8_SPLITHALF`, `GOINFER_CPU_FUSED_GATEUP` and `GOINFER_W4A8_BATCH` before `main`. These settings only affect goinfer's text-generation decoder, which pbrain never runs. They don't change embeddings or search results. This still breaks pbrain's rule against environment reads, so the audit lists the eight reads as known, and they will go away when goinfer ships the fix. The CPU-only and macOS archives are unaffected. Tracked upstream in [goinfer #70](https://github.com/pkieltyka/goinfer/issues/70).
