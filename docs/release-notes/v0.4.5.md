# pbrain v0.4.5

This release updates goinfer to v0.6.7. EmbeddingGemma 2 syncs on ordinary CUDA are now much faster on longer passages, and the vectors are unchanged. After upgrading from v0.4.4, only the CUDA fp16 indexes for the Google pack and Q8_0 need a rebuild.

## Install

The archive variants are the same as in v0.4.4. The standard Linux amd64 archive includes CUDA (NVIDIA) and Vulkan (discrete AMD), and the Linux arm64 archive includes CUDA alone. Both link the fast fp16 CUDA kernels. The archives ending in `_cpu.tar.gz` contain an untagged CPU-only build, like a plain `go install`. The macOS archives are CPU-only and still unsupported; CI cross-builds and audits them.

To build the GPU binary yourself on Linux amd64, use
`go install -tags cuda,vulkan,eg2_combined,eg2_fp16 github.com/pkieltyka/pbrain/cmd/pbrain@v0.4.5`. On Linux arm64, use `-tags cuda,eg2_combined,eg2_fp16`.

## Upgrading

Run `pbrain sync` after upgrading from v0.4.4 if you use the Google pack or Q8_0 on the CUDA fp16 path, adding `--personal` if you use a personal section. Those fingerprints include the pinned goinfer revision. The rebuild reuses the downloaded model files. bge-small indexes and the Gemma base-profile indexes for CPU, ordinary CUDA and Vulkan stay valid.

## Changes

- **Faster EmbeddingGemma 2 sync on ordinary CUDA.** The goinfer root, CUDA and Vulkan modules move to v0.6.7. The ordinary CUDA path now uses transposed attention for eligible batches whose longest prepared input reaches 128 tokens. On an RTX PRO 6000, fresh 219-passage syncs went from 18.52 to 6.86 seconds for UD-Q6_K_XL (11.82 to 31.93 passages/s). Q8_0 with `semantic.cuda_precision = "fp32"` went from 18.39 to 6.79 seconds (11.91 to 32.27 passages/s). On 59 passages, the times went from 2.99 to 2.49 seconds and from 3.02 to 2.56 seconds. Sampled GPU peaks stayed at 2,130 MiB on 219 passages and 2,094 MiB on 59. The Google and Q8_0 fp16 controls stayed within 1% of their previous wall times. All compared vectors were bit-identical. ([#66](https://github.com/pkieltyka/pbrain/issues/66))
- **Compared with bge-small.** With model verification and loading included, bge-small on four CPU cores took 19.52 seconds for 219 passages (11.22 passages/s) and 1.81 seconds for 59 passages (32.54 passages/s). On the 219-passage fixture, the tested Gemma CUDA syncs were 2.85× to 3.27× faster than bge-small. On the 59-passage fixture, bge-small finished first. [Benchmark matrix](https://github.com/pkieltyka/pbrain/blob/v0.4.5/internal/cli/README.measure.md#goinfer-v067-cuda-sync-66)
