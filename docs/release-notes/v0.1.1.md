# pbrain v0.1.1

v0.1.1 is the first published release. v0.1.0 was tagged on 2026-11-21 and never published: its
release run stopped at a failing test (see "Tests" below).

## Install

```sh
go install github.com/pkieltyka/pbrain/cmd/pbrain@v0.1.1
```

Or download a binary from this release. While the repository is private, both need repository access.

| Binary | Status |
| --- | --- |
| Linux, amd64 | Supported; CI tests it. |
| Linux, arm64 | Built for every release; not tested in CI. |
| macOS, amd64 and arm64 | Built, **untested and unsupported for now**. |

## Changes since v0.1.0

- **Fixed: `model_path` reached through a symbolic link (#21).** A `model_path` in `personal.toml`
  whose folder lay behind a link was refused with `invalid_config`. A folder named from outside
  pbrain is now resolved once, links included, and links are refused only below it, as the brain,
  the personal section and the cache already were.
- **Platforms: Linux only for now.** pbrain is tested and supported on Linux. CI no longer runs the
  tests on macOS; the macOS binaries are still built and attached to the release.
- **Tests (#2).** `TestMutationFollowsScannedIdentity` could fail on ext4 when a freed inode number
  was reused, and it stopped the v0.1.0 release run. The test now stages its replacement file beside
  the original. pbrain's behaviour is unchanged.

## Semantic search models

- `bge-small-en-v1.5` is the default, as in v0.1.0: a 134 MB download on the first `pbrain index`.
- `embeddinggemma-2` stays selectable with `model = "embeddinggemma-2"` under `[semantic]` in
  `pbrain.toml`. Its full-size figures are deferred until the model is cleared for use. What was
  measured: a first index at 0.902 passages a second on four CPUs, a projected 15 hours for the
  5,000-item, 50 MB test brain, in a run that was not finished.

## Measured speed

Measured with `bge-small-en-v1.5` on the 5,000-item, 50 MB test brain (4,500 shared and 500 personal
items), on four cores of an AMD Ryzen 9 7950X under Linux:

| Measurement | Time | Peak memory |
| --- | --- | --- |
| First `pbrain index` | 1 h 18 m (10.31 passages a second) | 1,315 MiB |
| `pbrain index` after one new note | 0.68 s | 472 MiB |
| Warm `search --semantic`, shared view (4,500 visible items) | 291–298 ms | about 505 MiB |
| Warm `search --semantic`, personal view | 321–326 ms | about 550 MiB |

The search figures are medians of ten warm runs, with and without `--bm25`, from the release candidate
`cbaaa0e`; later commits change no code in the binary. The index was built with the earlier `9f53910`
build. Lexical search and `get` were not measured again on this machine: on four CPUs of an Intel
Core Ultra 7 255H they took 135–189 ms and 134 ms, and the first index there took 1 h 41 m.
[Method and both machines' full tables](https://github.com/pkieltyka/pbrain/blob/v0.1.1/internal/cli/README.measure.md)

## Known issues

- **macOS: two commands that first use a section at the same moment (#1).** When the section's
  lock file does not exist yet, as in a new brain or a new personal section, and two pbrain
  commands start together, one can fail at once with `io`: "another pbrain command holds this
  section's lock; try again". Two `pbrain index` runs that share a new model cache can fail the
  same way with "the model lock cannot be taken". Run the command again: it works, and the fault
  cannot recur once the lock file exists. Linux is not affected. A fix exists and is not in this
  release.
- **macOS is otherwise untested.** No Mac measurement has been made, and the arm64 Mac binary has
  never run a model in our hands.
