# pbrain v0.4.7

This release makes Metal sync batch passages on a base Apple M4 and moves goinfer to v0.6.9. It also fixes a lock race on macOS. After upgrading from v0.4.6, the CUDA fp16 indexes for the Google pack and Q8_0, and Q8_0 Metal indexes, need one sync to rebuild.

## Install

The archives are laid out as in v0.4.6. The standard Linux amd64 archive includes CUDA (NVIDIA) and Vulkan (discrete AMD), and the Linux arm64 archive includes CUDA alone. `darwin_arm64` is the Metal build and `darwin_arm64_cpu` the untagged CPU-only build. The archives ending in `_cpu.tar.gz` contain an untagged CPU-only build, like a plain `go install`. All builds are cgo-free.

To build the GPU binary yourself on Linux amd64, use
`go install -tags cuda,vulkan,eg2_combined,eg2_fp16 github.com/pkieltyka/pbrain/cmd/pbrain@v0.4.7`. On Linux arm64, use `-tags cuda,eg2_combined,eg2_fp16`. On Darwin arm64, use `CGO_ENABLED=0 go install -tags metal github.com/pkieltyka/pbrain/cmd/pbrain@v0.4.7`.

The Darwin archive binaries are not signed or notarized. On an Apple M4, a copy of the v0.4.6 Metal archive binary marked with a browser-style quarantine attribute did not finish `--version` within 20 seconds, and `spctl` rejected it. A browser download was not tested. Binaries built with `go install` on that M4 ran normally. Signing is deferred ([#70](https://github.com/pkieltyka/pbrain/issues/70)).

## Upgrading

Run `pbrain sync` after upgrading from v0.4.6 if you use the Google pack or Q8_0 on the CUDA fp16 path, or Q8_0 on Metal. Add `--personal` if you use a personal section. Those fingerprints include the pinned goinfer revision. The rebuild reuses the downloaded model files. Base-profile indexes, including bge-small, stay valid.

## Changes

- **Metal sync batches on a base Apple M4.** `embeddinggemma-2-q8-0` sync now embeds up to four passages per GPU forward. On the 219-passage fixture, batching raised throughput from 9.44 to 10.23 passages/s (8.3%), with about 200 MB more peak process footprint. A first sync of the 5,000-note corpus took 1 h 21 m, against 1 h 28 m on v0.4.6. Batched and single-passage vectors matched bit for bit on the fixtures, so batching keeps the same index fingerprint. Other Apple Silicon Macs keep one passage at a time. Set `PBRAIN_METAL_BATCH=0` to turn batching off. [Measurements](https://github.com/pkieltyka/pbrain/blob/v0.4.7/internal/cli/README.measure.md#metal-batching-on-the-base-m4-72) ([#72](https://github.com/pkieltyka/pbrain/issues/72))
- **goinfer v0.6.9.** The goinfer root, CUDA, Vulkan and Metal modules are aligned at v0.6.9. On the RTX PRO 6000, all 118 rebuilt CUDA fp16 vectors matched their v0.6.8 counterparts bit for bit. ([#72](https://github.com/pkieltyka/pbrain/issues/72))
- **macOS: two commands that first use a section at the same moment no longer fail.** When a section's lock file or a model cache's lock file did not exist yet and two pbrain commands started together, one could fail at once with `io`. The lock file is now created exclusively and the open retried. A lock that cannot be taken for a reason other than waiting now says so instead of naming another command. ([#1](https://github.com/pkieltyka/pbrain/issues/1))
- **macOS is tested in CI.** Every change now runs the Go suite on macOS arm64, including the race detector and the release archives, and the native suite passes on an Apple M4. [Apple M4 measurements](https://github.com/pkieltyka/pbrain/blob/v0.4.7/internal/cli/README.measure.md#rule-3-and-full-size-sync-refresh-32) ([#9](https://github.com/pkieltyka/pbrain/issues/9))
