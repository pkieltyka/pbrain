# pbrain v0.4.3

This release updates goinfer to v0.6.6, and pbrain now uses goinfer's own per-device capability report to choose the CUDA fp16 fast path. Upgrading from v0.4.2 changes only the CUDA fp16 fingerprints for the two Gemma models. Those indexes are stale until sync rebuilds them. bge-small indexes and Gemma CPU, CUDA fp32 and Vulkan indexes stay valid.

## Install

The archive layout is the same as in v0.4.2. The standard Linux amd64 archive includes CUDA (NVIDIA) and Vulkan (discrete AMD), and the Linux arm64 archive includes CUDA alone. Both link the fast fp16 CUDA kernels. The archives ending in `_cpu.tar.gz` contain an untagged CPU-only build, like a plain `go install`. The macOS archives are CPU-only, untested and unsupported for now.

To build the GPU binary yourself on Linux amd64, use
`go install -tags cuda,vulkan,eg2_combined,eg2_fp16 github.com/pkieltyka/pbrain/cmd/pbrain@v0.4.3`. On Linux arm64, use `-tags cuda,eg2_combined,eg2_fp16`.

## Upgrading

If you upgrade from v0.4.2 and use a Gemma model on the CUDA fp16 fast path, run `pbrain sync` after upgrading, adding `--personal` if you use a personal section. The fast path is the default on fp16-enabled CUDA builds (the Linux GPU archives), when the selected NVIDIA device reports `cuda-eg2-fp16` as runnable (compute capability 8.0 or newer). Set `semantic.cuda_precision = "fp32"` to opt out. The CUDA fp16 fingerprints include the pinned goinfer revision, so these indexes are stale after the upgrade until you sync. The rebuild reuses the downloaded model files. On the 59-passage fixture, vectors from the v0.4.3 rebuild matched bit for bit those from the v0.4.2 source build, which is pinned to goinfer v0.6.5, for both the Google Gemma pack and the Q8_0 GGUF.

## Changes

- **goinfer v0.6.6.** The goinfer root, CUDA and Vulkan modules move together to v0.6.6. ([#64](https://github.com/pkieltyka/pbrain/issues/64))
- **Fast-path eligibility from goinfer.** pbrain now decides whether a GPU can use the CUDA fp16 path from goinfer's per-device report, before loading any model weights. pbrain no longer runs its own capability probe. goinfer's CUDA backend still uses gocudrv v0.3.2, which pbrain now depends on only indirectly, through that backend. ([goinfer #68](https://github.com/pkieltyka/goinfer/issues/68))
- **Clearer fp16 attach errors.** As before, once sync chooses the fp16 path for a device, it attaches to that device by UUID and doesn't switch to another profile if the attach fails. The two failure causes now give separate errors that name the selected UUID: the device is missing, or it can't run the fp16 path.
