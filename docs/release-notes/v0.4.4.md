# pbrain v0.4.4

pbrain no longer depends on aikit. The bge-small embedder's BERT encoder and WordPiece tokenizer are now part of pbrain. The EmbeddingGemma 2 GGUF models can now index on AMD GPUs through Vulkan, and there is a new opt-in UD-Q6_K_XL model. Upgrading from v0.4.3 does not rebuild any index: every existing model and index fingerprint is unchanged.

## Install

The archive variants are the same as in v0.4.3. The standard Linux amd64 archive includes CUDA (NVIDIA) and Vulkan (discrete AMD), and the Linux arm64 archive includes CUDA alone. Both link the fast fp16 CUDA kernels. The archives ending in `_cpu.tar.gz` contain an untagged CPU-only build, like a plain `go install`. The macOS archives are CPU-only and still unsupported; CI cross-builds and audits them. Every archive now includes `licenses/aikit/LICENSE` and `licenses/aikit/NOTICE` for the code taken from aikit.

To build the GPU binary yourself on Linux amd64, use
`go install -tags cuda,vulkan,eg2_combined,eg2_fp16 github.com/pkieltyka/pbrain/cmd/pbrain@v0.4.4`. On Linux arm64, use `-tags cuda,eg2_combined,eg2_fp16`.

## Changes

- **bge-small code moved into pbrain.** pbrain now has its own copy of what bge-small needs from aikit v1.79.1. That's the loader for verified model bytes (including safetensors), the FP32 BERT forward pass, the WordPiece tokenizer, and their CPU math kernels for amd64 and arm64 with a portable fallback. `github.com/pkieltyka/aikit` is no longer a module requirement, and a build check fails if it comes back. ([#62](https://github.com/pkieltyka/pbrain/issues/62))
- **Same vectors, no rebuild.** Before aikit was removed, pbrain recorded aikit's tokenizer IDs and vectors for 113 test inputs. pbrain's copy matches them bit for bit, in single-text and four-worker calls, on native Linux amd64 (AVX2/FMA) and on Linux arm64 emulated with QEMU (NEON). Existing bge-small indexes and cached vectors stay valid.
- **bge-small CPU throughput.** The test embedded the same 59 passages on four Ryzen 9 7950X cores. The new code ran at a median of 35.34 passages/s, against 35.57 for the v0.4.3 source. That is 0.65% lower, across three matched pairs whose ranges overlapped. The timer excluded model verification and loading.
- **EmbeddingGemma 2 GGUF on AMD.** Q8_0 and the new opt-in UD-Q6_K_XL row can sync on Vulkan in the standard Linux amd64 archive. To select Q6, set `semantic.model = "embeddinggemma-2-ud-q6-k-xl"` in `pbrain.toml`. Its first sync fetches one verified 249 MB GGUF, converted by Unsloth from Google's EmbeddingGemma 2. Q6 runs on CPU, ordinary CUDA (it has no fp16 fast path) and Vulkan. Use `pbrain sync --device vulkan` to choose the AMD GPU explicitly. Search still runs on the CPU, and bge-small is still the default. On an RX 9060 XT, both rows passed the CPU/Vulkan cosine check and the same-device batch-layout check, which requires byte-identical output. The lowest CPU/Vulkan cosine was 0.9999999999961869 for Q6 and 0.9999999999975044 for Q8. ([#65](https://github.com/pkieltyka/pbrain/issues/65))
- **What syncs after switching.** Selecting Q6 needs a sync to build its separate index and cache. Vulkan can reuse existing Q8_0 vectors from a CPU or CUDA fp32 index. Moving a CUDA fp16 Q8_0 index to Vulkan changes precision, so sync rebuilds those sections.
