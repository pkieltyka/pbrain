# Reuse a CPU query model across agent calls

**Recommendation for #81.** Ship `pbrain batch` first, after #80's tool catalog lands and the benchmark below demonstrates a gain. One child process per script gives a code-mode client both streaming and adaptive calls with ordinary pipes. Prototype `pbrain mcp` against the same executor for comparison. A client that keeps an MCP session across agent turns can amortize the first model load across scripts too. That is the reason to ship MCP if the agent evaluation demonstrates demand. Neither design needs a daemon, listening socket or background indexer. The v0.5.0 release can proceed independently.

Q8_0's 586.6 ms on four Ryzen cores measures verification, loading and **one query**, with the model file already in the OS page cache. It is not the process-launch time or a latency saving we can promise. A warm client still pays for authorization, fresh disk state, query embedding, scoring and rendering. [Measurement and memory context](remove-bge.md#what-makes-q8_0-a-costly-default)

| Decision | JSONL batch | Session-scoped stdio MCP |
|---|---|---|
| Calling code | Spawn once with piped stdin/stdout/stderr. For each call write one JSON line, flush, read one correlated result. A search can choose which get to write next. One shell invocation per query loses the benefit. | The harness launches one subprocess per workspace/client session, initializes once, obtains tools once and issues `tools/call` repeatedly. Code-mode uses the harness's MCP tool bridge or keeps one MCP client open. Starting an MCP server for each tool loses the same benefit. |
| Cost and lifetime | No handshake. Closing stdin after a script's last request drains accepted work, flushes replies and exits. Multiple scripts pay multiple cold starts. | Handshake and tool descriptions cost bytes/tokens once, depending on harness caching. Longer reuse between turns trades against resident memory. Close stdin/disconnect to end the session. |
| Failure and cancellation | A malformed line can fail independently. Interrupting a blocked active call cancels the **process/session**. No per-ID cancel protocol in v1. | Protocol separates method/framing errors from tool outcomes and supports cancellation by ID. A reader must stay responsive during a slow tool call. |
| Dependencies | Existing Go JSON, buffered I/O and CLI command core. | More interoperability work. Evaluate a maintained Go MCP SDK in the prototype, including binary-size and release-audit impact. Adding a production dependency or shipping this second interface is an operator decision. |

## One catalog and command path

Use #80's proposed `internal/cli.Catalog(features)`, `Bind(tool,args,features)` and `Call(ctx,env,tool,args,features,onNotice) Result` for both transports. Tool names are `pbrain_<command>`, inputs use the exact schema property names, and the catalog version is `pbrain-tools/1`. Bind produces argv with `--json`, flags in equals form and a literal `--` before operands, then calls the real parser. A query containing spaces or starting with a dash stays one operand. Both transports offer exactly the callable catalog, including `sync` with its first-sync guidance; transport commands, schema, skill, help and version are outside it. No recursive session tools or shell. `Env.Stdin=nil` on every tool: add takes `body` or `body-file`, import accepts its catalog input, and relative paths go through the normal guards from the launch directory. Test CLI and both projections against identical catalog fixtures; the MCP listing must equal #80's MCP projection. Leave OpenAI/Anthropic projection choices to #80.

The only new execution state in `cli.Env` is the optional CPU query-model slot. Both use #80's Call with fresh per-request buffers and clock; it returns `Result{Output, Error, Notices, Exit}`. Keep `finish`'s handling of committed writes, check findings and delete previews. The ordinary CLI keeps its stdout/stderr behavior and no warm slot. If Call captures diagnostics, provide an optional sink for already sanitized, structured notices as they occur, as well as the ordered final list. No raw adapter stderr reaches protocol clients. `cmd/pbrain` owns real streams, startup environment, working directory and signals. A request-local `brain` selector goes through normal discovery; no request can replace the process environment or set a default for later calls.

**Batch framing (proposed v1).** One UTF-8 JSON object per physical line: `{"id":"q1","name":"pbrain_search","arguments":{"query":"locking","semantic":true}}`. An optional top-level `schema` accepts exactly the supported catalog version; reject an unsupported version before binding. A nonempty string ID is a correlation value, not an idempotency key. Write and flush one ordered terminal line per input, with `id`, `exit`, `notices` and optional `result` and `error:{code,message}`. Use `id:null` for an unreadable ID. Blank/malformed records, invalid UTF-8, arrays, duplicate keys and unknown envelope/argument fields get a per-request usage diagnostic; continue at the next LF. Accept a final complete record without LF. Use bounded framing, e.g. 32 MiB of encoded request bytes, sufficient for a 5 MiB inline input even when every byte needs a six-byte JSON escape. Drain an oversize line without retaining it. Enforce the ordinary decoded CLI limits as well. Read/execute/flush one call at a time and use pipe backpressure. Stream live notice lines with the request ID on stderr, including notices before downloads or writes, using the same sanitizer; the terminal notice sequence is authoritative. A script drains both pipes concurrently. A cleanly delivered stream exits 0 even with individual tool failures. A transport I/O failure stops intake and exits nonzero. Reconcile a possibly committed write by reading back before retrying.

**MCP mapping.** Pin and negotiate a specific protocol revision in the prototype (2025-11-25). Use newline-delimited JSON-RPC 2.0 over stdio, with initialize/initialized, ping and tools/list/call. Only protocol messages on stdout. Malformed JSON, invalid RPC envelope or unknown protocol method get standard JSON-RPC errors. Unknown tool gets invalid params. A known tool with no output and a validation or domain failure returns `isError:true` with the safe code/message. Follow #80's document-presence rule. Both a `check` report with findings (exit 1, no Error) and a `delete` preview (exit 1 plus `confirm_required`) return the document with `isError:false`; preserve the exit, terminal diagnostic and explicit need for confirmation so an agent cannot mistake a preview for a deletion. Successful `structuredContent` matches #80's advertised output schema; use #80's object wrapping if required, and provide the compact JSON text fallback for clients that read only content. Preserve exit status, terminal diagnostic and notices as namespaced result metadata and surface actionable notices/errors in text for clients that discard metadata. Never encode failure as a successful empty search. Use request-associated live progress when the client provided a progress token; otherwise deliver notices in the final result. Preserve existing handler ordering of notices and actions. See the [MCP tools](https://modelcontextprotocol.io/specification/2025-11-25/server/tools), [stdio](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports), [lifecycle](https://modelcontextprotocol.io/specification/2025-11-25/basic/lifecycle) and [cancellation](https://modelcontextprotocol.io/specification/2025-11-25/basic/utilities/cancellation) contracts.

**Client compatibility gate.** The prototype and #80’s MCP evaluation target **Claude Code 2.1.332 and Codex CLI 0.172.0**, using their native stdio MCP clients. On 2026-11-26 both listed a local fixture tool after the server selected `2025-11-25`. A network-isolated probe with disposable config, no credentials and no model turn recorded these exchanges:

| Client control path | Wire evidence |
|---|---|
| Claude Code `claude mcp get wireprobe` | Tried `server/discover`, received JSON-RPC method-not-found (−32601), then offered `2025-11-25` in `initialize`, sent `notifications/initialized` and `tools/list`, and reported connected. |
| Codex CLI `app-server`, control method `mcpServerStatus/list` | Offered `2025-06-18` in `initialize`, continued after the server returned `2025-11-25`, sent `notifications/initialized` and `tools/list`, and returned the advertised fixture tool. |

This proves discovery and negotiation on those builds. Before scoring agents, run the actual selected harness binaries against the prototype **and** #80’s measurement shim. Each must complete that handshake and list the catalog, then execute a fixture search and a follow-up get over the same child. Record exact client build, offered and accepted revisions, call IDs, outcome and process start count. Repeat on any version change. A missing handshake, wrong result or hidden CLI fallback fails the client gate; exclude it from MCP latency and token comparisons and report the incompatibility. A `2026-07-28`-only client is outside this prototype. Its per-request metadata and `server/discover` require another wire implementation; a shared tool descriptor does not establish interoperability. Include a discovery-only negative test with no tool or model side effects. [MCP compatibility across revisions](https://modelcontextprotocol.io/specification/2026-07-28/basic/versioning)

One active tool per session. For MCP use one reader, a single serial worker and a serialized writer. Bound the pending FIFO (initially one additional call); return a retryable server-busy protocol error for overflow **before execution**. Read control messages while busy. Cancel queued work by removing it, active work via its own context. Suppress the cancelled response per MCP, ignore late cancellation, and join workers before reuse or close. A CPU forward may return only at its next cancellation boundary. On MCP disconnect or process interrupt cancel pending/current work, wait for `Source.Close` and other deferred cleanup; committed writes keep today's checkpoint semantics. Never automatically replay a mutation or promise rollback after publication. No interleaving of two domain commands within a session. Independent processes still contend through normal filesystem locks.

Skip an MCP batch tool initially. A code-mode loop can use ordinary tools/call with the same warm model. If real clients spend significant time/tokens on repeated request envelopes or expose only one tool invocation per agent turn, consider one separately cataloged wrapper after measurement: bounded ordered calls, per-call results, per-call personal flags, no nesting or shared transaction. It changes round trips, not embedding throughput.

## What survives a call

1. **Fresh inputs.** Each invocation gets a fresh flag set and time snapshot and calls `brain.Open`, `RequireView` where applicable and the existing handlers. Re-read configuration, named roots, exposure checks, Git ignore state, item catalog, graph and manifest/SQLite generation. A command observes the same snapshot/races as a new CLI invocation started at that instant. `skill` and other commands currently independent of a brain retain that property. Launch cwd/env are fixed like a child process's; restart to change them.
2. **Personal is explicit per call.** Derive view exclusively from this request. Shared reads remain shared after personal success, failure or cancellation. `personal:true` on a supported read selects the normal combined view. Re-run both exposure and availability checks before disclosing anything. Preserve the existing audience-settings command exception and write-destination rules, including rule-routed personal writes without granting personal read access. No personal page, ID resolution, vectors, continuation, diagnostic or authorization decision retained for another request; use only that request's view for disclosure. Do not cache results or log bodies/queries. One session serves one trusted local caller; the personal flag selects a view and is not an authentication mechanism.
3. **Model lease.** In `internal/semantic/source.go`, keep `Start.check`, parallel model/index tasks, `Attach`, `CatchUp`, `Score` and `Close` lifetimes per request. Pass an optional session-owned search runtime through `cli.Env` → `semanticOptions` → `semantic.Options`; use it only from `Source.runModel`. On every eligible call perform exactly today's `embed.VerifyManaged(..., ManagedSearch)` for managed files or `embed.Verify` for `model_path`, including opening the current regular files and reading authenticated bytes. Reuse only after successful verification of the same release model name, fingerprint and complete ordered file pins, with the same in-process registry and zero/CPU `OpenOptions`. A protected identical replacement is reusable after verification. A missing/unsafe/wrong file, changed model, invalid cache location, stale manifest or revoked guard follows the ordinary outcome; a retained encoder can never bypass a failed check. Never use path, mtime, inode or a filesystem watcher as proof of identical bytes. This first implementation saves model decode/open; it intentionally still pays the authenticated read/copy and, for unsealed or external files, the SHA-256. Time those separately. Any cheaper verification policy needs its own design.
4. **Ownership.** On a miss, close the old CPU runtime, open the new one from the verified Artifact with `Registry.Open`, then store the CPU handle alone. On a hit immediately discard the newly verified Artifact. A proposed `semantic.QueryRuntime` in `internal/semantic/query_runtime.go` has one `acquire(ctx, registry, artifact)` operation returning the embedder and a release callback, plus idempotent `Close`. Replace the unconditional embedder close in `Source.Close` with the appropriate release after both background tasks finish. Standalone release still closes the model; session release returns the slot. An embedding/adapter failure poisons the slot and closes it after the call. Cancellation never lends an embedder to another call until its worker has stopped. CPU query and permitted CPU catch-up may borrow it within one search. Evict before an actual sync build so GPU/CPU writers never share it or pay double residency. Status, lexical reads and sync qualification retain existing strict/open-free paths. Use the existing CPU writer-profile restrictions; read supported completed profiles with CPU queries, skip catch-up into profiled indexes.
5. **Locks and memory.** A semantic request still does the equivalent of `runSearch` in `internal/cli/read.go`. Read current index generations and check title/body coverage. For catch-up, keep the 20-item/20-new-passage bounds, one `TryLock` per applicable section, under-lock manifest comparison, and two-second admission window. Busy or changed generations leave items uncovered normally. Sync and writes take existing locks and publish in their current order. End every request with no transaction, lock, SQLite DB, named directory or catalog retained. Keep at most one CPU model with its tokenizer; idle batch retains it until EOF. For an MCP prototype evict after 60 s without a borrower (monotonic timer, serialize eviction with acquire/release). Close on normal shutdown; no forced GC per query. One Q8 rule-3 process peaked at 1,035 MiB; that is neither the idle retained size nor a measured full-size Q8 search peak. Measure both the model and transient index/verification memory. Multiple simultaneous client processes each pay the cost. Keep transport/framing overhead distinct from the existing per-result budgets. Never combine multiple personal/shared calls into one unfiltered response.

## Build order and proving tests

1. After #80, add table-driven CLI/session equivalence tests in `internal/cli` using a fake model, fresh brains and fixed clock/randomness. Run the same valid and invalid catalog cases through canonical CLI JSON, batch and the MCP prototype. Compare result, exit, error, ordered notices, citations, truncation and continuation. Include check-with-findings, delete preview, after-write notice, a multiline `body` escaped in one record followed by a body-less add and another command, semantic fallback and schema drift. A parser test must prove one malformed/oversize record cannot consume the next one.
2. Implement the optional runtime lease. With instrumented registry/files, count one CPU open for N semantic reads, N verifications, zero opens for lexical-only or absent indexes. Test close counts, multiple model rows, config changes, same-size corrupt replacement with restored mtime, missing file, alternate brain/model_path, cancellation during open/forward, eviction and disconnect. Race-test ownership and prompt shutdown with fakes. Check no process-wide encoder leaks into ordinary CLI invocations.
3. Interleave operations in a live session with a second process editing, deleting, publishing, holding an index lock, changing the selected root or making the personal folder exposed. Assert fresh-command parity for shared → personal → shared and personal-failure → shared (including errors/notices), skipped profiled catch-up, in-bound and over-bound gaps, and no duplicate writes on a lost response. Test relative dates across a day boundary. Exercise MCP initialization/list/call, unknown names, malformed RPC, backpressure, queued/active cancellation, EOF and broken pipes with an independent protocol test client, then run the named-harness compatibility gate above. Keep transport definitions generated/validated from #80 as the toolset evolves.
4. **Measure before choosing a second public interface.** Same binary/build, Q8_0 bytes and ready retrieval fixture, logical cwd, CPU affinity (0–3 on pax), GOMAXPROCS=4, warmed OS pages and quiet host. Identical list of distinct semantic queries, same views, limits, request order and index generation. Use N=1, 5 and 20 for break-even, plus N=100 for steady-state tails. Rotate three arms across five independent sessions per N: one fresh CLI process per query; one fresh JSONL child per script; one fresh initialized MCP session per script. Test a reused MCP session across consecutive scripts separately. Include full spawn/handshake/list/transcript costs in client totals, individual first-response latency and subsequent per-call p50/p95, positions/query lengths, tool round trips, bytes/tokens sent to the agent, errors and ranked/cited output equality. Do not mix overlapped per-stage work with wall time. Record wall for verify/read/hash, CPU open/decode, first query, scan/index/score and IPC; report settled idle RSS and peak RSS per process, CPU time, model-open counts, cleanup at EOF/idle. Use the same measurements for both managed sealed and strict/unsealed cohorts. Include lexical control, a separate externally edited/catch-up sequence and an adaptive search → get chain. Reset mutable fixtures per arm. Compare (#80's same agents/tasks) code-mode script versus MCP-native client turn counts. Record the harness, model/version, reasoning setting and visible schema/skill tokens. Keep the transport microbenchmark independent of LLM latency. No hardware run is part of this planning task.
5. Report the smallest N where total latency beats repeated CLI and the absolute saving/remaining verification and scan cost. Recommend batch for release only if correct outputs/guards hold and paired N=20 total and warm median improve outside repeat variation without unbounded memory growth. Recommend adding MCP if it also sustains that gain and real MCP clients benefit from cross-turn reuse or materially fewer host/model round trips. A speed tie between the two persistent arms is expected when their only difference is framing. Record the numbers in `internal/cli/README.measure.md`; document the chosen command, notices/exit/lifetime, scope of model reuse and code-mode invocation in `components/cli.md`, `components/semantic.md`, architecture §8.7 and the bundled skill before release.
