# #61 · Default CUDA precision for EmbeddingGemma 2

**Decision.** Qualify `cuda-eg2-fp16` as the default CUDA document encoder for both Google EmbeddingGemma 2 and Unsloth Q8_0 on compute capability (CC) ≥8.0. An explicit `semantic.cuda_precision = "fp32"` selects the current product CUDA kernel, `cuda`. Model files, downloads, tokenizer, 768 stored float32 coordinates, 0.72 cutoff and CPU query runtime stay the same. Document vectors receive distinct identities. Implement after #59 and plan integration, against the three goinfer v0.6.4 tags at `ab2721995e027c8ce6630396c922916cb2357a1d`.

#60’s one-layout replay found zero bit-identical fp16/fp32 vectors out of 200 **for each row**, despite minimum cosine 0.9999998167 (Google) and 0.9999994520 (Q8). Existing pbrain CUDA processed 6,754/6,796 positions/s including preparation and packing. The goinfer-only fp16 forwards reached 44,863/45,347 positions/s. Neither number establishes the speed or retrieval quality of an fp16 pbrain index. [#60](https://github.com/pkieltyka/pbrain/issues/60) · [Upstream replay and build-identity requirement](https://github.com/pkieltyka/goinfer/blob/v0.6.4/docs/measurements/eg2-fp16-composed-2026-11-22.md)

## 1. Define policy, writer identity and upgrade behavior

- In `internal/brain/config.go` and `brain.go`, add the optional project TOML key `[semantic] cuda_precision`. Accept exactly the strings `fp16` and `fp32`; explicit empty, wrong type or other value gives `invalid_config`. When omitted, use one release-wide default, identical even in a CPU-only binary. Start the implementation with fp32 as default; flip it to fp16 only at the rollout gate below. A valid setting has no effect on bge-small or semantic-off. No precision flag, environment override, second model name or new model folder.
- Distinguish the **request** (the setting after applying the release default) from the **writer profile** (the precision actually used for a section). FP32 retains the row’s existing model fingerprint. FP16 uses lowercase hex SHA-256 of the ASCII concatenation `"pbrain-vector-profile-v1\n" + baseFingerprint + "\ncuda-eg2-fp16\n" + goinferRevision`, with **no trailing newline**. Use the qualified full revision above, independent of GPU ordinal, machine, or pbrain’s own Git hash. Add a source/pin test keeping the revision in step with the root and CUDA modules. Future goinfer pins require requalification and a new fp16 identity. The already-qualified legacy fp32 namespace stays compatible with existing CPU, plain CUDA and eligible Vulkan writers.
- Keep `embed.Model.Fingerprint` as the verified artifact row’s base identity. Add a row capability such as `Model.CUDAFP16Fingerprint string`, populated for the two Gemma rows in **all** binaries and empty for other models. Carry a separate resolved vector fingerprint into the index and cache. Factor `IndexFingerprint`’s hash-of-chunker-and-fingerprint so existing callers retain their legacy value and the builder can pass the resolved value directly. Never mutate the model handed to `Registry.Open` or fold precision into `FolderName`. Add golden tests for both rows, both directions, changed runtime revision, and unchanged raw file folders and fp32 fingerprints.
- Keep manifest format 3 and SQLite format. For Gemma only, write one optional string `cuda_precision_request:"fp16"` when that policy produced the generation (including a fallback to fp32). Omit it for fp32 requests. Absence in older manifests means fp32 request. The existing manifest and DB-meta fingerprints identify the **effective** mode independently. Validate present fields strictly. FP32 request admits only its base index fingerprint; fp16 request admits a correctly marked generation with either its current fp16 fingerprint or that row’s base fingerprint (CPU/old-card fallback). Old or unknown fp16 revisions are stale. A manifest marker alone cannot make an arbitrary fingerprint acceptable. Keep the usual DB fingerprint, row, size and checksum checks.
- On a change of effective profile or request, build a new generation under the section lock, respecting the normal checkpoint/atomic manifest protocol. Never seed the replacement from another profile’s SQLite rows. Shared vectors may be reused only from the effective fingerprint namespace, including valid vectors on a switch back. Personal vectors stay section-local. An unmarked legacy Gemma index is still ready for explicit fp32; on an upgrade where the default flips, one sync establishes the new policy, even if a fallback host ultimately writes fp32. An interrupted switch leaves a complete published checkpoint of one profile. Old binaries recognize an fp16 fingerprint as stale. If an old writer later publishes plain fp32, the new reader again requires a sync under its fp16 request.

An artifact-only identity would allow an fp32 cache hit or resumed generation to supply documents for fp16. Deferring the choice until model open would also miss an all-cache-hit sync. Resolving the writer before either lookup addresses both cases.

## 2. Resolve the device once, before admitting old rows

Pass the normalized request from `internal/cli/semantic.go` through `semantic.Options`. Represent the writer decision explicitly, e.g. `embed.WriteProfile{Fingerprint, Precision, Selector, DeviceID, Reason string}`, where `DeviceID` is the resolved persistent ID for CUDA and `Selector` is the goinfer kernel name. Give the two Gemma entries an optional resolver used by the registry; all other entries use the base fingerprint. Thread the result through `OpenOptions` for a sync, keeping model verification and `Registry.Open`’s entry check on the base model. Have the document embedder report its actual writer fingerprint, and check it against the resolved one **before** collecting any vectors. CPU query opens continue to report their base identity.

- After `Build` takes the lock and scans a nonempty eligible Gemma section, but **before** `builder.run` calls `openIndex`, resolves replacements, consults either reuse tier or publishes anything, resolve the writer. Share a lazy, invocation-scoped resolution between the shared/personal builds, including the inventory and normalized requested selector. Thread it into named-device validation and attachment so pbrain does not call its inventory again. Binding to the UUID on open still lets goinfer verify the physical card. A low-level check made by goinfer to validate attachment is independent of pbrain’s one inventory. No model load just to choose a fingerprint. Resolve even when this host has different hardware and all source notes are unchanged. Existing all-cache-hit builds can still avoid opening a runtime. No capability probe for explicit CPU, fp32-only selection, other model rows, a read command or an empty section. If an existing section becomes empty, clear it under its previously valid effective profile when policy matches; otherwise publish an empty base generation under the current request. A nonexistent empty section creates nothing. Defer any error for an unavailable explicit selector until the section actually needs an embedder, as existing no-work syncs do.
- Keep the model eligibility filters and current device ranking. A named CUDA device is resolved to its existing persistent ID. Under auto the existing selection order chooses the device first; precision follows that card. In **one** Linux+CUDA-tagged production file `internal/embed/gemma2/cuda_capability_linux.go`, import the already-pinned `github.com/eitamring/gocudrv/cuda` v0.3.2 directly. Initialize the driver, parse the selected alias ordinal, call `GetDevice(ordinal)` and `UUID()`, compare with goinfer’s selected backend-qualified UUID (compare the complete device token case-insensitively after removing only the backend qualifier; a MIG identity that this driver API cannot verify is inconclusive), then call `ComputeCapability()` on that same handle. Never use device 0 by assumption or infer architecture from the marketing name. Expose a stub on other builds and fake this function in host-only tests. Promote the existing dependency from indirect without changing its version. An AST import-boundary test scans repository Go files across tags and permits the driver import only in that one file. Replace the interim read with goinfer’s per-device capability/selector inventory once tagged and qualified. [Upstream #68](https://github.com/pkieltyka/goinfer/issues/68)
- Replace the implicit `cudaSelector` build-tag choice in `internal/embed/gemma2/accel_cuda_combined.go` and `accel_cuda_default.go` with explicit profile-to-selector binding. Linking `eg2_combined` is required for fp16; it must never redirect an fp32 attach from `cuda` to `cuda-eg2-combined`. The linked-selector list identifies compiled kernels, not what a particular card can run. For fp16 request + selected CUDA + linked selector + CC≥8.0, bind `UseDevice(persistentID,"cuda-eg2-fp16")`. For CC<8.0 on CUDA hardware supported by the ordinary backend, bind the **same card** with `"cuda"` and choose the fp32 identity before cache/DB access. When the fast kernel is absent, use ordinary CUDA when available. A failed capability read, UUID mismatch or absent driver never by itself fails sync: use the normal fp32 CUDA/CPU resolution (or qualified Google Vulkan as selected), validating an actual attachment by persistent ID. Never treat a new occupant of an old ordinal as the selected card. Existing errors for a separately invalid explicitly named device remain independent from precision detection. Q8 still excludes Vulkan. Do not classify generic attach/OOM/device-lost errors as CC<8.0 by matching goinfer text.
- Keep `embedding_device` and `cpu_fallback`. For downgrade of a requested CUDA fp16 path, emit a single stderr notice `cuda_precision_fallback`: for example `cuda:0 supports compute capability 7.5; using fp32 CUDA (fp16 requires 8.0)`. An unknown capability or unlinked selector has its own accurate reason; CPU-only auto fallback retains its existing device notice. Emit a precision downgrade at resolution when it affects the generation, including a forced migration that reuses all eligible vectors. Reuse the command’s code de-duplication and existing JSON notice envelope. No duplicate notice across sections, no GPU notice on search/status, and no spurious fallback when a person requests fp32 or CPU.
- Once fp16 is selected, attach only the verified fp16 selector to the resolved device. An attachment failure or device change after resolution cannot select an fp32 writer under the reserved key. Fail that attempt through the existing typed I/O path and leave its last published checkpoint usable. In `gemma2.go` reserve the auto CPU continuation only for base-profile writers. Keep the 8,192 aggregate-position cap, 2,048 per text, working-set checks and whole-input certified OOM split on the same encoder. An fp16 singleton OOM, device loss, failed cleanup or unmarked failure terminates the section; no switch of precision midway. A later sync can deliberately select another effective profile and rebuild.

## 3. Make readers and cache reuse profile-aware

- In `internal/semantic/index.go`, retain the request when reading, opening and publishing a manifest; carry it through checkpoints and catch-up. A shared helper validates a section manifest against the current request and **known** fingerprints for the base model. Use it in `Source.check`, `runIndexes` and `sectionState` for status. Validate the actual snapshot opened by `openIndex`, including the request and DB meta, even if an earlier preflight saw another generation. Record the effective profile in each `openedIndex`. The reader recognizes the current fp16 identity even on a machine with no CUDA support. Search always embeds the query on CPU. Shared and personal sections may have different effective profiles; validate and score each independently using the qualified CPU query pairing and the existing cutoff.
- `builder` and `sectionIndex` carry the resolved vector fingerprint separately from `m`. Pass it to `newIndex/openIndex`, `cachedVector` and `keep`. As today, enumerate reuse only inside the active SQLite generation and allow only the shared section to use a shared vector cache. Reject cross-row/cross-precision hits for every tier, including own base rows and same-run aliases. A root named for fp16 must never contain a newly computed fp32 vector, even transiently.
- In `Source.CatchUp` exclude fp16 sections **before** planning cache reads, acquiring locks or embedding missing documents. Keep covered fp16 results. Missing/changed notes get existing partial/not-ready behavior until the next sync. In a mixed view a qualified fp32 section may still catch up normally. Recheck the remembered manifest before any catch-up write, so a concurrent profile switch cannot let CPU catch-up overwrite an fp16 checkpoint.

## 4. Qualify the binary and the product before changing the default

| Gate | Required evidence for each model row |
| --- | --- |
| Storage, selection and old hardware | Model-free tests for default/explicit fp16/fp32, config type/invalid values, bge/no-model, two visible cards, CC 7.5/8.0, missing driver, UUID remapping, probe error, no fp16 kernel, explicit CPU and both Q8 Vulkan rejection and Google Vulkan eligibility. Count inventory probes (≤1 per eligible sync, zero for reads). Verify attach receives the chosen UUID/kernel. Test upgrades, policy toggles, hardware downgrades/upgrades with unchanged notes, reused vectors and filenames in both sections, restart after checkpoint, singleton OOM, concurrent catch-up, stale manifests and older binaries. A default qualified build must prove opt-out opens plain `cuda`, even with all three CUDA tags. |
| End-to-end vectors and ranks | From empty isolated indexes and vector caches, build the frozen 59-passage retrieval brain through real `pbrain sync` on the RTX with each precision and row. Match rows by item/path/ord/digest, check dimension, finiteness and unit norm. Report exact bits, worst/median per-passage cosine and how many fall below 0.999 against fp32 CUDA and CPU. Require none below 0.999. Run CPU-query searches at the existing 0.72 cutoff, both standalone and alongside BM25. Compare ordered IDs per question, report every rank or threshold crossing, require no loss of an expected hit first/top-3/first page versus matched fp32, and no extra held-out false answers. Pass the two existing §8.7 admission gates. Report actual counts on 47 answerable and 30 held-out negatives (historical Q8: 39/47 first, 42/47 top-three/first page, 30/30 abstentions). |
| Same-mode bit invariance and memory | On one pinned build, selector, physical card and driver compare all 768 float32 bits against singletons for each of the 59 passages in default, reordered/restored, narrow-budget and test-injected certified-OOM split layouts; prove the retry was exercised on the real encoder. Compare same-profile cache payloads and ordered DB rows across successful splits. Trace every call, enforce 8,192 total positions, 256 texts and the estimated additional workspace guard (existing singleton exception). Record actual default budget, post-attach memory, sampled peak host/device memory and utilization for both arms. Investigate any excess over the budget or material peak increase before default rollout. |
| Representative speed | During a quiet slot, one GPU run at a time. Use the archived 200 ordered passages / 100,066 prepared positions for an adapter replay, then a bounded real sync on a small Markdown subset of the #43 corpus with its fixture digest recorded; use exactly the same notes, model files, four pinned cores, budget and cold isolated indexes/caches for both arms. Count actual newly embedded passages/positions. Report end-to-end positions/s and passages/s, attach, prepare, forward and publish timings and peaks. Require a repeatable positive end-to-end gain beyond timing variation per row, not merely a forward-only gain. Short paired runs only; set a 2-minute timeout per sync invocation, reduce the subset equally if needed, preserve partial results separately. Defer noisy trials; no full-corpus run. |
| Distribution and CI | In `.goreleaser.yaml`, amd64 GPU tags `cuda,vulkan,eg2_combined,eg2_fp16`; arm64 GPU tags `cuda,eg2_combined,eg2_fp16` **only after** its cross-build and executable smoke pass. Exercise CPU-only startup with drivers absent/masked, devices JSON and one-note sync. Assert the expected selectors are linked and no unexpected GPU initializes at startup. A host-only smoke script that returned early on an architecture mismatch is a skip; use a native arm64 runner or executable equivalent for the smoke. If unavailable/failed, retain arm64’s current CUDA-only archive and say so in the release notes. CPU companions and Darwin stay untagged. Update archive-tag checks, build/vet matrix, race/unit suite and exact-head Linux CI. |

At integration, publish evidence and commands in `internal/cli/README.measure.md`. Both rows must pass before the single release default changes. If any gate fails, keep the default fp32, expose the qualified fp16 path only by explicit selection, report the failed gate and actual arm64 coverage to the operator, and revise release notes accordingly. Never publish a mixed-precision generation, including under opt-in. Update the skill’s semantic topic, configuration examples and next release notes with the shipped default, rebuild behavior and opt-out. #59’s verification cache protects the same model bytes under both profiles. No new downloads or change to its pins.
