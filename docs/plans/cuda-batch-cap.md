# #50 · Let the CUDA memory budget set the batch size

**Decision.** Remove pbrain’s 8,192-position aggregate clamp for CUDA document embedding on the pinned goinfer v0.6.2. Keep the ordered 256-text window and the existing byte budget. Retain Vulkan’s 8,192-position clamp exactly as qualified in #49. The expected benefit is fewer CUDA forwards on cards with sufficient free memory. The throughput gain is an open measurement.

## Packer change

1. Work from the implementation parent after #51. The reference reviewed here is pbrain `bde52e3`, with all three goinfer modules at v0.6.2. In `internal/embed/gemma2/batch.go`, give the existing `batchSize(ids [][]int, positions int) int` its already backend-adjusted limit. Remove its unconditional `min(positions, embeddinggemma2.MaxTokens)`. Compute the limit once in `embedDocuments` from the resolved `e.info.Device` and byte budget. Apply the unclamped rule only to the `cuda:` prefix. Keep the current Vulkan coefficient and cap, and retain the old cap for any future unqualified accelerator. A small package-private `batchPositionLimit(device string, budget int64) int` lets the packer tests exercise the actual policy. Divide in int64 before converting the bounded quotient to int.

   | Resolved device | Aggregate positions admitted per call |
   | --- | --- |
   | CUDA | floor(budget / 136,000 bytes) |
   | Vulkan | min(8,192, floor(budget / 107,528 bytes)) |

   Keep `memoryBudget` and the existing CLI parser. With live free bytes, use 30% rounded down, capped at 6 GiB. With estimated free bytes, use 30% up to 1 GiB. An unknown figure gets 1 GiB. A positive `PBRAIN_GPU_MEMORY` in whole MiB overrides the percentage, up to 6 GiB and also up to live free bytes when available. Live zero stays zero. As today, even a zero budget admits one prepared input alone. The budget covers estimated batch workspace. Resident weights, context and other device users must be accounted for separately when measuring.

2. Preserve input order, the first-text exception and the 256-text ceiling. The next text starts the next call if adding it would exceed either limit. One input calls `EmbedIDs`, several call `EmbedIDsBatch`. CPU, query embedding, tokenization, the builder’s outer window and publication order keep their existing paths. In particular, `(*encoder).tokenIDs` already limits each pbrain input to 2,048 positions including special tokens. Upstream `ForwardBatch` independently validates each input against 8,192 and checks the total against its grid and signed-index limit before allocating. Preserve cancellation and `forwardError` on failure. A device loss or failed allocation ends this run through the existing error path. Resubmitting a failed forward can encounter a broken accelerator. [goinfer PR #45](https://github.com/pkieltyka/goinfer/pull/45)

3. Use the existing 136,000-byte estimate on this pin. It was measured on CUDA v0.5.0 and needs verification at the larger shapes. With 1 GiB it permits 7,895 positions, with 2 GiB 15,790, and with 6 GiB 47,370. An arbitrary higher constant would ignore headroom on smaller or shared GPUs. Copying goinfer’s buffer allocation formulas into pbrain would bind the packer to kernel internals. Upstream #27 **closed** with PR #57 (`cf50a3ad`), after v0.6.2. Its optional `Encoder.BatchMemory(preparedLengths []int)` distinguishes unsupported shapes and unknown estimates and separates incremental peak bytes from resident weights. It is absent from the pinned root and CUDA modules. Adopting it belongs with a qualified tagged pin. Meanwhile the estimate directs admission and the memory gate below decides whether #50 can ship. [goinfer #27](https://github.com/pkieltyka/goinfer/issues/27) · [PR #57](https://github.com/pkieltyka/goinfer/pull/57)

## Correctness gates

1. Extend `TestGemmaPacker` in `internal/embed/gemma2/batch_test.go` to use the backend-specific limit. At a sufficient budget, four 2,048-position texts plus one position fit in one CUDA call and split 4+1 on Vulkan. Exactly 8,192 fits both. At 1 GiB test CUDA exact fill at 7,895 and spill at 7,896. Check zero budget, a single valid input larger than its budget, 256/257 texts and a sequence needing several windows. Assert exact ordered prefixes. Run the existing `TestMemoryBudget` and `TestGemmaAcceleratorDispatchBatchingAndCloseRetry`. Cover the independent input limit through the real preparation path (`TestGemmaSpecialTokensAndCut` with a text longer than 8,192, checking the actual prepared length is at most 2,048). For raw IDs, the v0.6.2 boundary is goinfer’s: record its exact-limit and oversized-member tests from `backend/cuda/embeddinggemma2_test.go`. A valid singleton over the workspace budget does not authorize an overlength input.

2. Extend `TestGemmaBatchSameBytes` in `internal/embed/gemma2/batch_cuda_test.go` on the same CUDA build, model and card. Collect singleton vectors, then use the 59 ordered fixture passages under the old-cap equivalent (`8192 * 136000` bytes via `OpenOptions.MemoryBudget`) and at 6 GiB. The fixture has 9,271 prepared positions. Assert the wider case **actually dispatches** a call above 8,192 and that the narrow case splits. Compare all 768 coordinates of every normalized vector with `math.Float32bits`, including signed zero. Repeat with a permuted order and restore indices before comparison. Run this gate for each admitted CUDA model row that shares the packer, including Q8_0 after #51. Keep the Google row as the timed reference. Run the Vulkan packing tests without loading a driver. #49 qualified its GPU under the old cap and PR #45 changed only the CUDA backend.

3. Shape independence requires both identical new vectors and deterministic selection of old ones. `internal/semantic/build.go` fixes the replacement paths before the scan. In `reuse.go` and `index.go`, priority is the item’s own base row (lowest ordinal), an eligible base row outside the replacement set (lowest path then ordinal, including paths pending removal), the first answer for that digest in this run (pending slot/alias or stored row), then the shared model-keyed cache. Only a miss reaches the embedder. Personal sections skip the shared cache. Keep the ordered correspondence between inputs, returned vectors, aliases and stored passages. No fingerprint, cache-key or DB format change is needed.

   Run `TestBuildWindowInvariance`, `TestReuseTiers` and `TestBuildResumed` in `internal/semantic`. Against the narrow CUDA reference, start two isolated copies of the same corpus, base generation and cache. Cover cold builds plus a seeded incremental run with duplicate digests, competing base rows and a shared-cache hit. Compare embedded/reused counts and shared cache relative names and payload bytes. Check that the personal run adds no shared vectors. Compare each manifest-selected SQLite file byte for byte, including ordered passage BLOBs, for both sections. Use the existing mixed-origin restart expectations in `TestBuildResumed` for its separate restart case. Comparisons across model rows or across devices do not establish same-device byte identity.

## Measure on pax

Run after #51 releases the NVIDIA card. Use the same Google pack, compiler flags, pin and RTX PRO 6000 for the parent/control and candidate. Set `PBRAIN_ALLOW_GEMMA2=1`, select `cuda:0`, and run one workload at a time. Record commit and binary hashes, driver, device, affinity, `GOMAXPROCS`, actual budget, per-forward shape, peak host RSS, post-attach device baseline, sampled peak process/device memory and GPU utilization. Save raw samples and their cadence. Sampled peaks are lower bounds on transient allocations.

**First, replay the #49 slice.** Use `tools/phase28/evidence/vulkan-49-v062/capture.tar.gz`, member `slice/passages.json`, first 200 entries in captured order. The archive’s scratch harness `TestVulkanMatchedSliceV062` fixes the budget at 1 GiB. Parameterize that assertion and the budget it passes to `reg.Open` in the measurement copy. Instrument the forward calls on each checkout’s own production packer. Replacing its entire `batch.go` with the archived instrumented version would silently restore the old clamp. Use one timed `Embed` on the already-open model at `GOMAXPROCS=32`. Verify all 100,066 prepared positions and compare the output bytes. These are **offline predictions** from greedy packing of the archived lengths:

| Budget (MiB) | Old calls | New calls | Largest new call (positions) |
| ---: | ---: | ---: | ---: |
| 1,024 | 14 | 14 | 7,890 |
| 2,048 | 13 | 7 | 15,781 |
| 4,096 | 13 | 4 | 31,430 |
| 6,144 | 13 | 3 | 47,351 |

The historical 1,024 MiB control took 14.854 s, **13.46 passages/s**. Repeat it on both binaries; that budget cannot exercise this change. Work up the table, comparing both binaries at equal budgets. Alternate run order for three clean paired trials per reported budget and report median and range. Lower launch count is expected. At full size the GPU was already about 98% busy, so a small gain, no gain, or a slowdown are all plausible. The earlier 7.7% gain from two to eight real passages is context, not a forecast for wider calls.

**Then run the #43 end-to-end comparison.** Use the Gemma CUDA case in `tools/phase28/evidence/sync-pax-43/measure.py` for each binary, fresh cache and indexes, verified model prestaged, identical fixture digest. Use CPUs 0–3, `GOMAXPROCS=4` and verify a 6,144 MiB workspace budget in both runs. The historical Google-pack full sync embedded 48,511 passages from 5,000 items / 50 MB in 1h 01m 02s, **13.25 passages/s**, 4,317.5 MiB host RSS and 2,136 MiB device peak. This is a different denominator and harness from the 13.46 slice. Use the paired current-pin control to attribute any change to #50. Record wall time, passages/s, counts and peaks. Run the archived `compare.py` and explicitly require its printed `database_bytes_equal` to be true for each section as well as successful ordered-row and integrity checks. Expect 43,642 shared and 4,869 personal passage rows. Record the results in `internal/cli/README.measure.md` with the evidence location.

**Stop rules.** Stop widening immediately on a vector or DB mismatch, unexpected device/shape, accelerator error, or observed multi-input workspace growth over the configured budget after subtracting the isolated post-attach baseline. Report the first failing shape, estimate, actual peak and device error. Do not retry a lost device. Repeat contaminated trials after the host clears. If the 6 GiB slice is reproducibly slower than its matched old-cap control by more than 5% across three clean pairs, report that regression to the operator before paying for the full pair. Otherwise perform the full runs, including when the slice gain is within noise. A full-sync regression or ambiguous timing goes to the operator with the measured memory trade-off before rollout. These timing thresholds are proposed experiment rules. Byte identity and bounded admission are release gates.
