# #50 · CUDA batch admission and recovery on goinfer v0.6.3

## Outcome

**Keep the 8,192 aggregate-position cap on both CUDA and Vulkan.** On the matched 200-passage RTX PRO 6000 slice, lifting the CUDA cap raised throughput from 13.51 to 13.77 passages/s (+1.9%) and peak device memory from 2,130 to 7,188 MiB (+5,058 MiB). The operator judged the gain too small for that memory cost on a shared card and declined the cap increase in #50.

For #56, apply the cap first. Use `BatchMemory` to shorten a CUDA batch when its additional peak exceeds the workspace budget. Retain certified OOM split-retry and `Devices`/`UseDevice`. This decision supersedes the larger-batch admission, test and spec changes proposed below. On the revised head, rerun CUDA byte identity including a forced split, then time the default-budget 200-passage slice and measure peak device memory against the 2,130 MiB pin-only reference. A peak close to that reference is expected and still needs verification. Follow with the planned storage and bounded Radeon checks.

## Original proposal

After #51 merges on v0.6.2, pin the goinfer root, CUDA and Vulkan modules to v0.6.3 together. Use the attached encoder’s estimate to admit CUDA batches above 8,192 aggregate positions. Keep Vulkan within the envelope qualified by #49. Adopt unified discovery and attachment now. Keep pbrain responsible for model eligibility, automatic ordering, fallback and notices. The unified call probes linked backends before filtering. It performs no model upload. Search, explicit CPU, and sync with no embedding retain their probe-free paths. Keep tagged imports for registration and the Linux/amd64 constraint on Vulkan.
- Retain the named-selector rules. Preserve ambiguous, device-lost, host/device OOM and unexpected failures. Check `AttachedDeviceReporter.AttachedDevice().ID` against the requested persistent ID before publishing the runtime. A failed reading cannot be safely replaced by a live reading from a different card. `RunInfo` keeps the ordinal, name and resulting budget. ## 3. Admit an ordered prefix by its prepared shape

Change the adapter’s private packer in `internal/embed/gemma2/batch.go`. The only public boundary remains `Embed(ctx, role, texts)`. Tokenize once, keep the lengths beside the prepared IDs, preserve input order, and admit at most 256 whole texts per call. pbrain still cuts each input to 2,048 positions including prompt and specials. goinfer separately validates its per-input 8,192 cap, model limits and CUDA launch geometry. Queries and standalone calls use `EmbedIDs`.

For each next prefix, call the **same attached** `e.model.BatchMemory(lengths)` before forwarding. A simple implementation scans increasing prefixes up to the first refusal, with the singleton as the first candidate. Prefixes are bounded by 256. This avoids requiring monotonic estimates across different forward types or cached rotary-table states. Re-evaluate for the next call after every successful forward and every recovered failure. Keep all probes, forwards and retries sequential on this encoder.

| Result for the candidate shape | Admission rule |
| --- | --- |
| CUDA `BatchMemoryUpperBound` (v0.6.3) or a documented `BatchMemoryApproximate` | Admit a multi-input prefix when `AdditionalPeakBytes <= info.Budget`. Equality fits. A known zero is a valid estimate. Keep `ResidentWeightBytes` separate for diagnostics. The post-upload budget already accounts for resident weights. |
| CUDA `BatchMemoryUnknown` | Use the existing fallback `floor(budget / 136000)` positions. This is the **only** CUDA case that uses that coefficient. CUDA has no fixed 8,192 aggregate cap. |
| Vulkan `BatchMemoryUnknown` (v0.6.3) | Keep `min(8192, floor(budget / 107528))` positions and 256 texts. A Vulkan headroom basis of *estimated* can coexist with a workspace estimate of *unknown*. Keep the #49 aggregate ceiling even if a later estimator appears, until separately qualified. |
| `ErrUnsupportedBatchShape` | End the candidate prefix before the rejected addition and forward the previously admissible prefix. If the singleton itself is unsupported, return the wrapped cause. Validate every input’s length; singleton admission cannot legalize an invalid input. |
| Other estimator error, including closed/broken encoder | Propagate the cause via the existing accelerator error mapping. Emergency fallback arithmetic applies only to a successful unknown-quality result. |

A valid singleton runs even when its additional workspace exceeds the budget. No work is reserved by an estimate. CUDA bounds tracked device buffers, including scratch and rotary growth; driver-private overhead and concurrent use can still produce OOM. Avoid stale estimates, a duplicate weights charge, or an artificial limit computed from historical bytes/position on the known CUDA path. [BatchMemory contract](https://github.com/pkieltyka/goinfer/blob/v0.6.3/embeddinggemma2/batch_memory.go)

## 4. Recover only from a certified forward OOM

Put recovery in the Gemma adapter, around the actual prepared forward, before `forwardError` maps a final failure. Use it for both `embedDocuments` and single-input accelerator paths. Keep the builder and cache unaware of retry attempts.

1. Check the context before/after each probe/forward and before retrying. Cancellation retains precedence. On success validate the result count and preserve its positions. If `errors.Is(err, embeddinggemma2.ErrDeviceLost)`, immediately take the existing `embed.ErrDeviceLost` → named `io` path, for auto and explicit devices alike. Abort on any other error unless **this forward** matches `embeddinggemma2.ErrBatchOutOfMemory`. Its parent `ErrDeviceOutOfMemory`, attach/upload/cleanup failures and text matching never authorize a retry.
2. On the marker with two or more inputs, halve the failed group’s aggregate **positions** (integer floor) as a secondary maximum on this encoder, taking the smaller of that and any previous retry limit. Repack precisely the failed range at boundaries between whole inputs with that limit and the current workspace rule. Run each resulting group left to right on the **same encoder**, repricing the remaining prefix after a child completes. An input over the reduced allowance runs alone. Each child of a failed multi-input call is strictly smaller, and a later failure can only lower the limit. Keep it for subsequent batches in this section. Use an unset state distinct from a zero limit. Never re-embed an already successful prefix or retry an unchanged request.
3. At one input, stop GPU retries. Follow the existing “Back-off” singleton policy. A named device returns the accelerator error with its native cause. Under `auto`, only a **certified singleton OOM** allows a move to CPU. Retain the lightweight CPU encoder from before attachment (same decoded model and tokenizer). Close the GPU successfully before switching; on close failure preserve its handle for cleanup and return the error. Finish the failed input and remaining suffix on CPU, including later calls, update `Info` to CPU with `FallbackMemory`, and let `builder.reportRuntime` emit the existing `cpu_fallback` notice. Route the remaining prepared IDs directly through CPU singleton embedding. Never send pending batches through the detached GPU. Already successful GPU vectors remain in order. Preserve nil results on a terminal error; the builder only stores vectors from a completed `Embed` call and retains its normal checkpoint rules. [Certified retry contract](https://github.com/pkieltyka/goinfer/blob/v0.6.3/embeddinggemma2/batch_oom.go)

## 5. Prove the device, batch and storage contracts

- **Inventory and admission without hardware.** Extend the existing `TestDeviceSelection`, registry/CLI and `TestGemmaPacker` cases. Include two CUDA cards with different IDs and headroom, Vulkan estimated/unknown, partial failure plus valid row, masked or duplicate IDs, ordinal remapping between probe and attach, attached-ID mismatch, named failure, auto fallback, CPU/no-probe and Q8 exclusion. Check actual attached memory in the budget. In the packer fake return estimates deliberately different from `136000 × positions`. Test exact fit and one byte over, zero and unknown, oversized-but-valid singleton, unsupported/invalid input, several windows, 256/257 texts, and four 2,048-position inputs plus one position. Verify CUDA can admit the last shape and Vulkan splits 4+1. Retain the long-text preparation and existing input limit tests.
- **Injected failure proof.** Extend the fake accelerator in `internal/embed/gemma2/accel_test.go`. Return a wrapped `ErrBatchOutOfMemory` on the first large group and again on a child; use distinct, unequal-length inputs and record attempts, identities and token IDs. Assert strictly smaller child groups, the same handle, original order, one successful result per input, no replay of a successful prefix, the reduced limit on the next window and bit equality to a failure-free run. Inject cancellation after a successful child, certified singleton failure under auto and named selection, generic OOM, device loss and failed close. Check stop counts, error identity, no partial results, and notices. Make the unmarked cases fail even if their error text contains “out of memory”.
- **Real CUDA bit equality and rule 2.** Run `TestGemmaParity` with verified files, Google and Q8_0 CPU/CUDA parity (each cosine ≥0.999 against its qualified reference and CPU pairs), `TestGemmaBatchSameBytes` and #51’s `TestGemmaQ8CUDAByteLayouts`. Use the 59 ordered passages (Google: 9,271 prepared positions), singleton, narrow and actual wide dispatch above 8,192, and reordered layouts with indices restored. Compare each of the 768 final float32 values by bits. For the forced-split case use a test-only forward wrapper that returns the marker **before dispatch** once, then executes all children on the real CUDA encoder. Trace the branches and compare every vector to the unsplit/singleton reference. This exercises pbrain’s recovery on real outputs without exhausting the card. goinfer’s cleanup guarantee is independently tested upstream. Compare same-build/same-device vectors after a successful GPU retry; a deliberate auto-to-CPU transition uses CPU parity for the affected suffix.
- **Database and cache.** Keep `internal/semantic/reuse.go`, `index.go` and `build.go` ordering. The replacement set is fixed at scan start. Reuse reads the item’s own base row (lowest ordinal), another eligible base row outside the set (lowest path/ordinal), the first answer this run (slot/alias or stored row), then the model-keyed shared cache. Only a miss reaches the packer. The private section omits that cache. Run `TestBuildWindowInvariance`, `TestReuseTiers` and `TestBuildResumed`. From identical cold and seeded starting states, compare narrow, wide and injected-retry builds with duplicate digests, competing base rows and a cache hit. Require equal embed/reuse counts, cache paths/payloads, ordered rows including vector BLOBs, and byte-identical manifest-selected shared and personal databases. Retain mixed-origin restart expectations. Model fingerprints, schema and cache layout stay unchanged.
