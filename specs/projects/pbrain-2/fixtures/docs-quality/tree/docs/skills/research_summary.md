# Automatic skill creation and updates (Hermes Agent)

## Bottom Line

Hermes Agent (NousResearch/hermes-agent, studied at v0.23.4, released 2026-11-24) keeps skills as agentskills.io-style `SKILL.md` directories under `~/.hermes/skills/`. The agent writes them through one validated tool, `skill_manage`, which does create, patch, rewrite, support-file write/remove and delete. "Learns by doing" is mostly a **background review fork**. After each turn, if at least 10 tool-calling iterations have passed since the last skill write (`skills.creation_nudge_interval`), Hermes replays the conversation in a forked agent. That fork is told to "Be ACTIVE" and to patch the skill that was in use before creating anything new. New skills must be "class-level umbrellas", and failures, negative tool claims and one-off narratives are excluded. Bloat is handled afterwards by a **curator**: inactivity archival is on by default (stale at 14 days, archived at 30), and LLM umbrella consolidation is opt-in. Every mutation is recorded in a content-addressed ledger with single-edit rollback. Human review exists (`skills.write_approval`, which stages diffs) but is **off by default**. Content writes are not gated by who owns a skill. There is no semantic version bump and no git integration.

## Key Findings

- **The trigger is a counter, not a judgment.** `skill_review_due` fires when `_iters_since_skill >= 10`. The counter resets on any `skill_manage` call, and the review is suppressed for cron and subagents. The foreground prompt adds only "When you work out a non-trivial workflow, record it with skill_manage for future reuse." ([review_signals.py](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/agent/review_signals.py), [prompt_builder.py](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/agent/prompt_builder.py)). Details: [creation-triggers-and-review.md](./creation-triggers-and-review.md).
- **Dedup comes mainly from the prompt's update-first order**: (1) patch a loaded skill, (2) patch an existing umbrella, (3) add a `references/`/`templates/`/`scripts/` file, (4) create a new class-level skill (no PR numbers, error strings or `fix-X` names). The only hard duplicate check is exact-name collision on create. There is no similarity search ([background_review.py](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/agent/background_review.py)).
- **"Lessons, not logs."** Skills hold imperative rules with one clause of why, attached to steps. They exclude incident narration, dates and quotes, and are fixed in place rather than appended to. The linter's calibration comments record what happened without this: a 100k-char "incident-log" SKILL.md and a skill with 443 per-session reference files ([skill_linter.py](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/tools/skill_linter.py)).
- **The background fork is tightly sandboxed.** It gets only skills/memory tools plus read-only file tools. Writing to an existing file requires a fresh `skill_view` in the same review (read-before-write is enforced). A security scan is mandatory for its writes, and it may archive only curator-managed skills ([skill_manager_guards.py](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/tools/skill_manager_guards.py)). The foreground agent has looser guards: the scan is opt-in, and generic file tools bypass `write_approval` (gap tracked as #60440).
- **Who governs what:** only background-review creates are marked `created_by: agent` and so fall under the curator. Foreground and `/learn` creates are user-owned. The review may still **edit any skill**, including hand-written, bundled, hub and pinned ones, and an edited bundled or hub skill then stops receiving upstream updates. **Pin** blocks deletion. **Lock** blocks every agent write ([Curator doc](https://hermes-agent.nousresearch.com/docs/user-guide/features/curator)).
- **Versioning is audit, not semver.** The `.curator_ledger.jsonl` keeps per-file sha256 before/after manifests with blob storage. Rollback works per mutation or per whole curator run (tarball snapshots). The `version:` frontmatter is never bumped. Details: [update-safety-and-governance.md](./update-safety-and-governance.md).
- **The curator fights bloat after the fact.** Its prompt calls "hundreds of narrow skills" "a FAILURE of the library" and pushes umbrella merges ("fewer than 10 archives … you stopped too early"). The one measured run: 346 skills became 249 archives and 18 umbrellas (issue [#7816](https://github.com/NousResearch/hermes-agent/issues/7816)). Consolidation is opt-in because of cost and how broad the changes are. Details: [curator-lifecycle.md](./curator-lifecycle.md).
- **Loading is progressive and model-routed.** A system-prompt index shows `name: description` with the description clipped to **60 chars** by default, under a strong "you MUST load it … Err on the side of loading" instruction. `skill_view(name)` loads SKILL.md plus a `linked_files` map, and `skill_view(name, path)` loads one reference. Skills added mid-session arrive as a per-turn delta note, keeping the cached system prompt stable. Details: [selection-and-loading.md](./selection-and-loading.md).
- **Format: an agentskills.io superset.** Required `name`/`description` match the spec, as do `references/`, `scripts/` and `assets/`. Hermes adds `templates/`, nested `metadata.hermes.*` gating (`requires_toolsets`, `fallback_for_tools`, `platforms`, `config`, `blueprint`), secret/credential declarations, `${HERMES_SKILL_DIR}` substitution and opt-in inline shell. Anthropic's Agent Skills use the same three-level disclosure, but Claude Code does not create skills on its own in general. Details: [skill-format-and-storage.md](./skill-format-and-storage.md).
- **Storage tiers** (precedence): project (trusted repos only, scanned) → local `~/.hermes/skills` → `skills.create_dir` (can redirect new agent skills to "a shared "brain" directory, a git-tracked repo") → `external_dirs`. External dirs "are not a write-protection boundary".
- **Privacy detail worth copying:** `/learn` forces `author: Hermes` and forbids filling in the OS user or git identity, because "Skills get shared and published, so an environment-derived name is a privacy leak" ([learn_prompt.py](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/agent/learn_prompt.py)).

## Open Questions / Gaps

- **Effectiveness data is thin.** The only number is the curator's 346 → 249 archives / 18 umbrellas run. I found no measurement of whether self-written skills improve task success. (User reports belong to the "Evidence" subtopic.)
- **How often reviews actually write.** PR #17213 says reviews were too passive before 2026-04-29. I did not find post-change rates of writes per review.
- **Issue #7816 quotes** come from a WebFetch summary of a very large page (~500 KB), not verbatim text. The 346/249/18 figures should be re-checked against the thread if they become load-bearing.
- **The reason for dropping negative-claim TTLs** (the maintainer closed #7816 as "No longer needed") is not explained in the thread.
- I read code at v0.23.4. Behaviour in older releases (e.g. the local v0.20.3 clone at `/home/peter/Dev/hermes-agent`) differs in places, for example the flat versus operations-array `skill_manage` schema. I did not diff the versions systematically.
- The docs site has no per-page dates. I used the in-repo docs at the tag as the dated source.
