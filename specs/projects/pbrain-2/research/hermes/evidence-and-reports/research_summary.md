# Evidence and user reports (Hermes Agent)

## Bottom line

Users do report a real "it gets better at my recurring task" experience with Nous Research's Hermes Agent. Those reports are anecdotes on narrow, repeated tasks, and the best setups often add their own grading, consolidation or memory layers on top. No controlled evaluation shows that the skills Hermes writes for itself improve later outcomes. The project's own tracker says none exists ([#96704](https://github.com/NousResearch/hermes-agent/issues/96704), open). Independent benchmarks run on the Hermes harness find that curated skills help a lot and self-generated ones help little. The failure modes are well documented by heavy users with logs: duplicate and unused skills, wrong rules that persist ("learned helplessness"), silent rewrites of working skills by the background reviewer, skills that are written but never loaded, memory filled with wrong or irrelevant facts, secrets quoted back from memory, and a background review that can use 21–66% as many input tokens as the conversation itself. The fixes so far are mostly prompt tweaks and opt-in gates, and the defaults still let the agent write without approval.

## Key findings

- **No measured benefit for the stock loop.** [#96704](https://github.com/NousResearch/hermes-agent/issues/96704): "Nothing in the tree varies a skill or a memory entry and measures the downstream task outcome." The proposed fix is a three-arm harness with a holdout arm, and it is still on a community fork. The widely repeated "40% faster after 20 self-created skills" figure traces to a third party or to "Nous claims", with no method I could find. — [measurements](./measurements-and-benchmarks.md)
- **Benchmarks: human skills help, self-written skills don't.** FinSkillBench replicated on Hermes: no-skill 0.366, curated 0.528, self-generated "little benefit despite higher computational cost" ([arXiv:2608.18099](https://arxiv.org/abs/2608.18099)). arXiv:2610.03564 finds in-episode self-generated skills "add only +0.5 points". SkillLearnBench: "self-feedback alone induces recursive drift" ([arXiv:2604.20087](https://arxiv.org/abs/2604.20087)). Misevolution: in "All 21 combinations" the agents wrote unsafe skills, and checking at write and retrieve time cut harm from 21.3% to 4.0% ([arXiv:2608.12851](https://arxiv.org/abs/2608.12851)).
- **Bloat and duplicates (measured).** One install had 152 skills, 22 of them zero-use near-duplicates ([#67582](https://github.com/NousResearch/hermes-agent/issues/67582)). A 182-skill, 4-agent audit found three-skills-in-8-hours clusters, skills copying the knowledge base, and 13 descriptions whose trigger words fell outside the ~57-character window (gfpyc on [#96704](https://github.com/NousResearch/hermes-agent/issues/96704)). Users blame the review prompt's "Be ACTIVE — most sessions produce at least one skill update". That phrase is still on main as of 2026-11-26.
- **Wrong and stale skills.** A transient Playwright failure became a permanent "browser tools do not work" rule ([#6051](https://github.com/NousResearch/hermes-agent/issues/6051), fixed only in the prompt). A night-time review fork wrote "close ALL Chrome windows" into a working, user-built skill, with no ledger entry. The background review persisted a proposal "within roughly ten seconds", before the user had answered. Nothing records when a skill was last verified ([#25833](https://github.com/NousResearch/hermes-agent/issues/25833)). Curator merges break cron jobs ([#26326](https://github.com/NousResearch/hermes-agent/issues/26326)).
- **Written but not loaded.** Accurate skills about a recurring `.env` corruption went unused, the corruption recurred "the 4th or 5th time", and the reviewer then added more warnings to the same unused skills ([#66180](https://github.com/NousResearch/hermes-agent/issues/66180)). Weaker models rarely call `skill_view` ([#4589](https://github.com/NousResearch/hermes-agent/issues/4589)).
- **Memory pollution.** Irrelevant memories steered a new session off-task, and a feature was saved as "a bug" ([#22563](https://github.com/NousResearch/hermes-agent/issues/22563)). Memory "accretes into a second, worse session history" ([#135039](https://github.com/NousResearch/hermes-agent/issues/135039)). The background writer ignores the curation rules a user gave their agent ([#30220](https://github.com/NousResearch/hermes-agent/issues/30220)). Snapshot-based reviews can overwrite newer entries ([#9055](https://github.com/NousResearch/hermes-agent/issues/9055), open). Cron boilerplate gets stored as user facts ([#141912](https://github.com/NousResearch/hermes-agent/issues/141912)). — [failure modes](./failure-modes-from-the-tracker.md)
- **Secrets.** Credentials stored in memory get "quoted verbatim" in chat and reasoning blocks ([#20785](https://github.com/NousResearch/hermes-agent/issues/20785)). Before 0.16.0, history and HMAC secrets were stored in world-readable files ([PYSEC-2026-2511](https://osv.dev/vulnerability/PYSEC-2026-2511)). Agent-written skills are not security-scanned by default (`skills.guard_agent_created: False`).
- **Cost (measured).** The background review fork used about 21% (heavy profile) to about 66% (idle profile) as many input tokens as the main loop ([#87250](https://github.com/NousResearch/hermes-agent/issues/87250)). Each learned skill adds about 20 tokens to every later API call: 400 learned skills put the index at 8,989 tokens, 27% of a 32k window (glromero on [#96704](https://github.com/NousResearch/hermes-agent/issues/96704)). Fixed overhead was 73% of each call in v0.6.0 ([#4379](https://github.com/NousResearch/hermes-agent/issues/4379)).
- **What users like.** Skills are plain files they can read and edit. Narrow repeated workflows do improve, for example a digest skill that grew from 12 to 62 lines with filtering and dedup over 7 days ([DEV](https://dev.to/sreejit_/i-ran-hermes-agent-on-the-same-task-for-7-days-the-skill-file-on-day-7-looked-nothing-like-day-1-2oa8)). Preferences get "internalized" after a few rounds. — [positive reports](./positive-reports.md)
- **Human gates exist but are off.** `skills.write_approval` and `memory.write_approval` both default to `False`, and `background_review.enabled` defaults to `True` (`hermes_cli/config_defaults.py`, main `4b38ec1`). A request to confirm before creating or overwriting a skill was closed not_planned ([#26298](https://github.com/NousResearch/hermes-agent/issues/26298)). The offline self-evolution tool does route every change through PR review.

## Open questions / gaps

- **Reddit and X originals were not read.** The fetcher cannot reach reddit.com (or its mirrors), so Reddit and X posts are cited only through the vendor's user-stories page or other write-ups. That includes the "It always thinks it did a good job. ALWAYS." quote (107 upvotes, no link given).
- **Some figures are unverified.** The "self-generated skills −1.3 points" SkillsBench figure is not in the current abstract. The Hermes involvement in arXiv:2610.03564 is not stated in its abstract. I could not open CVE-2026-10223 on NVD.
- **No maintainer position found.** None of the comments on the skill-quality issues ([#96704](https://github.com/NousResearch/hermes-agent/issues/96704), [#25833](https://github.com/NousResearch/hermes-agent/issues/25833), [#66180](https://github.com/NousResearch/hermes-agent/issues/66180), [#67582](https://github.com/NousResearch/hermes-agent/issues/67582)) came from someone with member or owner status. Whether the "Be ACTIVE" bias is intentional is undocumented. [#30220](https://github.com/NousResearch/hermes-agent/issues/30220) was closed "completed", yet the phrase remains in the code.
- **Several sources rely on fetch summaries.** Some figures, such as the FinSkillBench self-generated result and the user-stories details, come from WebFetch summaries of pages rather than full-text reading. They are quoted as such.
