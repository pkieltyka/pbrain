# Measurements and benchmarks of Hermes Agent's learning

What has actually been measured about whether Hermes's self-written skills and memory help, and what they cost. Labelled by strength: **controlled** (paired arms, fixed tasks), **field telemetry** (counts from real installs), **vendor/secondary claim**.

## Bottom line of this doc

There is no controlled public evaluation showing that skills written by Hermes's own background review improve later task outcomes. The project's own tracker says so: [#96704](https://github.com/NousResearch/hermes-agent/issues/96704) (open RFC, 2026-08-27) — "Nothing in the tree varies a skill or a memory entry and measures the downstream task outcome. So there is no answer, today, to 'does a skill written by the background review make the next session better, worse, or neither?'" Independent benchmarks run on the Hermes harness find curated (human) skills help a lot and self-generated skills help little or not at all.

## Controlled / academic

| Source | What | Result | Hermes-specific? |
|---|---|---|---|
| [FinSkillBench, arXiv:2608.18099](https://arxiv.org/abs/2608.18099) (v1 2026-06-09) | finance agent tasks, no-skill vs curated vs self-generated | no-skill mean 0.366 → curated 0.528; "self-generated skills provided little benefit despite higher computational cost" (fetch summary) | Replicated on Hermes Agent as an independent harness, 8 models, 5,280 episodes; "same directional pattern" |
| [Knowledge or Calculator?, arXiv:2610.03564](https://arxiv.org/abs/2610.03564) (2026-10-02) | decomposes the curated-skill premium | curated +16.2 pts; skills generated within the episode "add only +0.5 points" while using more tokens and turns; tools alone +19.5, docs alone +5.6 | Search results say it re-ran on Hermes with only skill list/view tools; the abstract I fetched does not mention Hermes — unverified |
| [PAST-Bench, arXiv:2608.04003](https://arxiv.org/abs/2608.04003) (2026-08-04) | retained experience on vs off across ordered fresh-session tasks; 26 scenarios, 204 episodes | gains "real but uneven"; similar headline gains can come without the intended save/retrieve/update pathway | Hermes is one of four frameworks; authors' "Hermes+" (five interventions) improves gain, most on "tasks requiring outdated state to be replaced". No numbers in abstract |
| [SkillsBench, arXiv:2602.12670](https://arxiv.org/abs/2602.12670) (v4 2026-06-14) | 87 tasks, 18 model-harness configs | curated skills "33.9% to 50.5% (+16.6 percentage points)" | Not Hermes. A blog cites it for "self-generated skills averaged 1.3 points below no skill" ([Eric Cao, 2026-06-12](https://eric.run.place/blog/en/can-you-teach-an-ai-intern/)); the current abstract does not state this — unverified |
| [SkillLearnBench, arXiv:2604.20087](https://arxiv.org/abs/2604.20087) (2026-04-22) | continual skill generation, 20 tasks | abstract: "external feedback [gives] genuine improvement ... whereas self-feedback alone induces recursive drift"; blog cites human skill 10%→74%, best self-generation ~39% | Not Hermes |
| [Practice Makes Unsafe, arXiv:2608.12851](https://arxiv.org/abs/2608.12851) (v2 2026-10-07) | skill misevolution: 525 tasks | "All 21 combinations wrote unsafe skills, and 15 carried the harm into the new session"; checking at write and retrieve cut new-session harm 21.3% → 4.0% | Harnesses not named in abstract; linked to Hermes by a tracker commenter, not by the authors |

Read together: skills as an artifact clearly help when a human writes them; agent-written skills from self-feedback are roughly neutral and can drift or turn unsafe; verification at write time is the lever the papers find.

## Project-side evaluation

- **No eval of the loop in-tree.** [#96704](https://github.com/NousResearch/hermes-agent/issues/96704) lists four existing harnesses (session_search, compaction, readtool, browser_use) and none covers skills/memory. Proposed arms: A (offline write-side quality: creation rate, trigger precision, duplicate-class rate), B (artifact present vs absent), C (loop holdout: "the review fires normally, then its output is withheld"). Commenters added: 3–5 replays per cell ("Single-run comparisons kept lying to us"), "make removal a first-class outcome", and an attribution chain `eligible → activated → adhered → effective`. As of 2026-11-06 work sits on a fork branch ([BlueRingsLabs learning-loop-eval](https://github.com/BlueRingsLabs/hermes-agent/tree/learning-loop-eval/evals/learning_loop)), tested "only ... against a scripted model". No maintainer has replied in the thread (all commenters association NONE).
- **hermes-agent-self-evolution (forge).** [Repo](https://github.com/NousResearch/hermes-agent-self-evolution): DSPy/GEPA offline optimisation of SKILL.md, "~$2-10 per optimization run", guardrails incl. full test suite and "PR review" — changes are never committed directly. Its phase-1 report (as summarised in [#96704](https://github.com/NousResearch/hermes-agent/issues/96704) by AngelCampa1): arxiv skill 0.408 → 0.569 (+39.5% relative), but fitness is "keyword overlap with an expected-behavior rubric", 7 synthetic cases, "headline number is measured on a single held-out example", benchmark-regression gate "Planned". Key contrast drawn there: forge has a human gate on every change; the in-session loop, with `background_review.enabled: True` and `write_approval: False` by default, does not.
- **"40% faster" claim.** Repeated widely ("GEPA ... cuts task time 40% after 20 self-created skills — independently verified", [Axis Intelligence review, 2026-05-28](https://axis-intelligence.com/?p=30521)). Axis attributes the number to an external TokenMix.ai benchmark, not its own test; other pages say "Nous claims" with no method ([weihaoqu wiki](https://weihaoqu.github.io/learnAIDoc/wiki/hermes-agent-self-improving-ai/)). The Hermes homepage makes no numeric claim ("It learns your projects, auto-generates skills, and never forgets how it solved a problem"). **Treat as unverified.**

## Field telemetry (real installs)

- **Write-side quality** — 182-skill and 70-skill deployments, see [failure modes](./failure-modes-from-the-tracker.md) §1–2 (gfpyc on [#96704](https://github.com/NousResearch/hermes-agent/issues/96704)).
- **Skill-count growth in a 3-week review**: 4 self-created skills by day 3, 11 by day 10, 17 by day 21; "Research tasks needed less step-by-step prompting by week 3"; "Skill transfer is domain-bounded" ([Axis Intelligence](https://axis-intelligence.com/?p=30521), v0.10.0). Counts measured; benefit is the reviewer's judgement.
- **One skill over 7 days**: 12 → 62 lines, v1.7, added source filter, rubric, dedup window, fallback threshold; author "didn't review the skill file during the week"; no success/cost metric, no control ([sreejit, DEV, 2026-05-16](https://dev.to/sreejit_/i-ran-hermes-agent-on-the-same-task-for-7-days-the-skill-file-on-day-7-looked-nothing-like-day-1-2oa8)).
- **Approval-gate compliance audit**: an external script over 129 sessions (2026-04-05..29): "112 of 129 sessions contain at least one violation (86.8%)"; the agent's own `platform-hardening` skill "self-assessment understated the scope significantly" [#17619](https://github.com/NousResearch/hermes-agent/issues/17619). Evidence that a skill describing a rule does not enforce it.

## Cost

- **Learned skills grow every later prompt.** glromero ([#96704](https://github.com/NousResearch/hermes-agent/issues/96704), 2026-11-06), offline, two runs agree, main at `90c19e31`: skills index 1,015 tokens at 0 learned skills, 2,875 at 100, 8,989 at 400 (27.4% of a 32k window) — "each learned skill adds around 20 tokens to every later API call until the curator archives it. MEMORY.md and USER.md at capacity cost 941 tokens and stop there." Break-even: a learned skill is a net cost unless its savings exceed ~20 tokens × every API call of every session that doesn't use it. Review fork cost stated in code as "~30K tokens / event". Review only fires after a turn with ≥10 tool iterations (skills) or every 10 user turns (memory). *Measured.*
- **Background review fork share.** [#87250](https://github.com/NousResearch/hermes-agent/issues/87250) (v0.20.1, re-measured 2026-08-15): profile A 82 forks, 34.4M input in 6 days ≈ "21% of what the conversation itself used"; profile B (mostly idle) 65.5M input in 18 days ≈ "66% of main-loop input"; ~90% cache reads; forks ran to the 16-iteration cap because the prompt discourages "Nothing to save"; usage was invisible to `session_model_usage`. Fixed for accounting/config via PR #87400 (closed 2026-08-16). *Measured.*
- **Fixed per-call overhead.** [#4379](https://github.com/NousResearch/hermes-agent/issues/4379) (v0.6.0, closed 2026-09-12): "73% of every API call is fixed overhead" (~13.9K tokens: tool definitions 8,759, system prompt + skills catalog 5,176). *Measured on 6 request dumps.* [#2045](https://github.com/NousResearch/hermes-agent/issues/2045): 87 bundled skills ≈ 1,500–2,000 tokens of listing.
- **Session replay.** [#5563](https://github.com/NousResearch/hermes-agent/issues/5563) (2026-04-06, Claude Opus, 8+ h/day): "~2.6M tokens (~69% of total consumption)" lost to context replay in one 12-hour session; "turned a productive 12-hour workday into burning through an entire monthly API budget". *Measured from session files.*
- **Silent fallback to the main model.** "603 million tokens in seven days" when 12 auxiliary tasks (compression, curator, flush_memories, session_search ...) fell back to the main model ([azamat_safarov, DEV, ~2026-06-02](https://dev.to/azamat_safarov/hermes-agent-burned-603m-tokens-behind-my-back-i-cut-background-costs-by-up-to-125x-43oi)); no per-task breakdown; "125x" is a parameter ratio, not a measured saving.
- **Aggregate spend**: OpenRouter's public app page, 30 days to 2026-04-14: 1.96T tokens, ≈$3.15M/month on priced rows (modelled 72/28 input/output split) ([CodeSOTA](https://codesota.com/agentic/hermes-agent)). Scale indicator only.
- **Individual spend**: newsletter author ~$22/month, cut "from about $2 a day to about $0.50" by lowering memory cap to 1,300 chars and restricting cron toolsets ([HolmeBengt, 2026-08-02](https://buttondown.com/HolmeBengt/archive/why-your-hermes-feels-slow-and-costs-to-mutch-its/)). *Anecdote.*
