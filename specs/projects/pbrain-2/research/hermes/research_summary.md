# Research: Hermes (automatic skill creation and "learns by doing" agents)

## Bottom Line

The "Hermes" people praise is **Hermes Agent** by Nous Research: an MIT, self-hosted, model-agnostic Python agent harness. It launched in February 2026, moves fast, and is still pre-1.0 (v0.23.4, 2026-11-24). Mnemosyne's `integrations/hermes` targets this same host. Its "learns by doing" is not a judgment the model makes. It is a **counter-triggered background fork**: every 10 user turns (memory) or 10 tool iterations (skills), a copy of the agent replays the conversation. It patches or creates agentskills.io-style `SKILL.md` files and two tiny frozen-snapshot files, `MEMORY.md` and `USER.md`, with no human approval by default. Users do report that narrow, recurring tasks get better. But no controlled evaluation shows that the stock loop's self-written skills improve outcomes. Independent benchmarks find that curated skills help a lot and self-generated ones help little. The tracker also documents bloat, wrong rules that stick, silent rewrites of working skills, unused skills, memory pollution, secrets quoted back, and review costs of 21–66% of main-loop input tokens. For pbrain-2, take Hermes's **prompt discipline and shape rules**, its **bounded frozen snapshot** and its **provenance and never-auto-delete** habits. Refuse the **unattended writer**. Route learning through pbrain's authored handoff and Git review, and add "doc" as a promotion target.

## Key Findings

- **Hermes Agent is the right Hermes, and it is the same host Mnemosyne plugs into.** It is separate from Nous's Hermes LLMs. It runs as a TUI, a messaging gateway (~25 platforms), an ACP editor agent, Desktop/Webapp, or cron. It has a single memory-provider slot, which Mnemosyne fills. The "co-worker" wording comes from NVIDIA's NemoClaw blueprint, not from Nous. ([what-hermes-is](./what-hermes-is/research_summary.md))
- **Skill creation is a counter plus a prompt.** `skill_review_due` fires at 10 tool iterations since the last skill write. The fork is told to "Be ACTIVE" and to update before it creates: patch the loaded skill → patch an umbrella skill → add a support file → create a class-level skill. The only hard duplicate check is an exact name collision. ([skill-creation](./skill-creation/research_summary.md))
- **The quality rules are the reusable part.** The prompts say: save "lessons, not logs"; save only facts "GROUNDED in this conversation"; never infer user traits; no negative claims about tools; "the same lesson learned twice is ONE rule"; fix in place. The linter's calibration notes record what happened without these rules: a 100k-char incident-log skill and a skill with 443 per-session reference files. ([skill-creation](./skill-creation/research_summary.md), [memory-and-learning-loop](./memory-and-learning-loop/research_summary.md))
- **Memory is small, bounded and frozen.** `MEMORY.md` is capped at 2,200 chars and `USER.md` at 1,375. Both are injected once at session start to keep prompt-cache hits. An overflowing write errors, and the model must curate. Transcripts go to SQLite and are searched with FTS5 (no LLM since May 2026). One optional external provider attaches through a `MemoryProvider` interface with prefetch, sync, session-end, pre-compress and mirror hooks. ([memory-and-learning-loop](./memory-and-learning-loop/research_summary.md))
- **Governance is after the fact and mostly off.** `write_approval` exists but defaults to false, and generic file tools bypass it (#60440). A content-addressed ledger allows rollback of a single mutation. The curator archives stale skills (14 days stale, 30 archived), and umbrella consolidation, which is LLM-driven, is opt-in. Pin and lock flags exist. There is no semver and no Git integration. ([skill-creation](./skill-creation/research_summary.md))
- **Skills are loaded only if the model chooses to load them.** The system-prompt index clips descriptions to about 60 chars. Users found trigger words cut off, accurate skills left unused while the failure they describe recurred, and weaker models that rarely call `skill_view`. Each learned skill adds about 20 tokens to every call (400 skills came to 27% of a 32k window). ([skill-creation](./skill-creation/research_summary.md), [evidence-and-reports](./evidence-and-reports/research_summary.md))
- **Evidence: anecdotes for, measurements against the stock loop.** Positive reports cover narrow, repeated workflows, such as a digest skill that grew from 12 to 62 lines over 7 days. Hermes's own tracker says nothing measures downstream effect (#96704). The "40% faster" claim has no method behind it. On FinSkillBench run on Hermes, curated skills scored 0.528 against 0.366 with no skills; self-generated ones gave "little benefit". The Misevolution study found unsafe self-written skills in all 21 combinations it tested. ([evidence-and-reports](./evidence-and-reports/research_summary.md))
- **Unattended writes damage shared, trusted state.** In #105921 a fork deleted four standing permission rules from `MEMORY.md`; the user caught it only by diffing Git. In #32858 the review prompt was saved as the user's own preferences and synced to Honcho. Snapshot-based reviews overwrite newer entries, and credentials in memory get quoted verbatim. ([lessons-for-pbrain-2](./lessons-for-pbrain-2/research_summary.md), [evidence-and-reports](./evidence-and-reports/research_summary.md))

## Implications

- **Learning loop.** Keep pbrain's single authored handoff at Stop. Do not add a periodic fork, which does not fit a tool that harnesses call. Copy the grounding rules, the do-not-capture list and the update-before-create rules into the pbrain skill and handoff prompt. Leave out the "Be ACTIVE" bias.
- **Agent-facing file.** Use a static, human-written `BRAIN.md` pointer plus a dynamic, frozen `pbrain recall --task` snapshot at SessionStart (the design caps it at 3 rows and 1,200 chars). Do not commit an agent-written `MEMORY.md`: Git history cannot be forgotten, and the file would churn across worktrees.
- **Skills become docs.** Add a doc under `./docs` as a third `promote` target. Search docs before creating one (update before create). Use read-before-write as a content-hash compare-and-swap. Deliver through normal Git review, and turn the gate on by default for shared writes.
- **Hygiene.** Write a read-only report at most (docs never retrieved, broken cited paths) and a front-matter lock flag. Never auto-delete, and never feed usage data into ranking.
- **Admission.** Extend `secretscan` to reject invisible and control Unicode and the hook prompt's own text. Follow `/learn`'s rule of forcing a neutral author name: an author name taken from the environment leaks private data.
- **Still to decide in the spec:** the doc front-matter policy, and whether top doc hits join SessionStart injection. The planned 24-task evaluation should settle the second. Hermes's lack of evidence argues for measuring pbrain-2's loop from the start.

## Conflicts and Uncertainty

- **Vendor claims versus evidence.** Nous's README and marketing ("creates skills from experience, improves them during use") are not backed by measurement. Independent benchmarks and the tracker point the other way. The evidence leans towards "helps on narrow repeated tasks, unproven in general, with real costs".
- **Docs lag the code.** The README still advertises LLM-summarised session search, which was removed in May 2026. April 2026 write-ups describe a `replace` memory action and in-chat nudges that no longer exist. The Curator docs disagree with the code on archive timing (30 vs 90 days). All mechanism claims here are pinned to v0.23.4 or main of 2026-11-26. Behaviour differs in older releases.
- **The "Be ACTIVE" bias is unresolved.** #30220 was closed "completed", yet the phrase is still on main. No maintainer has said whether the bias is intended.
- **Scanning is uneven.** Memory writes are threat-scanned. Agent-created skills are scanned only in the background fork; in the foreground the scan is opt-in (`guard_agent_created: False`).
- **Small open discrepancies:** where Honcho injects recall (the docs say system prompt, the provider contract implies the user message), and the index clip length (60 chars in the code versus ~57 in a user's audit).

## Gaps

- **No controlled evaluation of Hermes's self-written skills or memory.** None exists (#96704 is open). Closing this needs a holdout-arm harness, which pbrain-2's own evaluation could include.
- **`/learn` staging is unread.** The MarkTechPost article returned 403 and the skill-integrity plugin page returned 404. Closing it needs a read of `agent/learn_prompt.py` and the related code paths.
- **Some figures come from fetch summaries of large pages**, not verbatim reads: the #7816 curator numbers (346 skills → 249 archives / 18 umbrellas), the FinSkillBench self-generated result, and the user-stories details. Re-read the full text before relying on them.
- **Reddit and X originals are unfetched.** They are cited only through vendor pages and write-ups.
- **Unknown write rate.** How often reviews actually write after PR #17213 (April 2026) is not known. Neither is whether the cheaper-model review really captures "identical" memory.
- **Not read:** the Hindsight, Mem0, Supermemory and OpenViking provider sources. The pbrain cost figures in the lessons subtopic are qualitative judgements, not measurements.
