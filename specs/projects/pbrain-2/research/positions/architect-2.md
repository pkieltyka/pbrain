# Independent position for pbrain-2

**Build memory and docs around one learning loop.** An agent working on a task can leave a grounded observation for its successor. When that observation proves useful again, an author can propose a change to a document the team already reads. The successor should be able to cite that document after the original handoff expires. Preserve arbitrary Markdown discovery as well as the standing and history of managed decisions.

## Learning across sessions

- `store` records an attributed, unreviewed observation such as a blocker, experiment outcome or next action. Start with explicit text. A proposed decision found through recall is still a claim until independently checked. Team handoffs expire in seven days and blockers in fourteen, with a cap of 10,000 live rows per view and replay bounds as in #83. An agent or person can forget a row early. No memory TTL can remove a reviewed item.
- `recall --task N` gives a bounded recent page even without query words. Text recall starts lexical, with task/view filters, recency, source and observation time visible; evaluate semantic recall on missed paraphrases before adding a memory-specific embedding threshold. Keep documents and memories in separately labelled pages, including in MCP. A document search must never quietly inject transient memory. If a memory says CI passed and the cited run says it failed, the run wins.
- Start automatic capture with a factory-managed, fresh, shared-only worker. A session-start hook recalls for the task. A once-only Stop prompt asks the agent for what it learned and the next action; an enrolled broker admits one authored summary. Establish eligible inputs and file access at launch; revoke before any unknown/private ingress and recheck at broker write. In mixed or unmediated sessions use explicit store only. Do not harvest chat. Structured bus reports remain visibly unverified for every producer, ranked behind authored rows, ineligible for promotion. Scan all admitted text and metadata before storage/logging; secret scanning cannot establish privacy. Never read or probe a private view for a shared request. Treat recalled prose as quoted, untrusted evidence, never as system instructions.
- `promote` takes authored memory only. Preview exact Markdown, destination, author and status, confirm the frozen bytes in the selected checkout, then use ordinary Git review. Never route private memory to shared. A typed pass/fail report cannot acquire a verified header by changing its title or kind; independently cite the actual run in a new item. Manual promotion gives the team a durable institutional memory days after transient rows have expired.

### What the Hermes research changes

Use one prompt at a task boundary. Ask “What did you observe, what source can the next agent check, and when would this matter again?” Permit an empty answer. Skip routine logs, duplicated lessons, inferred preferences, prompt text and secrets. Give a shared worker a neutral enrolled actor label and task-scoped source; avoid inheriting personal Git author details in an automatic write. The recorded Hermes review costs of 21–66% of main-loop input tokens come from particular reports. They justify measuring our capture cost even when no row is saved. They do not establish the cost or benefit of our proposed hook. The evidence for curated skills supports testing reviewed lessons on recurring tasks; downstream benefit from Hermes's unattended writer remains unproven. [Hermes evidence and reports](../hermes/evidence-and-reports/research_summary.md)

At SessionStart inject a frozen, quoted task page once, initially up to three rows and 1,200 characters including provenance labels. An explicit recall reads current state and honors expiry, forget and view selection. Forgetting stops future retrieval; it cannot redact a previous model input. Keep document search available on demand. Test doc hits in the initial page as a separate condition before spending that context on every session. Use the hard limit for the whole page across sources. [Hermes memory and learning loop](../hermes/memory-and-learning-loop/research_summary.md)

Add an ordinary document as a possible same-view promotion target alongside a managed learning or decision. Before proposing a new doc, search for an existing one. For a new target, preview exact path and bytes and use exclusive creation. For an existing doc, preview the base digest and proposed diff, preserving unrelated content and foreign front matter. A stale base requires a fresh preview. External editors need not take pbrain’s lock, so an initial implementation can return a Git patch for review and application while avoiding direct replacement of the live file. The host hook has no authority to confirm, install a skill, rewrite operating instructions, or remove a reviewed document. A typed report remains ineligible for all targets. A human-maintained procedure can be indexed and cited like other Markdown without treating retrieval as authority to execute it. [Lessons for pbrain-2](../hermes/lessons-for-pbrain-2/research_summary.md)

## State and concurrent writers

| State | Identity, storage and locking |
|---|---|
| Documents and managed items | Originals stay in the checkout. An item writer keeps the existing section lock and exclusive publication protocol. An external editor need not take a pbrain lock. Validate changes before returning cached rows. |
| Derived document indexes | Move shared derived SQL images/manifests to the guarded per-user cache. Namespace by project **and resolved checkout**, view and configured roots. Verify input coverage and model/chunker/writer fingerprint as today. Two divergent or dirty worktrees must never publish into the same current generation, even at identical HEAD. A stable per-index lock serializes publication. Preserve the memory-only SQLite/handle-relative snapshot design. |
| Models and vectors | Reuse verified model bytes and identical eligible shared content/profile vectors across worktrees. Keep private text, vectors, counts and generations in the guarded personal view. Rebuilding or purging shared caches must never traverse it. |
| Original memories | Recommend a separate local **state** directory, e.g. Linux XDG state or Darwin Application Support, with a guarded private mode and a harness allow-list. Memory text has no original to rebuild after a cache purge. This changes #83's suggested cache location; if the owner wants explicitly flushable scratch memory, cache storage is a viable choice with that loss stated. Keep personal memory under the resolved private root. Avoid writes to Git metadata. |

Derive the team-memory key from the canonical Git common directory and the selected brain's repository-relative location, independent of the caller's checkout; a brain outside Git uses its own canonical path. A fresh clone enrolls separately. Branch names and remote URLs are poor keys: branch switches disrupt continuity and forks can share a remote. Enroll one team per OS user and machine; no distributed sharing promise. Record task plus origin worktree/revision if available, marked as context, so a result on one branch cannot imply success on another. Shared state does not grant OS isolation from a malicious same-user process.

Use one bounded snapshot per view with a stable file lock, read-modify-replace through open directory handles, flush and directory-sync. Readers see an old or a new complete snapshot. Check event nonce plus immutable observation time to handle retry, reject conflicting payloads, and keep content-free tombstones to defeat late replays. Test crash, forget versus replay, concurrent admissions and a reader during publication on two worktrees, including Darwin. Measure bytes rewritten under five agents before choosing a database or journal. Keep memory locks out of warm tool leases. For promotion alone use the ordered memory-then-item lock and durable one-use spent token from #83.

## Documents and standing

For a newly initialized project, configure one or more named, relative document roots, initially `docs/`. Discover regular UTF-8 Markdown recursively, including newly dropped files. Recheck the eligible file set and current bytes on reads. Lexical discovery should work before the first embedding build. Semantic results must use current passages under existing catch-up/freshness limits. Keep file-line and body-offset citations, including for files with no metadata.

Use **root roles** to decide which parser and writes a file admits. Existing managed item roots retain their current parser, IDs, kinds, graph, audience and `check` behavior, including findings on malformed items. Allow pbrain to create managed decisions and learnings there. A plain-document root always yields a document, even if somebody included YAML keys called `status`, `decided` or `replaces`. Neither a missing block nor a partial or foreign block makes its author a pbrain author. Leave source bytes untouched. For a well-formed leading metadata mapping, allow a bounded scalar title as display text, otherwise use the first heading or filename. Preserve physical line coordinates through the consumed header. If a candidate header is malformed or unclosed, preserve the file as ordinary text with original offsets; never infer standing, routing, links or tags from that block. A plain document can link by ordinary Markdown path/anchor; only a managed item participates in pbrain's `replaces`/standing graph. Give a loose file an opaque, disjoint ID derived from named root and exact relative path. Same basename in two directories is valid. Renaming it invalidates its old citation; permanent citations belong to managed items or a pinned Git revision. Report ambiguous roots, aliases and case/Unicode path collisions without selecting a winner. `check` can report document problems separately without treating absent pbrain front matter as an error.

Root declaration fixes the view before walking. Reject intersecting shared/private roots and managed/plain overlap, exclude Git and pbrain metadata, do not follow symlinks, and keep the personal exposure guard. A source field or foreign front matter cannot change scope. New enrollment must show which directories become shared, including untracked Markdown; no automatic broadening for an existing brain. Do not quietly remove blocked bodies from results while retaining their titles, counts, paths or vectors.

## Interface, rollout and decision

Offer `pbrain docs search|get|list|check|sync`, and `docs add` for an authored managed item; a loose file already exists and needs no add ceremony. Keep `store|recall|forget|promote` at the top level. For v1 brains freeze existing root selection, command names, JSON, errors and #80 tool identifiers. A namespace alone must not expand the old `pbrain search` result type to include arbitrary docs. Share execution paths where contracts match. Add distinct catalog tools for genuinely expanded results and use the same per-call binder for #81. Enable broader roots only after an explicit config migration with a dry-run inventory; preserve item IDs and Git source bytes. No immediate removal of old aliases or schema changes in place.

The skill owns the portable workflow. I would ship one optional, human-maintained BRAIN.md pointer if a team wants a discoverable entry point: where the docs are, how to recall for a task and how to propose durable knowledge. No generated memory digest in Git, no private contents, no startup rewrite. Use the bounded SessionStart page for automatic context. Recheck scope and freshness on every explicit recall.

Start with (1) manual memory across worktrees, task recall and forget; (2) loose Markdown discovery and guarded checkout-local derived indexes, with old-brain parity and file/rename/privacy cases; (3) one lifecycle adapter and reviewed promotion to an item or doc. Freeze the retained 35-note retrieval oracle, add unfrontmattered long documents and same-name files, test new/edited/deleted docs without stale citations. For learning, pair 24 synthetic handoffs on at least six tasks with identical budgets, agent/build and scheduling. Score correct resumption, repeated failed work, false carryover, source-backed decisions, cold/warm latency and time spent writing. Count all capture and injection tokens, duplicate or unused lessons, incorrect lessons repeated by a successor, and human review time. An outcome counts as durable learning only when a fresh agent independently succeeds on a held-out recurrence using the cited, reviewed lesson after the handoff expires. Proposed minimum: four more correct resumptions, zero private/secret leaks, no increase in wrong durable decisions. Report ineligible-session rate and repeat a task after TTL to check whether reviewed learning survives. Risks to watch are write amplification, checkout divergence, accidental publication of private notes, excessive startup context and confident repetition of stale claims. A recall-hit count alone answers none of these questions.
