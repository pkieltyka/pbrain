# pbrain-2 — lead-dev position

**Recommendation.** Build a variant. Make ordinary Markdown easy to find and give agents an explicit way to record and recall what they learned. Keep managed decisions and learnings in Git, with their current authority and review rules. Ship the memory path first, then expand doc discovery. Treat the docs scanner, memory store and CLI namespace as separable changes so teams can adopt each without migrating an existing brain.

## Memory and the learning loop

Start with explicitly authored observations, handoffs, blockers and sourced findings. A stored statement can report a decision, with author and time attached. It acquires project standing through the managed Git-item flow. Use #83's bounded snapshots and replay receipts, lexical/task-only recall, visible age/source and scoped forget. The proposed 7 days for handoffs/outcomes and 14 for blockers is a good initial bound for working memory. Longer retention is a separate decision with a measured need. A useful finding becomes durable when later agents can retrieve and apply it after the original memory expires.

**Take the prompt discipline from Hermes.** On departure, ask the active agent for one lesson or handoff grounded in evidence it actually saw. Require the source, what applies, and what is still uncertain. Skip logs, inferred preferences, credentials, personal material and unchanged repetitions. Ask the agent to search relevant knowledge and propose a revision to an existing entry before adding a competing one. An empty handoff is a valid outcome. Use explicit `store` first, then the #83 factory-managed worker. At startup inject one frozen, task-scoped page capped at three rows and 1,200 characters, with source and age. Fetch further context on demand. Keep injected prose advisory and compare against current docs before acting when it carries authority or could be stale. Start with memory-only injection so the pilot isolates what memory adds. [Hermes research synthesis](/home/peter/Dev/pkieltyka/pbrain/specs/projects/pbrain-2/research/hermes/research_summary.md)

**Keep the write boundary.** Allow shared handoff prose only with positive shared-only provenance through the actual broker write. Typed bus reports remain unverified, source-labelled, below authored handoffs and ineligible for promotion. Reuse secret scanning with value-free failures, separate private state and a fresh per-call view. Hook output cannot grant permission. No periodic background fork, transcript harvesting, unattended skill creation or rewrite, inferred user profiles, or generated `MEMORY.md`. The research synthesis reports bloat, sticky wrong rules, silent changes and secret echo, plus review overhead of 21–66% of main-loop input tokens in the reported cases. Evidence for curated skills does not establish a gain from self-written ones. Keep those numbers as prior evidence and measure our own end-to-end loop. [Hermes evidence and limitations](/home/peter/Dev/pkieltyka/pbrain/specs/projects/pbrain-2/research/hermes/research_summary.md)

**Promotion closes the loop.** First use #83's guarded publication, frozen preview bytes and durable one-use token to propose a learning or decision with a lasting citation. Once configured doc roots have stable addresses, allow a runbook or other doc as a distinct promotion target. Search the existing docs first. For an update, start with a reviewable patch based on the current target bytes and reject a changed base before applying it. A Git review can accept the change. Expiry can remove ephemeral memories. It cannot alter or delete a tracked doc, skill, learning or decision.

## Docs and front matter

Use `./docs` as the default document root for a **new** setup, relative to the project config. Let a project name other roots and exclude generated or vendor Markdown. Existing brains retain their configured location and current scope until explicitly enrolled. Resolve roots once, reject overlapping or escaping roots in the first implementation, and reuse the guarded walk. “Drop a file and find it” should mean immediate lexical search after the file lands and semantic coverage after sync or bounded catch-up. It should never mean following arbitrary symlinks, bypassing ignores, or indexing the personal tree in the shared view. [Current discovery and walk](/home/peter/Dev/pkieltyka/pbrain.worktrees/peter-lead-dev/internal/store/store.go:288)

- **Ordinary docs** get a namespaced, root-relative path address and existing file-line/body-offset citations. A rename updates the address on the next scan. Equal filename stems in different folders are normal. Files with no header are searchable as-is. Safely parsed foreign or partial headers may supply a title and documented display metadata, such as validated tags. Fall back to a heading or filename. Malformed or oversized metadata falls back to text within the existing file-size limits. Preserve source bytes, never fill front matter automatically, and ignore foreign kind, status, audience and replacement fields for authority. Git placement and config determine which view may read a file.
- **Managed items** keep their current stem IDs, type/standing, links, replacement rules and checks. Use an explicit managed area inside the doc roots, with that area scanned once, or a separate existing managed root. Never infer item status from a coincidental `kind` or `decided` key in an arbitrary doc. In a managed area, missing or broken required metadata remains a `check` finding and does not silently reclassify the file. Cross-references to ordinary docs can start as citations. Keep `replaces`, `verify`, and ID-based editing on managed items.

Today the walker already discovers regular Markdown. `Catalog.readOne` couples admission to `item.Parse`; its filename identity and graph rules then flow into reads, writes, checks and semantic indexing. The cheap seam is a separate document admission path feeding a read-only search representation. Making every file look like a synthetic item would create ID collisions, accidental replacement edges, and old edit commands targeting unmanaged files. Give the semantic layer a document key and the existing passage/text plumbing. Preserve managed-item line and offset semantics. ## Local state and worktrees

Put **derived shared indexes** under the guarded per-user cache, using the existing cache override and platform defaults. Key them per project **and checkout**, with corpus configuration in the generation identity. Two linked worktrees can have different bytes at the same path. They must never publish into one manifest. Keep model assets and eligible shared vectors reusable by their existing content/profile identity. Change that identity only when the input or vector contract changes. Preserve a separate private namespace, preferably under the resolved personal section for the first migration. Moving personal generations later needs a separate guarded cache root unreachable from shared operations. Keep the current validated in-memory SQLite image and handle-relative publication. [Current manifest](/home/peter/Dev/pkieltyka/pbrain.worktrees/peter-lead-dev/internal/semantic/index.go:57)

Originals are source evidence. Keep them with their section and preserve their export, backup and cleanup rules. Keep item and settings locks beside what they protect, so old and new writers serialize. Put the index lock beside its new manifest. Treat old derived generations as expendable, leave them in place through the compatibility window, rebuild on first new sync, and show readiness explicitly. No checkout rewrite or copying of old vectors across incompatible identities. [Existing lock contract](/home/peter/Dev/pkieltyka/pbrain.worktrees/peter-lead-dev/specs/projects/pbrain/architecture.md:1022)

**Retained memories** deserve an owner-only per-user state directory, separate from disposable cache eviction, if the team expects them to survive until their retention deadline. Reuse the peer-reviewed #83 snapshot design and exposure checks. Key shared state by canonical Git common-directory identity and brain-relative path with local enrollment, independent of the calling worktree. An external brain is resolved in its own context. Separate clones, users and machines have separate state in v1. Keep personal memories under their resolved personal root. A stable shared-state lock serializes writes across worktrees. A sandbox should be granted its designated state child or a broker call. Git metadata stays read-only.

## CLI and skill

Add `pbrain docs search/get` for the new document contract, with ordinary documents and managed items labelled distinctly. Keep `prime` on managed standing. `docs add` can delegate to managed-item add if users want a namespaced write verb. Documents dropped into roots can still be edited with ordinary tools. Preserve existing top-level commands, flags, IDs, outputs and #80 tool names for current workflows. Parse namespace routes into the same executor. Give genuinely new result shapes new catalog entries, with CLI/Bind/Call parity, and avoid exposing duplicates to agents merely because there are two spellings. Keep `store/recall` as memory operations. A caller can ask for separately labelled memory and document results later. Do not merge their scores or use recall as an alias of search. [Existing catalog/binder](/home/peter/Dev/pkieltyka/pbrain.worktrees/peter-lead-dev/internal/cli/catalog.go:155)

Use the skill to say when to recall, when to store, what must be cited, and when to propose a durable item. A small optional project-owned `BRAIN.md` can name local roots and team conventions or link to the skill. Keep it static, human-controlled and free of private material. Skip a generated memory summary on disk. It would be a second, stale context surface with tricky invalidation and disclosure. Inject only bounded, current rows at the supported hook.

## Build order and gates

1. Deliver manual `store/recall/forget` across two worktrees. Add reviewed promotion into the current managed Git items once publication and replay faults are tested. Keep the snapshot format bounded and measure contention, write amplification and warm recall before introducing a log or another storage engine.
2. Qualify one restricted factory adapter and evaluate a frozen synthetic handoff set against skill and docs alone. Include a later task where a prior lesson must be applied and another where stale advice must be ignored. Measure correct resumptions, duplicated work avoided, wrong decisions, citations, all prompt/recall tokens and producer delay. Count excluded sessions and repeated or unused captures. Require zero shared differences when private data is added, and prove a promoted finding remains discoverable and useful after its memory expires. Score the mechanism on outcomes rather than how many notes it creates.
3. Deliver opt-in plain Markdown lexical search and path-addressed reads alongside a frozen legacy compatibility fixture. Run the same admission cases through semantic sync/status/search and relocate the shared index as a separate migration. Cover missing/foreign/broken headers, equal stems, rename/delete, long evidence near the end, linked worktrees at divergent revisions, and private/ignored/symlink sentinels. After the guard and addressing tests pass, add the reviewed docs promotion target.

The large costs are preserving byte/citation and ID compatibility, separating worktree generations, and proving the host disclosure boundary. A broader docs corpus can slow scans, dilute answers, and make the first CPU index expensive. Confirm quality and abstention on the existing fixture plus realistic ordinary docs before changing defaults on existing projects. I would defer automatic summaries, remote sync, cross-machine memory, schema churn, and any new required model or service. Keep #80's pilot and #81 paused while the owner decides the command and storage contracts.
