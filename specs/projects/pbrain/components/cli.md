# Command line

`internal/cli` turns one invocation into a typed command, opens the resources that command needs, and writes the result, notices and errors. The command owns argument validation and exit status. Brain owns discovery and configuration. Search, graph, render, the write transaction, import and index own their respective results. [Functional spec §§5–10](../functional_spec.md) · [Architecture §§6, 9, 10 and 13](../architecture.md)

## Entry point

```go
package cli

type Env struct {
    Args []string
    Stdin io.Reader
    Stdout, Stderr io.Writer
    Getenv func(string) string
    Dir string
    Now func() time.Time
    Rand io.Reader
    Git gitx.Runner
    Net fetch.Net
    Files sys.Files
    Models embed.Registry
}

type Features struct { BM25 bool }
var Release = Features{}

func Run(ctx context.Context, env Env) (exit int)
func RunWith(ctx context.Context, env Env, f Features) (exit int)
```

`Args` excludes argv[0]. The process adapter in `cmd/pbrain` supplies the working directory, the invocation environment, clock, cryptographic random reader, native files and network, and `gitx.NewRunner(executable, environ)`. `cmd/pbrain` saves the process’s real output streams in `Env.Stdout` and `Env.Stderr`, and points `os.Stdout` and `os.Stderr` at the null device before running any command. It supplies nil Stdin for a terminal, the actual reader for a pipe or redirected file. Check whether the actual stdin descriptor is a terminal at the process boundary. For a terminal, a body-less add has an empty body. A zero-length pipe is a valid empty body. Run never inspects a process-global stream or clock. Only main calls `os.Exit`. The process adapter supplies `Env.Models` through `embed.NewRegistry`, with the bge-small entry backed by aikit and `gemma2.Entry()` once its adapter passes its release gates. The [semantic design](semantic.md) defines the adapter entries. The registry’s Derive method is used only inside embed.Pack. Semantic commands use its supported-model metadata, adapters and query/document embedding implementation. An ordinary lexical command never opens a model. CLI tests supply a fixed registry.

Capture one instant from Now and use a constant closure returning it for the command. In main the clock returns the instant in the machine's zone. Use that instant’s Location when Getenv("TZ") is empty: the main adapter supplies the effective system location when TZ is unset, UTC when TZ was explicitly empty. This preserves the distinction without changing Env.Getenv. For a nonempty zone, trim one optional leading colon and load its IANA name. Embed the standard library’s time/tzdata in the executable for minimal hosts. Use UTC for UTC. Resolve it once and pass it with the instant to time-window parsing, ranking and review dates. For a bad supplied zone, a command requiring local calendar arithmetic returns usage with a fixed zone diagnostic. No command changes the process location; independent commands can run concurrently with different zones. UTC item timestamps are the same instant converted to UTC.

## Init output

The default location prints `initialized <path>` on one line. For a custom location use the path and selector from `brain.Init`. When they are equal, print one line: `initialized <path> — outside the brain, use --brain or PBRAIN_DIR (from this directory, use this path)`. When they differ, print `initialized <path>` and then `outside the brain, use --brain or PBRAIN_DIR (from this directory): <selector>`. Each line ends in LF. This labels a selector value; it is not a shell command.

Use `render.ExactPath` on each value independently. An unrepresentable path prints as `?`. For an unrepresentable custom selector, print one line, `initialized <path> — selector unavailable (invalid UTF-8)`. Initialization still succeeds. JSON uses the encoded path and selector tokens directly. Include `path` when representable, and `selector` only for a custom, distinct, representable value. A custom location also carries `hint` with the corresponding explanatory text above, without the path, selector, or their separators. Read `path` as the selector when the hint says to use this path.

## Command grammar

The global flags are `--brain DIR`, `--personal`, `--json`, `--help` and `--version`. Boolean flags use pflag boolean semantics; required values support separate and equals forms. Flag names are exact. Global flags may precede the command or follow it. A command's local flags may appear between its operands. A literal `--` ends option processing. Only repeatable flags accumulate values. Use StringArray or equivalent so a comma in one value does not become a second entry. Preserve presence as well as value: an omitted summary, title override, author or destination is distinct from an explicitly empty value. Reject a supplied empty path selector as usage. Use pflag's ContinueOnError with automatic printing disabled.

| Command and operands | Local flags | Handler |
|---|---|---|
| `init` | `--path DIR` | brain.Init, then print its display path and custom-location hint |
| `skill [list\|TOPIC]` | none | embedded core, names or exact topic |
| `search QUERY…` | filters, page, `--context N`, `--color`, `--semantic`, `--bm25` when released | exact matches, optional semantic and partial matches, result fitter |
| `list` | filters, page | inventory |
| `get ID` | `--color`, `--history`, `--outline`, offset and max-chars, limit only in history/outline | body, lineage or headings |
| `prime` | repeatable tag, offset and max-chars | current decisions and verified learnings |
| `tags` | page | tag inventory |
| `check` | page | findings and global error count for this view |
| `add` | `--title` required, `--kind`, `--body`, `--body-file`, `--source`, `--decided`, `--verified`, repeatable `--tag`, `--replaces`, `--relates`, `--stale-after`, `--author`, `--shared` | new first-party item |
| `import INPUT` | `--title`, `--source` on a file, `--link-only`, `--summary` on a linked import, repeatable `--tag`, `--replaces`, `--stale-after`, `--author`, `--shared` | destination, acquisition, new source item |
| `verify ID` | `--by` | guarded in-place verification |
| `delete ID` | `--yes` | preview or commit |
| `audience` | page | list own rules |
| `audience set MATCH shared\|personal`, `audience unset MATCH` | none | locked settings edit |
| `sync` | `--status`, `--device SELECTOR` | incremental section build, or read-only status |
| `devices` | none | what a sync could embed on; needs no brain |

`index`, the name of `sync` until 2026-11-21, is not in the command table and has no alias (owner's decision): it takes the unknown-command usage path, exit 2, like any other word.

“Filters” means repeatable `--kind` (any) and `--tag` (all), `--status`, `--since`, `--until`, `--all`. “Page” means `--limit`, `--offset`, `--max-chars`. Join search operands with single spaces preserving literal quotation marks inside them; the query parser owns phrases, prefixes and usage failures. Decimal paging arguments must fit a native int; offset is nonnegative, max-chars and limit positive. Apply the per-mode upper limits and defaults from §6.1 (check has no specified upper limit). Audience uses the built-in list defaults (20 and 2,000). Project list settings apply to list alone. The brain loader rejects an out-of-range project default with invalid_config. Use configured limits only for their corresponding command; history/outline retain their own limits. Search alone registers the independent boolean flags `--semantic` and `--bm25`; list accepts neither. Run delegates to RunWith(ctx, env, Release). RunWith builds its command table from f and registers --bm25 when f.BM25 is true. Release.BM25 becomes true only in the change that records a passed release gate. In a build that holds it back, help omits it and its use follows the ordinary unknown-flag usage path (exit 2), even in combination with `--semantic`. Scenario scripts and the calibration tool pass Features{BM25: true} to RunWith to exercise the candidate before release. They leave Release untouched. Prime and ordinary get accept no result-count limit.

Dispatch in two short passes. First consume leading global flags and their operands to locate the command. Register its exact form and globals in a fresh FlagSet, then parse the remaining tokens, validating subcommand-specific flags after parsing (including audience listing versus editing). The command table supplies the value arities for both passes and help. Precompute JSON diagnostic mode using the same token boundaries, scanning flags even after an unknown one, skipping each recognized value, and stopping at the option delimiter. Thus a literal body or query containing `--json` cannot change the output stream format. Usage covers missing/extra operands, malformed flag arguments and wrong flag combinations: both destination flags, both body input flags, summary without link-only, source override on URL import, history with outline, page flags on an audience edit and invalid time windows. Item field values and refused write targets are domain errors from their owners. A missing required title is usage; an explicitly empty title is invalid. `--help` prints root or selected-command help and `--version` prints the release version without opening a brain. No command and no help/version gives usage. Generate root and command help from the command table, including flags and operands. Help has no result budget. Accept and ignore a global --personal on help, version, init, skill and devices; these commands have no personal item view.

## Execution and streams

Search defaults to five results and 3,000 code points. Register its integer `--context N` in every build. If absent, pass zero in `search.Request.Context`. If supplied, require a decimal integer from 1 through 3 and pass it unchanged. An explicit zero, a missing or malformed value, an out-of-range value, or use on any other command gives `usage` before discovery. Context works with any enabled combination of retrieval flags.

Register `--color` only on search and get, including get's history and outline forms. Requesting colour together with `--json` gives `usage` before discovery, with the diagnostic on stderr in JSON. Choose `render.JSON` for JSON, `render.TextColor` for colour and `render.Text` otherwise. Pass the format to `FitBody` for ordinary get and `Fit` for search, history and outline. Colour depends only on the flag. The process adapter checks stdin for body-less add and never probes stdout for colour. The renderer owns the budget, line ranges and choice of optional context or colour within the fitted page.

1. Validate grammar before discovery. Dispatch help, version, skill and devices directly; init calls brain.Init without a prior Open. All other commands open one guarded Brain, defer Close and select the caller's view. A required unreachable personal view fails before item reads. Audience listing/edits address personal.toml in the brain folder, including with unreachable personal storage.
2. Item reads scan/resolve through the catalog. Search and list pass filters and a single time snapshot, get resolves exactly one id, and check determines its exit from the whole view. Render the final result into a bounded buffer before releasing any of it on stdout. The fitter owns budgets and continuation. Search invokes semantic retrieval only with its flag; missing semantic resources issue notices while ordinary lexical failures propagate. Only index build may download a model or create index storage; a search with the flag may add entries to an index that exists. Status does neither.
3. Item writes validate the audience table, compute Dest/Lookup/Disclose before acquiring input and send import's destination notice before its guarded file read or network request. Read stdin only for add without a body option and only after that decision, bounded to 512,000 Unicode code points and valid UTF-8. Pass a file to store.OpenInput, which enforces its byte limit after the guard. Prepare outside the destination lock and let the write handler refresh inside it. A rule-selected personal destination widens lookup but not disclosure. Existing-item writes lock the target's actual section. Delete preview takes no lock. Audience edits use [the settings transaction](audience.md).
4. Only CLI prints. Use the renderer for budgeted docs, unchanged embedded bytes for text skill output, and compact JSON for JSON mode. Skill returns `{"text":"…"}` or `{"topics":[…]}`; help and version return `{"help":"…"}` and `{"version":"…"}`. Each document ends with one LF. Emit notices immediately on stderr, including destination and model-download notices ahead of acquisition. Each JSON stderr line is exactly one `{"notice":{"code":"…","message":"…"}}` or `{"error":{"code":"…","message":"…"}}`. Text diagnostics use one line, `code: message`. Every id and every path that CLI places in text goes through `render.ExactValue` and is never flattened or cut (spec §6.2, "One id or path, one line"): the id and the path of a write result; the first line and each id list of a delete preview and of its result; the path of a check finding; the path in the `destination` notice; and an id or a path inside the message of an error or a notice. A value that `ExactValue` cannot write prints as `?`. The search location, get's path line and init keep `render.ExactPath`. In JSON an id or a path stays an ordinary string, and a `path` that is not valid UTF-8 is left out. Never echo raw parser, filesystem or subprocess errors, credentials, flagged secrets or private suggestions. Use the message's permitted disclosure view.
5. Success returns 0, including empty results and idempotent writes. Wrong usage returns 2. Other expected failures use their domain code and exit 1, normally empty stdout. Check with any errors returns 1 with its report, even past the last finding. Delete preview prints its result, then confirm_required on stderr and exits 1. After a committed item change, emit after_write for cleanup failures and preserve the success outcome. Treat an unexpected error or recovered panic as io with fixed text. A stdout delivery error cannot retract delivered bytes or a committed write; report a delivery failure on stderr if possible. For a published write its notice must tell the caller to look up the item before repeating it.

## Semantic commands and scan notices

Open and guard the brain before handling a semantic command. Construct its Options from the selected brain, env.Files, env.Models, the configured model name and the project’s requested CUDA precision. If model_path is supplied, resolve it relative to the brain and open the model folder as Options.ModelDir. The semantic code verifies its pinned files before use. Resolve the cache location exclusively from Env.Getenv: PBRAIN_CACHE relative to Env.Dir when necessary; otherwise an absolute XDG_CACHE_HOME plus pbrain on Linux, then HOME/.cache/pbrain; on macOS HOME/Library/Caches/pbrain. Pass Git and Files and the resolved brain and personal section roots as forbidden to semantic.OpenCache. With no usable per-user location use the component's nil-cache rules. The semantic component owns the exact NotReady reason, fix and message mapping for semantic_not_ready and semantic_partial, the build/status text and JSON, the devices text and JSON, and the model_download, index_progress, embedding_device, cpu_fallback and cuda_precision_fallback texts. CLI serializes and emits them. [Semantic command contract](semantic.md)

- **Keyword broadening.** Copy the parsed BM25 boolean into `search.Request.BM25`. When it is the only search-mode flag, scan the requested view with bodies available to the scorer and fit the result without opening a semantic cache, database or model. When both flags are true, pass the same BM25 value and run the hybrid lifecycle below once. A semantic-not-ready result still includes eligible partial rows.
- **Hybrid search.** Parse the query and select the caller's view. OpenCache with create=false. Call semantic.Start with the context, options, joined query text and guarded section folders **before** the item scan. Defer source.Close exactly once immediately, including on scan, validation, search, fit or output failure; it returns nothing, and a search never opens a GPU, so Options.Device is left empty here. Missing prerequisites produce a source carrying a not-ready reason; lexical execution continues. Scan holding the bodies, Attach one SectionInput per selected section, call source.CatchUp (it writes only within the bounds of the [semantic design](semantic.md), "Catch-up in a search", and returns only the context's error), set Request.Semantic, and call search.Run, which joins Score. Fit the merged result for the requested mode. Dispatch one semantic notice from Result.Sem and print the fitted output. Lexical-only search never creates a source or opens the cache.
- **Index build.** OpenCache with create=true only after validating the requested model and cache location. For each selected section, shared first, pass Build a ScanFunc that takes a fresh store.Scan with bodies kept **after Build acquires the index lock**. Filter the returned catalog to the requested section and provide access to that scan's body bytes. Pass fetch.New(env.Net) as the bounded model Downloader. Options.Device is `--device`, else Env.Getenv("PBRAIN_DEVICE"), else empty, and Options.GPUMemory is PBRAIN_GPU_MEMORY in MiB turned into bytes; check the form of both before the scan and fail with invalid_config on a malformed one (`--device` with `--status` is usage). Model download and progress callbacks write notices on stderr as they occur; a progress report that carries a Run becomes embedding_device or cpu_fallback, each at most once per command across the sections, and the section's JSON object takes its device from the BuildResult.
- **Devices.** `pbrain devices` opens no brain and no model: print env.Models.Devices() by the semantic design's text and JSON. A global --brain is not resolved. Collect the per-section facts and print the §9.4 result. A missing default personal folder contributes zero items without creation. Domain dates retain the one captured instant; build progress and checkpoint intervals track elapsed time across the build.
- **CUDA precision (#61).** A Gemma sync with a requested fast writer may inventory once across both nonempty sections, even when unchanged notes permit reuse. When the selected CUDA card must use fp32, emit `cuda_precision_fallback` with the reason at most once, using the standard text or JSON notice. Keep explicit CPU and fp32 requests quiet about precision. Pass the same normalized project policy to search and status for checking published manifests. Neither command queries CUDA.
- **Index status.** OpenCache with create=false, scan the chosen view once with bodies kept, then call Status. Preserve the missing-section state; load no model and create nothing. Print the per-section state and model presence in the requested format.
- **Skipped files.** Emit one notice with code `skipped_files` and message `N files skipped: run pbrain check`, with `1 file skipped` for a count of one (append ` --personal` for an explicitly personal view). Count the distinct broken files of the final disclosed scan(s): the `store.Skipped` entries whose code is `bad_front_matter` or `bad_file_name`, which are the ones check reports as errors. A `not_an_item` entry is never counted: a `.md` file without front matter is no item, so no read skipped anything (spec §6.3). Retries, preflight scans and section passes never double-count. Emit only for a nonzero count. This applies to reads and writes that use an item catalog, including index/build/status. A rule-routed personal write without the flag can count only shared skipped files. Check prints the findings directly and emits no skipped-files notice; there a `bad_file_name` entry is an error finding like `bad_front_matter`, with the text and the path rule of render.md, "Check"; commands without an item scan have no such notice. Import and rule-routed add use the `destination` notice, and shared deletion uses `git_history`, with their text owned by the write handlers.

## Proving tests

- `TestCLILocationContextAndColor` (39–41) reads a hit at its body offset with get and compares the file line to the outline. Test search with context omitted, 1, 2 and 3, with text and JSON, across the enabled retrieval modes. Reject 0, 4, a missing or malformed value, and context on get or list. Check colour on search and each get form, rejection on list, and rejection of colour plus JSON in either flag order with empty stdout and a JSON usage diagnostic. Use failing discovery doubles for wrong usage. At a tight limit check the base page, continuation and get slice with and without decoration. Compare the same text invocation on a pipe and a pseudo-terminal with terminal output translation disabled.

- `TestCLIArgumentMatrix` exercises every table row and help from main, both global-flag positions, equals forms, repeated tags containing commas, `--`, a literal flag as a value, unknown options with JSON requested later, and an explicitly empty linked summary. The old name: `index` and `index --status` are unknown commands, with the usage error on stderr in text and in JSON, empty stdout and exit 2, and root help lists `sync` and not `index`. Scenarios 17, 23, 24 and 28.
- `TestCLINoBrainDispatch` uses failing Git, network and filesystem doubles for help, version, all skill forms and devices. Init uses only its own discovery path. Scenarios 23, 27.
- `TestCLISingleInstantAndZone` runs two zones concurrently with one injected instant, local midnight and daylight-saving boundaries, and checks a single effective command timestamp. Cover explicitly empty TZ with UTC, unset TZ with a non-UTC system zone, and :Europe/London. Scenario 30.
- `TestCLIViewAndInputOrder` records events for a pipe, file and URL; a refused audience never reads one byte, a terminal never blocks, the destination notice precedes acquisition, and a rule hides private duplicate suggestions. Scenarios 6, 24–26.
- `TestCLIExitStreams` parses every stdout document and each JSON stderr line separately. Cover successful empty search, usage, timing of notices, io, personal_exposed, ambiguous_id, check past the page, delete preview, after_write, and a committed write with failing output. Verify one skipped_files count across retries, redacted to the caller’s view, with no notice on check itself; a brain whose only odd file is a `.md` without front matter gives no notice, and a file whose name is not valid UTF-8 is counted. A write result, a delete preview and a check finding for a file whose name holds a line feed are each one line with the quoted token. Scenarios 8, 15, 17, 29.
- `TestCLISemanticAndOutline` exercises index status with no model, no_model on build, model_download ordering, fallback notices, combined personal view, outline paging and history incompatibility. Scenarios 33–37. Check Start → scan → Attach → CatchUp → Run → fit and exactly one Close on every post-Start failure. Scenario 42 through the command: one added note is found by the next search with no notice and a following build embeds nothing; a lexical-only search after an add opens no cache, loads no model and takes no lock. Pause a build before its scan and assert it holds `<section>/.pbrain/index/lock`. An item writer can still acquire `<section>/.pbrain/lock`. Status never creates the cache. Check each NotReady reason against the semantic message table. Use a fixed test embedder and local fixtures; the command tests never contact a model service.
- `TestSyncDeviceNotices` and `TestCLIDevices` are specified in the [semantic design](semantic.md), test plan; scenario 43 runs through the command with a test model that has a GPU path and a device list made for the test.

- `TestCLISearchModes` (38) checks all four flag combinations; exact, semantic and partial output order; model-free execution with a failing semantic dependency; one source lifecycle in combined mode; and fallback to exact plus partial when the index is missing. Exercise both feature settings with RunWith and check help, text/JSON usage errors and rejection by list. On a held-back build, also assert that the production Run rejects --bm25 as an unknown flag. The calibration command uses `cli.RunWith(ctx, env, cli.Features{BM25: true})` on identical views and budgets for strict, BM25, semantic and combined searches, as specified in the [semantic calibration design](semantic.md).
