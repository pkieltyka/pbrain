# Functional review: semantic search amendment

Reviewed `bd0ffc7c4bb0cb68763cfb5eaebd01dc51e0fa46562d8defc0486d717baf6ef1` against the complete `4622a82f` base and owner decisions A1–A8 and C. Local opt-in search, lexical-first ordering, the model fingerprint, an abstention threshold, explicit download, a no-model outline and the accepted command amendments are represented.

1. **Blocking · §§5.1 and 9.4, local cache confinement.** `PBRAIN_CACHE` can select a directory inside a Git worktree or a brain, including via an alias or a missing leaf. The wording promises an outside-project cache but never says to reject that location before writing. A cache in the wrong checkout can make cross-project vectors eligible for commit. Validate the resolved cache root and its nearest existing ancestor before creating or writing anything. Reject a root inside a Git worktree or either section with `invalid_config` for index build and degrade semantic reads to the ordinary readiness notice. Preserve lexical reads. Add tests with direct, aliased and absent roots. This overlaps the other reviewer.
2. **Should fix · §§7.1, 9.3–9.4 and scenario 35, readiness by section.** Model presence, cache vectors and each section's index are independent. Deleting only intermediate shared vectors must leave an already-built index and local model usable. With `--personal` a ready shared index still contributes when the personal index is missing or corrupt. Classify absent, stale or unreadable data per requested section. Use what is ready and a bounded `semantic_partial` count of otherwise eligible unseen items, or lexical-only plus `semantic_not_ready` if no section or no query model is usable. The shared query must not consult or count a personal index. Read-only status should show readiness per section, and an explicit index run should recover derived corruption.
3. **Should fix · §7.1 and scenario 33, paging and budget.** Adding the semantic tail changes the closing continuation even if every lexical row fits as before. At a boundary it can also displace optional related lines. Promise unchanged lexical ordering, row content and snippet as units before budget fitting. Fit one merged sequence and compute pagination and extras from its actual emitted units. Assert equal lexical units and correct combined continuation instead of byte-identical CLI output. Include an exact-boundary test in text and JSON.
4. **Should fix · §§7.1 and 16, failure and abstention wording.** A missing model or index can degrade a valid search, but a bad argument, unreadable personal section or insufficient output budget still fails with its existing code. Qualify the exit-0 promise accordingly. A cutoff is a fixture-gated abstention behavior, so express the runtime promise as “no semantic hit below the cutoff” without promising that every unanswerable query has zero above-cutoff matches. Preserve the owner’s held-out abstention release test.
5. **Should fix · §9.4 and scenarios 35, 37, incremental cost.** Make the unit of reuse a passage with identical prepared text and fingerprint, independent of changed item headers or neighboring passages. Define `items` and `removed` as item counts and `embedded` and `cached` as passage counts. Specify the one-new-item cost and assert that an explicit rebuild embeds only its uncached passages, reusing unchanged text and dropping removed items. I support keeping search read-only: model inference for the query already spends part of the 1 s target, and a writer lock plus document inference would vary with worktree churn. Add a skill step to run `pbrain index` after a batch or pull and retry when readiness matters.

**Verdict — Changes required.** Constrain the cache before release and make the hybrid readiness, page and index-build behavior testable.
