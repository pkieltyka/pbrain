# Functional spec review, round 1

Reviewed the 575-line draft ending at §18 question 9, against the approved overview, owner Q&A, research and factory’s existing notes convention. The operator supplied pushback A–C separately. The proposed Go binary, Markdown store, local lexical search and optional factory integration fit the project. Six blocking findings affect confidentiality, the current decision, preservation of imported material or an explicit acceptance criterion.

## Blocking

1. **Shared discovery can ingest ignored factory notes (§§3.1, 6, 9.3, 13, 16).** A user points `init` at an existing notes folder. Its declared private directory can have any name and already be Git-ignored. The recursive Markdown scan can index it as shared before anyone creates local `personal.yml`. The same issue applies to other ignored directories. Optional Git also leaves an unknown exposure state, distinct from a confirmed non-Git directory. Define shared discovery as eligible tracked files plus eligible **unignored** untracked files. Exclude personal roots and local caches before traversal. Enforce resolved root boundaries on configuration, `--dir` and path lookups, and skip symlink entries in item trees. Reject overlapping roots except the designated personal subtree, which must be pruned from shared scans. In a worktree require working read-only Git checks or fail before indexing or writing. Let a fresh `init` install its ignore rules before performing the exposure check, without processing item content first. Test the existing ignored folder before and after configuration, a linked worktree, and unavailable Git.

2. **The personal boundary stops at the read commands (§§6.2, 7.3, 8, 9.1, 11, 15.4).** `check` takes no personal opt-in and emits paths. Default `get` suggests ids. `verify`, `fetch` and `check --fix` lack a section contract. A distinct `personal_link` error on a shared write can confirm the existence of a personal id. Specify one shared-only lookup view for bodies, hints, counts, diagnostics, mutation targets and indexes. Require explicit personal access for any item-level personal diagnosis or mutation. Always run the exposure guard, with a generic message on both output streams when detail would identify a personal item. Treat hidden and missing link targets identically. Run detailed cross-section reference audits locally under `check --personal` and refuse known shared-to-personal edges. Define the guarantee precisely for bytes someone has already put in a shared file by hand: a reader with only a shared clone cannot identify the origin of arbitrary pasted text. Moving a committed file to personal also leaves earlier Git copies. Test both streams and both index directories with a unique private id, a malformed personal item, a similar missing id and a tracked personal file.

3. **The replacement stamp can overrule the authoritative edge (§§3.3, 4, 5.2–5.3, 9.1; owner answer 2).** If A’s stamp names an existing B, the draft hides A even when B never replaced it. Repair can then write the missing claim into B. A stamp also overwrites the old `verified` or `provisional` value used to validate standing. A fork has two valid successor edges and only one slot for a stamp. Make the validated new-item edge authoritative. Keep old confirmation status intact on new-format writes, and make a convenience stamp optional and unambiguous. For legacy `superseded-by <file>` alone, resolve an unambiguous same-section target under a documented compatibility rule. Repair may derive a convenience marker from a unique valid edge. Never infer a new decision from a modern stamp or choose a winning branch in a fork. Test a stale stamp, a verified predecessor, legacy-only history, and a two-branch fork followed by one item that replaces both.

4. **Atomic file edits do not deliver the promised write contract (§§5.1, 8.1, 8.3–8.4, 9.1–9.2, 11).** Publishing a successor then stamping three predecessors can fail after the first rename. Two commands can both validate the same current predecessor before either publishes. An editor can change a source during the fetch. Prefer one authoritative item write per operation, defer convenience repairs, and define the point at which a successful write is visible. Serialize validation and publication among pbrain writers in a checkout. Reject a detected intervening change to an existing target. Treat the index as recoverable after publication and allow an unreferenced local cache blob after interruption. Distinguish a committed item with stale derived data from a failed add that callers may safely retry. Test concurrent replacements in one checkout, independent successors merged from two worktrees, and interruption between publication and index update.

5. **A provenance URL can cause a local transcript to be overwritten (§§4, 8.3–8.4, 14).** The documented local import of `transcript.md --source <doc URL>` passes the sole test for refreshability. A later fetch could replace the exported transcript with a different public representation. A changed fetch can also retain someone’s verification of the previous bytes, or discard the annotation provided on a bare link. Record or otherwise distinguish the acquisition mode for local exports, bare URLs and directly fetched URLs. Permit network acquisition only for the latter two, preserve authored annotations separately if supported, and exclude sources from verification or reset verification on content change. Show what happens to existing citations. Test a local export whose provenance URL returns different text, a link with a comment, and a changed verified source. Deferring repeat refresh substantially reduces this problem.

6. **A valid budget can be smaller than a `get` header (§§7.1, 7.3–7.5, 9.1, 11, 15.9).** In compact JSON the sample Redis decision’s id, type/status, title, date, author, decider, path and paging fields already take 329 characters with an empty body. The minimum accepted limit is 200. Cutting only the body can exceed the cap or yield the same offset forever. History, long link arrays and diagnostic paths have the same issue. Define characters as Unicode code points, count the final serialized form including escapes and the final newline, and reserve room for omission metadata. For exact lookup, return a small documented `budget_too_small` error with a required minimum when metadata plus one body character cannot fit. Every successful nonfinal page must advance. Bound history and check output and aggregate malformed-file notices on stderr. Test 200-character requests, long metadata, JSON escaping, multibyte text and a final page at end of body in both formats.

## Should-fix

7. **Hand edits and merges can make identity and history ambiguous (§§3.2, 5.3, 7.3, 9.1, 11).** Filename exclusivity in one directory does not guarantee a unique id across kind directories or branches. Choosing the first path can verify the wrong item. Self-links and longer cycles are undefined, and “oldest first” cannot describe two siblings’ lineage by itself. Check new ids across the visible section, reject ambiguous exact reads and all ambiguous mutations, and quarantine ambiguous graph edges. Report cycles, ignore their internal edges for currentness and bound traversal by visited ids. For fork/join history return each reachable item once in deterministic predecessor-first order with its predecessor ids. Test duplicate stems in different folders, a cycle and a diamond. Describe branch id collisions as unlikely.

8. **Public-only fetching needs a connection-level contract (§§1, 8.3, 11, 16).** The draft lists three denied address families and leaves the actual connected destination, ambient proxy behavior, unsuccessful HTTP responses, response decoding and short legitimate text unspecified. Require a publicly routable connected peer at every hop, direct unauthenticated requests, no fetching embedded resources, a successful response, supported UTF-8 media and explicit bounds on acquired and decoded bytes within the total deadline. Resolve relative links against the final URL. Define the bytes covered by the digest. Limit the short-content heuristic to HTML extraction and accept short valid plain text. Bare links can validate URL syntax without DNS and defer reachability to explicit acquisition. Exercise these outcomes with a controlled transport and representative static HTML, Markdown and plain-text fixtures before shipping URL acquisition.

9. **Import provenance, duplicate identity and cache semantics disagree (§§1, 8.3–8.4, 9.2).** Two unrelated exports named `transcript.md` have the same default source string, while distinct URLs may legitimately contain identical bytes. Promoting a bare link conflicts with duplicate rejection on the same URL. The original bytes of a changed page or a converted file cannot be reconstructed from normalized Markdown and a digest. Use the cache digest to deduplicate bytes. For item writes distinguish exact repeats from different references or different exports with the same basename. Give link promotion one explicit route that preserves the id. Document originals as expendable local snapshots, with no raw cache entry for a bare link. Test both transcripts, a duplicate retry, promotion and removal of an unavailable original.

10. **Imported bytes can affect checks and agent presentation (§§3.3, 7.2–7.3, 8, 9.1, 15.7).** The body-citation scanner treats an ordinary imported Markdown footnote as a pbrain id. Text search does not specify the outside-material label promised by acceptance, and raw control characters or newlines in derived titles and snippets can break result boundaries. Keep imported footnotes opaque, make generated authority metadata independent of all imported bytes, and mark source snippets consistently in text and machine output. Render metadata and snippets as single lines with control characters escaped. Specify whether possible secrets in the persisted locator and other metadata are checked as well as the title/body. Never echo a suspect value in an error. Use an exported document with ordinary footnotes, YAML, control characters and instruction-like prose as the fixture.

11. **Ranking, paging and stability need observable rules (§§5.4, 7.2–7.5, 9.2, 16).** Two implementations can disagree on “lexical relevance,” phrase boundaries, id tie order, and a match occurring only in `source`. The search footer promises access to more matches after the 50-result ceiling without giving a continuation. At UTC midnight a due flag can correctly change on untouched files. Pick a simple rank within each standing tier, for example title phrase, then title/tag hits, then remaining field hits, followed by created descending and id ascending. Specify word boundaries and case handling with a small fixture. Provide a continuation for search or accurately describe narrowing the query. Give `prime` the same id tie-break. Scope determinism to fixed files, configuration, flags and evaluation time, and test the exact due-date boundary and a rebuild with a fixed clock.

12. **Byte-preserving YAML edits need an unsupported-input rule (§§3.3, 8.2, 9.1).** Legal hand-edited YAML need not have one editable status line. A flow mapping, anchor, block scalar or duplicate key makes blind line replacement unsafe. Specify the flat subset pbrain writes and which existing representations it can safely patch. For an unsupported mutation, return a diagnostic and leave every byte unchanged. Define duplicate-key and wrong-type behavior on read. Exercise quoted values, comments, CRLF, multiline fields and unknown keys. Keeping the default replacement to one new file reduces the need for surgical YAML edits in Go.

13. **The generic skill imports factory’s binding policy (§§1, 4, 12–13; owner answer 1).** Telling all consumers to follow decisions and verified learnings until a newer decision replaces them contradicts the owner’s choice to leave workflow to consumers. It also differs from §5.2, where a verified learning can replace another verified learning, and from factory’s rule about an overriding spec. In the generic skill explain standing, currentness and how to inspect evidence. Put instructions about what binds and who acts exclusively in factory’s opt-in recipe. State that an old factory decision without `decided_by` remains accessible but loses decision standing and prime inclusion until manually confirmed. Test adoption against real factory-shaped files with and without that field.

14. **Diagnostic and bootstrap outcomes conflict (§§6.2, 8.3, 9.1, 9.3, 10–11, 16).** `check` with findings must emit its report and exit 1, whereas §11 makes stdout empty on all failures. The global JSON error contract omits where a successful import warning goes in machine mode. The binary is said to use Git only for exposure, while both author fallback and project-root discovery use Git. Specify report-bearing `check` exit 1 separately from fatal execution errors, expose bounded findings even when the first page omits an error, and document diagnostics by stream with `--json`. Enumerate Git uses, behavior for malformed configuration or an unavailable personal root, and which commands can run without opening a store (including help and skill). Test initialization in a subdirectory and a check with mixed severities.

## Nit

15. **The prime example’s counts do not add up (§7.5).** Twelve decisions and thirty learnings with two displayed leaves forty omitted. Correct the footer and have it suggest a command that can actually find the omitted eligible items. The present filter also includes provisional learnings.

## Positions on open questions

| §18 | Recommendation and reason |
|---|---|
| 1. Stamp wording | Use `--replaces` and `replaces` for new writes. Keep reading factory’s legacy spelling. Prefer an optional convenience field that preserves confirmation status. Teach the opt-in factory integration how to inspect the successor. |
| 2. Replacement standing | Keep the monotonic standing rule as a structural validity check. Apply it to every eligible edge. A reader must be able to recover both endpoints’ confirmation state. |
| 3. Ranking | Keep standing first among items that match every term, as recommended in the overview. Include a loosely matching decision and a directly matching learning in evaluation so later tuning has evidence. |
| 4. Shared imports | Keep the shared default and the reminder. The owner explicitly chose the audience of normalized copies in answer 9. |
| 5. Secret scan | Keep a short fixed scan of shared writes with specified patterns, scanned fields and bounded redacted diagnostics. This is a useful check before Git distributes a copy. |
| 6. Budgets | Start with the proposed 5/2,000 search, 6,000 get and 2,000 prime defaults. Verify the minimum, omitted counts and continuation before tuning the defaults on factory usage. |
| 7. Verifier | Keep the single optional `verified_by` on explicitly confirmed content. An agent can distinguish the confirmer from the author in one bounded lookup. The Q&A supports a lean authority record and contains no explicit requirement for an OKF verifier. |
| 8. Actors | Accept legacy bare names, prefer scoped actor names for generated values and require nonempty single-line values on new writes. The label identifies an assertion’s source and carries no authentication claim. |
| 9. Prime eligibility | Keep current decisions and verified learnings. This gives factory a compact account of settled choices and practical lessons. Keep source bodies out and make eligible omissions visible. |

## Positions on pushback

- **A.** Choose the drafted option A. Keep shared-by-default imports and a concise stderr reminder, show `--personal` explicitly in the transcript example, and make the destination clear in help before the write. Requiring an audience flag or changing the default would reopen owner answer 9.
- **B.** Agree on delivery order. Ship and prove local exports and bare links first. Complete static public URL import in the final v1 phase, gated on the public-destination, conversion, size, failure-preservation and local-cache fixtures. The owner included fetched contents in v1.
- **C.** Cut standalone `reindex` first since deleting the derived index already forces a rebuild. Defer repeat refresh of mutable sources. Allow explicit `import <url>` to fill an existing bare link by id-preserving promotion. Retain a bounded inventory operation for discovering current items without guessing query words, whether spelled `list` or folded into search. Keep the five stored kinds for factory compatibility and the external-source trust boundary. Expose their distinctions in help where they change an action.

**Verdict — changes required.** Six blocking, eight should-fix, one nit.
