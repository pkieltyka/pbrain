# Naming — round 1

Keep `item.Item` and “item” as the shared vocabulary. An item is one addressable, attributable unit of project knowledge. It may be a one-line decision or learning, a copied source document, or a linked pointer with only a summary. “Document” is useful when referring to a real source or the embedding input role. It implies more body content than an item promises. “Entry” is a reasonable alternative, though it can suggest a log or catalog row. “Note” and “Memory” already carry narrower meanings here. Teach “item” once with the kinds it covers and use those kinds when greater precision helps the reader. A rename is mechanically cheaper before implementation, but it still ripples through the spec, skill, component interfaces, result fields, notices and fixtures without making IDs or navigation clearer.
