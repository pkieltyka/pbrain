# Retrieval round 1 · @lead-dev

## Recommendation

Ship pbrain-owned lexical search and exact lookup over Git-backed items. Keep task-time retrieval as the default, make priming opt-in, and keep tags optional. Spend the first tuning cycle on evidence from real engineering tasks. The success measure is whether an agent retrieves the current, citable answer in a small payload and can tell when the brain has no answer. [Functional spec §§6–7](../../functional_spec.md) · [Retrieval and evaluation research](../../research/knowledge-memory-landscape/agent-memory-systems/retrieval-priming-budgets-and-eval.md)

## Search and context

An agent starts with two or three durable terms from the task, such as `job queue`, or an exact quoted phrase. Search matches all clauses across title, tags and body, applies audience and explicit filters, and keeps current matches ahead of history. Within the strongest current match class, the best decision in force moves first. A linked newer doubt can appear beside it when the budget permits. Use the result's ID to read the relevant item, verify its citation and consult history if needed. If search is empty, retry once with a different identifier or fewer terms. Use `--all` when the question calls for history and check the original evidence when recall is thin. [Functional spec §§4.5, 7 and 12](../../functional_spec.md)

Keep startup memory a small, frozen set of signposts. The default result cap is five hits and 2,000 rendered characters. Read one `get` at a time and make paging a deliberate choice. A 2,000-character cap is enforceable across harnesses, while actual token cost depends on the model and content. Measure the total cost of search, retries and selected reads alongside the per-call cap. A short initial result that forces repeated pages can lose on total cost. Letta's signposts, Hermes's frozen priming and Claude Code's on-demand topic files support this shape. ## Tags, documents and learnings

Tags already participate in matching and offer explicit filters in search, list and prime. Start with a handful of optional, lowercase subsystem names such as `queue`, `auth` and `deploy`, with one-line descriptions in a short project guide if needed. Use the same words in titles when they help a reader. Skip mandatory tags and a registry in `pbrain.toml` for v1. A tag needs to earn its maintenance cost through a repeated filter or a demonstrated vocabulary mismatch. If that happens, try an advisory vocabulary with examples before policing unknown tags. Keep status, authority, time and kind in their own fields. [Functional spec §§2.4 and 7](../../functional_spec.md)

Keep a document as a cited `source`, copied when retention is permitted and useful, or linked with a safe description. A durable learning is a small, independently retrievable claim with conditions and a citation. An incident transcript can remain linked while a learning records the reproduction condition and the verification that matters next time. A decision records the chosen policy and who decided. A tentative explanation can be provisional or linked as a doubt. The current skill bans task status and facts easy to recover from code or Git. Add a write-side test: would this change a future task, and could that future agent verify it? Skip routine updates and repeated notes. ## What to specify and measure

- **Functional spec now.** Keep the current ordering and budgets. Add one complete task example that searches, reads a cited item, handles a newer disagreement, and stops. Make the snippet contract test a real passage from a long source. The current first matching line can be boilerplate, and all query words can be scattered across unrelated sections. Test a passage near the relevant heading, and prove the body offset lets the reader reach it. Include an identifier-spelling miss, an empty query result and a linked source whose content is unavailable to the reader.
- **Architecture.** Start with a scan as the correctness baseline. Measure cold CLI reads and search at the spec's 5,000-item, 50 MB workload. Add a rebuildable lexical index only if measured latency needs it. Candidate gathering, passage selection and an index can change internally while audience, lifecycle, ranking, budgets and citations keep the same contract. The qmd research found its index can include Git-ignored files and its ordering lacks pbrain standing. Keep qmd outside the default path. [qmd research](../../research/knowledge-memory-landscape/qmd/research_summary.md)
- **Evaluation.** Build 20–30 real task queries with expected IDs, citations and expected abstentions. Include stale facts, contradictory notes, long document distractors, aliases and a unique private term. Measure current useful hits in the default page, correct citations after `get`, unnecessary reads, total tokens and latency. Require zero private leaks, including counts. Compare task results and total context with and without pbrain before adding another retrieval mode.
- **Later.** Add synonyms, advisory vocabulary or semantic candidates only for misses the fixtures show. Defer usage weighting, automatic memory consolidation and cached linked-text search.

## Questions for the owner

Which recurring jobs should succeed first, and which real artifacts and failures can seed the fixture? What total retrieval spend is acceptable per task or startup? Who confirms a learning that will guide other agents? Start with search-first, optional tags and no default prime. Revisit those defaults after the first team trial.
