# How BM25 fits in pbrain v1

**Ship BM25 in v1 as a way to broaden a keyword search.** Exact matches answer “which items contain every clause?” BM25 answers “which other items contain a substantial part of this query, especially its rarer terms?” Semantic search can find an item that uses different words altogether. An agent should be able to request all three in one call and see why each item appeared.

### The proposed command

| Command | Results in order |
|---|---|
| `search "queue retry timeout"` | Exact matches in the owner’s existing order |
| `search "queue retry timeout" --bm25` | Exact matches, then qualifying partial keyword matches |
| `search "queue retry timeout" --semantic` | Exact matches, then qualifying semantic hits |
| `search "queue retry timeout" --bm25 --semantic` | Exact matches, then qualifying semantic hits, then remaining partial keyword matches |

The shell quotes above pass one query argument. Quotation marks *inside* that argument retain pbrain’s phrase semantics. For example, a note containing “queue” and “retry” could appear as `partial 2/3` even though it lacks “timeout”. The short passage supplies evidence the agent can check. JSON adds `"partial":true,"matched":2,"clauses":3` only to partial rows. The counts are distinct matched clauses over all distinct query clauses, including common and absent ones. A shared result never depends on personal items or their term frequencies.

**Default is the main decision for the owner.** Three of us recommend one independent flag, `--bm25`, with no aliases. @lead-dev-2 still prefers broadening by default but accepts the explicit flag. @architect withdrew the suggestion that `--semantic` should imply BM25. Independent flags let an agent deliberately choose strict matching, a model-free retry or all three methods. An unavailable model in the combined command still yields exact and qualifying BM25 hits along with the usual semantic notice. ### Where BM25 buys something

| Placement | Effect on the fixture and on a short page |
|---|---|
| Rank inside exact match classes | Could improve a heavily populated class on a short query. It cannot rescue the 19/20 empty strict searches. Keep exact ordering, including the promoted decision, intact. @lead-dev would allow BM25 after class, recency band and standing when requested, with the same decision pinned. Test that variant separately. |
| Append after exact hits | Gives a model-free caller more cited items. Recommend the tail even when there’s an exact hit: a weak full-word match can coexist with a useful partial match. @lead-dev would append only when the **whole** exact list is empty. No variant should depend on how many rows fit the current page. |
| Put partials before, beside or after semantic hits | Before semantic, unguarded BM25's first three consume three slots and gave 5 correct first, 11 top-three. The approved exact-plus-semantic order gave 12 and 17 on these answerable questions without a cosine cutoff. Last preserves the strongest demonstrated first page. If five better-tier rows fill the page, the first partial may appear on the next one. |
| Fuse BM25 and semantic ranks | Equal-weight RRF scored 11 first and 16 top-three. Its rank alone cannot establish relevance; reordering the full list can displace a current decision. Keep scores inside their own tiers. |

Deduplicate on the existing item identity, before paging, with the earlier tier winning. An item admitted by both approximate methods keeps its semantic row. Each partial uses the existing best lexical passage. Decision promotion, replaced counts and outside-window counts stay exact-only. Individual-clause hints appear only when the whole combined list is empty. `--offset`, totals, `more`, `next` and the character fitter use the final list, including partials. Footer space and the stated minimum budget can change; exact row content and ordering survive. Under `--all`, preserve existing exact and semantic lifecycle ordering and put current partials before replaced partials. ### When can “nothing found” survive?

**Use clause evidence to admit a partial item and BM25 to rank it.** A marker cannot prevent a false positive. A universal raw BM25 floor varies in effect with query length and the corpus. Start calibration with the following deterministic rule, with no English stop list:

1. Build the eligible corpus from the caller’s view, lifecycle, filters and time window. Count each distinct folded query clause once, in first-occurrence order. A phrase or prefix is one clause. In the partial tier require every explicit phrase and prefix to match according to the existing grammar.
2. A clause is informative when `4 × df ≤ N`, where `df` is the number of eligible items containing it and `N` is the eligible corpus size. An absent clause counts in the denominator. Require at least **two** informative matches, and at least **half** of all informative clauses. An empty corpus or fewer than two informative matches gives no partial hit. For one- or two-clause queries this rule adds nothing beyond exact results. With fewer than four eligible items even an observed word cannot qualify. These are deliberate conservative boundaries to test.
3. Compare this candidate against half- and two-thirds-coverage rules on all clauses. Freeze one release rule using calibration data, then run held-out tests. Preserve the semantic model’s own cosine cutoff. If the tiers all decline, return the ordinary empty result.

**What we measured.** On 20 reworded questions about 50 spec sections, unguarded BM25 gave 5 correct first and 11 in the top three, but returned hits on 4/5 unrelated questions. With the quarter-frequency gate and the exact tier first, an independent replay gave **2 first, 5 top-three and 0/5 unrelated nonempty**. Keeping all words and requiring two-thirds coverage gave 2 first, 3 top-three and 0/5 unrelated nonempty in a standalone run. Removing English stop words changes these results. None of these tests measured a rendered page. [Guard comparisons](./round2-lead-dev-2.md) · [All-word control](./round2-lead-dev.md)

Five off-topic negatives are easy. Asked “Who verified the decision to import the Zurich Slack transcript?”, the quarter-frequency gate returned five partial sections even though “Zurich” occurs nowhere and the spec records no such event. Before release, each enabled mode must pass **at least 95% empty pages on held-out unanswerables and all designated abstention regressions**, alongside useful correct citations on model-free tasks. Include in-domain near misses, absent versions, personal-only answers, short queries chosen by working agents, and filtered small brains. Compare against strict search with one guided retry at identical character budgets. Tune on the calibration split only. If the first gate fails, revise it and evaluate on fresh held-out cases; keep thresholds fixed in the binary. @lead-dev would ship exact-only BM25 ordering while broader admission is being fixed. The other proposals protect exact order.

### Go scan for BM25, SQLite for vectors

Use the existing Go parser, fold and live scan. A write, hand edit or Git pull must be searchable immediately, including for a user who has never run `pbrain index`. For requested BM25, accumulate item length in words and clause occurrences across the title, each tag and body. Phrase occurrences stay in one field. Count each clause’s `df` once per item; use all eligible items for `N` and mean length, before paging or deduplication across tiers. Score in float64 in fixed query order, with `k1=1.2`, `b=0.75` and positive IDF `log(1+(N-df+0.5)/(df+0.5))`. Use the standard BM25 term-frequency saturation and length normalization. Break equal scores by newest creation time, folded id and path. The model-free modes load no vectors or model.

SQLite with sqlite-vec is the owner’s decision for vector storage. FTS5 is a separate lexical index. Using it here would add synchronization for live Markdown, tokenizer parity work for folded words, phrases and prefixes, and a way to restrict corpus statistics to the eligible view. A fast indexed query alone measures none of those costs. Benchmark the complete Go command on 5,000 items against the 300 ms model-free target and the combined command against 1 s. Include full-body term counts, a missing index, a Git edit, repeated pages, and shared-view output before and after adding personal items. [Engine probes](../../research/semantic-search-and-index/qmd-and-go-index-engine/go-index-options-and-probes.md)

Exact-order BM25 as a fallback would need its own owner decision. Update search, marker and budget rules, skill usage and scenarios together. The already accepted prefix example and broader fixture are included in that pass. Skip the empty-result semantic hint as the owner decided. This note changes no specification or component.
