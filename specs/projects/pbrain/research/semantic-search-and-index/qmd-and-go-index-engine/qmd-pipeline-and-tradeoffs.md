# qmd 2.9.0 retrieval pipeline

Reviewed 2026-11-20. The current stable release observed in the repository is v2.9.0 from November 18 UTC. Code claims here refer to its tagged commit `aa247d0`. Its lexical command is a useful reference for pbrain. Its hybrid command solves a different retrieval contract and carries more model and runtime cost. [Release](https://github.com/tobi/qmd/releases/tag/v2.9.0) · [Tagged source](https://github.com/tobi/qmd/tree/v2.9.0) · [Earlier pbrain qmd smoke test](../../knowledge-memory-landscape/qmd/engine-and-integration.md)

## How qmd indexes

- **Documents and content.** qmd walks configured matching files and maintains path/collection records, content by hash, a document-level FTS5 table and per-content chunk metadata. Updating a collection fingerprints files and reads only those the stat cache cannot reuse. The fast path uses size and mtime in milliseconds, with a recent-mtime guard that rechecks possible same-tick rewrites. On a stat change with the same content hash it updates the stat record only. Missing files are removed from the active collection. Content hashes allow reuse across identical bodies. [Schema and path sync](https://github.com/tobi/qmd/blob/v2.9.0/src/store.ts#L1390-L1490) · [File update](https://github.com/tobi/qmd/blob/v2.9.0/src/store.ts#L1928-L1947) · [Stat and hash path](https://github.com/tobi/qmd/blob/v2.9.0/src/store.ts#L2245-L2417)
- **Chunks.** The tagged defaults are 900 tokens, 135 tokens of overlap, and a window of 200 tokens in which to look back for a good split. A character fallback uses 3,600, 540 and 800 respectively. The splitter scores headings, blank lines and lower-level breaks, avoids cutting a fenced block when a suitable break exists, and can merge language-aware AST breakpoints in `auto` mode. The local path first uses conservative character estimates, tokenizes and recursively resplits oversize chunks, with hard progress rules. The external embedding path uses the surrogate-safe character splitter and estimated tokens. It does not invoke a local tokenizer. [Defaults and fingerprints](https://github.com/tobi/qmd/blob/v2.9.0/src/store.ts#L178-L196) · [Markdown breakpoints](https://github.com/tobi/qmd/blob/v2.9.0/src/store.ts#L250-L314) · [Tokenizer path](https://github.com/tobi/qmd/blob/v2.9.0/src/store.ts#L4215-L4420)
- **Vectors and updates.** The v2.9.0 package pins sqlite-vec 0.1.9. `vectors_by_collection` uses `vec0` with a collection partition key and cosine distance. One row holds a chunk vector within that collection. qmd tracks model and a hash of the model identifier, input formatting and chunk parameters. It verifies work pending by fingerprint and expected chunk count, and batches embeddings. The modern vector layout replaces older `vectors_vec` tables through migrations. Moving or refreshing a file does not require re-embedding unchanged content under an unchanged valid fingerprint. [Package pin](https://github.com/tobi/qmd/blob/v2.9.0/package.json) · [Vector layout](https://github.com/tobi/qmd/blob/v2.9.0/src/vec-layout.ts#L113-L163) · [Embedding completeness](https://github.com/tobi/qmd/blob/v2.9.0/src/store.ts#L2613-L2663) · [Batched writes](https://github.com/tobi/qmd/blob/v2.9.0/src/store.ts#L2962-L3013)

## How qmd searches

| Path | Implementation observed in the tag |
| --- | --- |
| Keyword `search` | SQLite FTS5 BM25 over document rows with column weights 1.5 for path, 4.0 for title, and 1.0 for body. SQLite BM25 sorts ascending. qmd returns larger-is-better `abs(score)/(1+abs(score))`. It scopes collections and metadata before the final limit and breaks lexical ties by filepath. A materialized CTE preserves the complete lexical match set when filtering by collection or metadata. [FTS5 search](https://github.com/tobi/qmd/blob/v2.9.0/src/store.ts#L5310-L5402) · [SQLite BM25](https://www.sqlite.org/fts5.html#the_bm25_function) |
| Vector `vsearch` | Embed query variants and search cosine nearest chunks with sqlite-vec. Set eligibility before KNN where possible and apply it again on the document join. Collapse chunks to each file's best distance before returning files. The initial KNN requests three times the file limit and doubles if duplicate chunks crowd it out, up to 4,096 chunks. The tagged vector code returns `1 - distance`. [Chunk-to-file resolution](https://github.com/tobi/qmd/blob/v2.9.0/src/store.ts#L5438-L5577) · [Vector score](https://github.com/tobi/qmd/blob/v2.9.0/src/store.ts#L5610-L5688) |
| Hybrid `query` | Probe the original keyword query. A scoped top normalized lexical score ≥0.85 and gap ≥0.15 skips expansion unless intent is supplied. Search the original in both legs, lexical expansions in FTS, and semantic or hypothetical-document expansions in vectors. Fuse ranks at file level and keep the top candidate window, 40 by default. [Strong-signal test and routing](https://github.com/tobi/qmd/blob/v2.9.0/src/store.ts#L6930-L7094) |
| Fusion | RRF with `k=60`, one-based ranks, weight 2 for each original-query list, 1 for expanded lists. qmd then adds 0.05 to an item ranked first in any list or 0.02 for other top-three positions. Those bonuses are specific to qmd. Typed structured queries use a different weighting rule that gives the caller's first list 2× weight. [RRF implementation](https://github.com/tobi/qmd/blob/v2.9.0/src/store.ts#L6048-L6091) · [Hybrid weights](https://github.com/tobi/qmd/blob/v2.9.0/src/store.ts#L6913-L6928) · [Structured weights](https://github.com/tobi/qmd/blob/v2.9.0/src/store.ts#L7486-L7511) · [Original RRF paper, 2009](https://cormack.uwaterloo.ca/cormack/cormacksigir09-rrf.pdf) |
| Reranking | Select one chunk per candidate file by term overlap, with supplied intent as a secondary signal. Cache query/model/chunk scores. A cross-encoder scores the selected passage. Blend the score with `1/RRF rank`, weighting that position signal at 0.75 for rank 1–3, 0.60 for ranks 4–10, and 0.40 thereafter. Deduplicate, apply the score floor and cap final results. `--no-rerank` returns fused scores. [Passage selection and bypass](https://github.com/tobi/qmd/blob/v2.9.0/src/store.ts#L7086-L7168) · [Blend and truncation](https://github.com/tobi/qmd/blob/v2.9.0/src/store.ts#L7181-L7251) · [Score cache](https://github.com/tobi/qmd/blob/v2.9.0/src/store.ts#L5983-L6038) |

**Docs and code disagree on scores.** The tagged README table describes absolute lexical scores and a reciprocal-distance vector transform. Read the actual backend output as above. Some other descriptions show the older global vector table, but `vectors_by_collection` is the new layout. Thresholds for one path do not directly transfer to another. In particular a cosine similarity or a fused rank score is not a calibrated probability of a helpful answer. [README score table](https://github.com/tobi/qmd/blob/v2.9.0/README.md#search-backends) · [Current vector schema](https://github.com/tobi/qmd/blob/v2.9.0/src/vec-layout.ts#L16-L23)

**Cost and output.** The default local models in this tag are EmbeddingGemma 300M Q8 for vectors, Qwen3 Reranker 0.6B Q8 and a fine-tuned 1.7B Q4 expansion model. The documented downloads total about 2 GB across the three. The models are separate from the Node or Bun runtime and index. Remote embedding and reranking are opt-in and send document or query data to the configured services. qmd's `bench` compares labeled queries using rank and latency metrics, while its separate reranker bench measures runtime settings on sample documents. I did not find a controlled qmd reranker versus no-reranker result on engineering project memory. The added model and token cost is measured only after pbrain's paired task fixture shows a quality problem worth addressing. [Model defaults](https://github.com/tobi/qmd/blob/v2.9.0/src/llm.ts#L283-L302) · [Downloads](https://github.com/tobi/qmd/blob/v2.9.0/README.md#gguf-models-via-node-llama-cpp) · [Quality harness](https://github.com/tobi/qmd/blob/v2.9.0/src/bench/bench.ts) · [Reranker runtime harness](https://github.com/tobi/qmd/blob/v2.9.0/src/bench-rerank.ts)

A qmd CLI JSON hit can include a file path, content-hash-derived docid, score, title, snippet, context and metadata. `get` can retrieve by short docid or path with line windows. Snippet extraction's character target bounds one field. An agent's whole response also includes paths, scores, metadata and other results. The ID can change when the content changes, unlike pbrain's stable item IDs. The earlier local v2.9.0 lexical smoke test found that a Git-ignored file matching the collection glob was indexed. Metadata filters are useful query filters, and the shared-personal boundary needs to be enforced at corpus selection and storage instead of depending on them. ## What to borrow

**Inference.** Borrow a deterministic structure-aware chunker, post-tokenization caps, batch inference, model/input fingerprints, content reuse for unchanged bytes and rank-based fusion across incommensurate scores. Keep absolute match validation, item identity, source offsets, standing, time windows, personal exclusion and the full response budget in pbrain. Collapse to an eligible item before ranking or limiting so a long document cannot buy multiple result slots. Avoid expansion, HyDE, cross-encoding, native qmd integration and remote inference by default. Test a paired task that needs a learning and a task that needs its evidence before adding ranking complexity.
