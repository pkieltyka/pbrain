# Proposed pbrain hybrid search and index lifecycle

Design inference, 2026-11-20. This is a recommendation for an owner-approved amendment. The completed functional spec still defines lexical search, a fixed output budget, exact ID lookup and a shared view that cannot observe personal items. The proposal keeps those behaviours as a separately testable path and adds semantic retrieval only when requested. [Functional spec §§5–7 and 17](../../../functional_spec.md) · [Owner-approved research plan](../research_plan.md) · [Retrieval pilot agreement](../../../reviews/retrieval/joint.md)

## Retrieval order and abstention

1. **Keep lexical as the default contract.** A strict query still uses the existing whole-clause parser, match classes, explicit filters, recency, standing and top decision promotion. Its zero-result counts remain exact and budgeted. Offer an explicit hybrid mode as a proposed interface, gated on the owner approving its behaviour. Planned input is one query sent to a lexical leg and an embedding leg, with no expansion model or reranker. If the runtime or local weights are unavailable, lexical search stays usable offline. An explicitly requested hybrid query should say when the semantic leg is unavailable or incomplete and avoid presenting that as full hybrid coverage. [Functional spec §7.1](../../../functional_spec.md) · [qmd hybrid path](https://github.com/tobi/qmd/blob/v2.9.0/src/store.ts#L6913-L6945)
2. **Resolve the eligible item set before retrieval limits.** First apply the view and lifecycle, then kind, tags, status and time filters. Query shared and personal stores separately if the person opted into both. Embed one query per requested compatible embedding space. Score eligible chunks and keep the best passage per item before selecting the semantic item window. For SQLite `vec0`, pass candidate row IDs inside KNN, then test for underfilled distinct items after grouping. At the measured scale a scan over prefiltered vectors can group exactly and avoids a hard chunk cutoff. Design a per-item candidate quota or bounded escalation where grouping is needed. [qmd KNN scope and grouping](https://github.com/tobi/qmd/blob/v2.9.0/src/store.ts#L5438-L5577) · [Local exact-search measurements](./go-index-options-and-probes.md#scratch-measurements)
3. **Treat fusion as secondary evidence.** Rank the eligible item lists separately, then use simple RRF `Σ weight/(60 + one-based rank)`, with a missing contribution equal to zero. Start with equal weights and one bounded window from each leg, such as 40 distinct items, and measure. Avoid raw BM25-plus-cosine blends until scores are calibrated on real tasks. BM25 depends on term and corpus statistics, cosine depends on model and composition, and scaling either score into a numerical range does not make it comparable to the other. RRF helps combine ordering and cannot decide whether either list contains a good match. [RRF paper](https://cormack.uwaterloo.ca/cormack/cormacksigir09-rrf.pdf) · [FTS5 ranking](https://www.sqlite.org/fts5.html#the_bm25_function) · [qmd score implementation](./qmd-pipeline-and-tradeoffs.md#how-qmd-searches)
4. **Preserve policy above scores.** Resolve the current/replaced partition and preserve the strongest current lexical decision promotion. Suggested first hybrid policy is to keep exact lexical hits ahead of semantic-only hits within each lifecycle partition. Keep order among exact hits unchanged initially, and use fusion to choose a bounded candidate set and order the labeled semantic additions. A useful candidate variant for the pilot allows fused evidence to break ties within the same lexical match class, recency band and standing. That changes visible order and needs a decision based on paired learning-needed and source-needed tasks. Use a stable item ID and path for final ties, and count and paginate results by the same policy. [Functional spec §§4.4 and 7.1](../../../functional_spec.md) · [Pilot ranking agreement](../../../reviews/retrieval/joint.md)
5. **Allow no semantic result.** A nearest-neighbor algorithm can return a closest item even for unrelated input. Require an absolute relevance gate for semantic-only candidates, calibrated against labeled related and unrelated pairs for the exact model, prompt and dimensionality. RRF or a query-relative rank are unsuitable as the gate. Keep a current benchmark for abstention, especially paraphrases, missing answers, old answers, same-name components and personal-only answers. If the calibration does not support a reliable threshold for a model, present lexical results and say the semantic leg is unavailable for that model. In hybrid mode mark semantic-only results as such. Stay within the existing body and whole-response caps, and let exact `get` provide the citation. [qmd score and minimum-score paths](https://github.com/tobi/qmd/blob/v2.9.0/src/store.ts#L7112-L7157) · [pbrain evaluation research](../../knowledge-memory-landscape/agent-memory-systems/retrieval-priming-budgets-and-eval.md)

## Passages and identity

**Inference.** Index a short learning as one chunk and split long copied sources at deterministic Markdown headings, paragraphs and fenced blocks. Start a pilot with 384–640 model tokens per chunk and 10–15% overlap when overflowing a section. This range is a tuning proposal. It leaves room for titles and headings in models whose tokenizer input budget may be shorter than qmd's 900-token target. Enforce the actual budget after formatting and tokenizing. Store an exact begin and end span in the stored Markdown body using the same Unicode code-point offsets as `get`. Prefix title and heading path into the embedding input if evaluation shows it helps. The prefix is context for the encoder and the citation always points to actual stored text. Long inputs must make forward progress without splitting UTF-8 text. For linked items index only the known metadata and written summary, and never fetch linked content inside indexing. Keep section outlines out of ordinary results. [qmd token-bound and fallback chunking](https://github.com/tobi/qmd/blob/v2.9.0/src/store.ts#L4314-L4420) · [Functional spec §§2.5, 7.1 and 8.4](../../../functional_spec.md)

Store parent item identity, section and canonical path separately from a cache key. Bloom filters, scores and chunks survive rebuilds only as derived data. Share embeddings by exact formatted-input digest within one audience and model space. Fingerprint the actual model revision or weights digest, provider identity, format and prompts, output dimensions and normalization, tokenizer, and chunk algorithm. A change to any of these starts a different index generation. Changes to standing, replacement or access can update metadata without embedding the same body again. Text that changes its body span or chunk content invalidates the relevant derived rows. [qmd embedding fingerprint and completeness](https://github.com/tobi/qmd/blob/v2.9.0/src/store.ts#L186-L196) · [qmd current-model rows](https://github.com/tobi/qmd/blob/v2.9.0/src/store.ts#L2619-L2663)

## Storage, refresh and recovery

**Inference.** Start with a pbrain-owned lexical Go scan, using modernc SQLite for the first persistent hybrid experiment. Keep one protected DB per section and checkout identity. For an explicitly shared personal folder, scope its DB and update lock to the canonical personal root and recompute any cross-view relation effects against the active shared checkout. SQLite transactions can place item/chunk metadata, FTS and vector rows in a consistent DB snapshot. A committed Git/Markdown item remains authoritative if index publication fails. Store schema and generation state beneath each section's `.pbrain/`, keeping import originals separate from replaceable DBs, WAL and rebuild files. [SQLite transaction model](https://sqlite.org/lang_transaction.html) · [SQLite WAL](https://sqlite.org/wal.html) · [Functional spec §§5.1, 8.1 and 9.3](../../../functional_spec.md)

- **Change detection.** On write and on opening the index, compare the eligible paths for the active view. Match stat data by path and filesystem identity, and check the file hash on change, coarse or recent timestamp, branch/worktree switch and uncertain state. A Git commit or HEAD can be a hint. Working-tree changes and untracked files still need validation. Prefer a full rehash of small trees or a suspicious generation over serving stale candidates. Resolve allowed paths before reading. If an entry moved out of the view or is deleted, remove it from candidates, counts, excerpts and derived storage. Build summaries and passage output from current validated content, with path/digest checks before accessing the raw file. [qmd stat/mtime race guard](https://github.com/tobi/qmd/blob/v2.9.0/src/store.ts#L1928-L1947) · [Git index stat cache design](https://git-scm.com/docs/racy-git) · [Functional spec §§2.2 and 5](../../../functional_spec.md)
- **Concurrent updates.** Let one writer lock per section serialize reconciliation and commit schedule across CLI processes. Capture stable input batches, compute expensive embeddings outside SQLite write transactions, revalidate before publishing and discard work for files that changed meanwhile. Readers use consistent transactions, with bounded waits for busy writers. Keep WAL and its shared-memory files local to the host. Use a SQLite release that includes the WAL-reset corruption fix if using WAL. SQLite allows multiple readers but one active writer. WAL needs local shared memory and has checkpoint behaviour to plan for. [SQLite WAL](https://sqlite.org/wal.html) · [Busy timeout](https://sqlite.org/c3ref/busy_timeout.html) · [SQLite 3.51.3 changelog and WAL-reset fix](https://sqlite.org/releaselog/3_51_3.html)
- **Rebuilds and failures.** On schema mismatch, integrity failure or changed model generation, continue with the Go scan over current files. Rebuild under a new derived name, stage complete document batches, publish only validated state, and retire an old generation after readers release it. Never overwrite an active database or discard its WAL files independently. Keep all text, vectors, logs and query statistics for personal items out of shared DBs. No remote provider receives personal text or queries by default. Use a separate personal opt-in and generation if a later amendment allows that, including the model's actually formatted input and any provider telemetry in the scope. A remote-only configuration should keep local strict queries usable offline. [SQLite WAL files and checkpoints](https://sqlite.org/wal.html) · [qmd remote embedding boundary](https://github.com/tobi/qmd/blob/v2.9.0/README.md#remote-embeddings)

## Go/no-go measurements

- Compare strict baseline, exact-plus-semantic candidates, and any weighted ranking variant on the same real task requests at the same context budget. Count citable current decisions in the first page, correct unknown outcomes, sources needed for a task, total rendered tokens and calls, and private leaks in results, diagnostics and derived storage. Include hidden personal names, deleted items, branch changes, and both authority and document questions. Treat no privacy leakage as a prerequisite. [Joint retrieval response](../../../reviews/retrieval/joint.md)
- Separately measure cold process startup, available-model query embedding, DB opening/sync, exact candidate lookup and excerpt rendering. Measure initial embedding time and refresh time for 5,000 items, plus the 50,000-chunk, all-source stress case. The measured 60 ms vector query leaves room, but does not prove the 300 ms end-to-end target with an embedding runtime. At 5,000 chunks and even 40 ms per embedding, a serial initial build takes about 200 seconds. That is arithmetic for planning, not a measured model rate. Keep a useful lexical first read and explicit, resumable semantic preparation instead of requiring a full model build before the first search.
