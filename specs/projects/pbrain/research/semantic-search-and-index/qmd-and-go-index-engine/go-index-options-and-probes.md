# Go index choices and exact vector lookup measurements

Versions and probes checked 2026-11-20. The workload is 5,000 items today and up to 50,000 chunks as an explicit stress case. The binary must run locally on Linux and macOS, remain useful offline, and keep Markdown authoritative. This document concerns index access after vectors exist. The separate model-runtime research owns model initialization and inference. [Research plan](../research_plan.md) · [Functional spec §16](../../../functional_spec.md)

## FTS5 fits as an accelerator

FTS5 BM25 exposes column weights in `bm25(table, ...)` and sorts lower scores first. Its built-in formula fixes the customary two tuning constants. It offers prefix indexes and positional data for phrase queries. The default `unicode61` tokenizer and its diacritic behavior differ from pbrain's strict case-insensitive letter/digit contract. The tokenizer also decides what a query prefix and a phrase can find. A Go check after SQL can remove false positives but cannot restore a candidate an incompatible tokenizer missed. For strict lexical search, keep the Go scanner as reference. Use a token stream shared with the reference scanner, or prove that indexed candidate selection is a superset with an explicit scan fallback when it cannot guarantee coverage. Choose phrase and prefix semantics in pbrain, and translate parsed clauses into bound, escaped FTS syntax. Apply filters before any result window and render pbrain's own passage and code-point offset. [SQLite FTS5 tokenizer and syntax](https://www.sqlite.org/fts5.html#tokenizers) · [SQLite BM25](https://www.sqlite.org/fts5.html#the_bm25_function) · [Functional spec §§6–7](../../../functional_spec.md)

## Scratch measurements

**Observed, 2026-11-20.** Go 1.27.3, Linux amd64, Intel Core Ultra 7 255H, `GOMAXPROCS=1`. Scratch DB files were written and reopened in the same run, with no filesystem cache flush, model, remote call or simulator setting. Vectors were deterministic, randomly generated float32 unit vectors, with 31 distinct queries and top 20 nearest. The Go loop maintains top 20 on a contiguous slice and supplies a reference top ID. Every sqlite-vec query returned 20 candidates and agreed with Go on the top ID. The DB contained both a raw vector table for the Go loading test and a `vec0` table for the SQL test. The vector-byte column is the theoretical payload for one representation. SQLite overhead and duplicated storage in the probe are excluded. These timings describe this machine and workload only.

| Chunks × dims | Raw float32 payload | Exact Go p50 / p95, resident | SQLite vec0 p50 / p95, warm file pages | Go table load after reopen |
| --- | ---: | ---: | ---: | ---: |
| 5,000 × 256 | 5.12 MB | 0.98 / 1.17 ms | 1.80 / 2.64 ms | 8.4 ms |
| 5,000 × 768 | 15.36 MB | 3.17 / 4.00 ms | 6.60 / 8.75 ms | 21.2 ms |
| 50,000 × 256 | 51.20 MB | 9.72 / 11.54 ms | 18.71 / 20.62 ms | 72.2 ms |
| 50,000 × 768 | 153.60 MB | 39.17 / 39.83 ms | 56.54 / 59.76 ms | 195.4 ms |

All vector rows above used modernc v1.62.0 with sqlite-vec 0.1.9. Loading the regular table into Go includes row decoding, allocation and database opening. A fresh CLI process cannot assume a resident matrix. The mattn probe with its older cgo extension returned 131.48 / 134.84 ms at 50,000 × 768 on the same host. Different extension versions and compilation make that a compatibility and performance observation, with no driver speed ranking implied. The modernc build transaction for the fixture's two vector tables took 84 ms at 5,000 × 256 and 3.04 s at 50,000 × 768. These are the costs of writing precomputed data, excluding inference.

For FTS5, 5,000 repeated 10.22 KB bodies and segmented titles produced 51.1 MB of text. The weighted BM25 function was projected and the query used `ORDER BY rank LIMIT 40`. Modernc indexed the fixture in 363 ms and returned the selective and corpus-wide query at p95 of 0.15 and 8.87 ms, ncruces in 384 ms with p95 0.16 and 13.34 ms, and mattn in 466 ms with p95 0.47 and 12.82 ms. Repetition makes the fixture artificially compressible and selects easy lexical predicates. These timings exclude Git checks, Markdown enumeration and parsing, CLI start, ranking policy and rendering. They establish rough query scale and extension compatibility, not compliance with pbrain's end-to-end target.

**Inference.** Exact search is viable at 5,000 to 50,000 chunks on this class of machine. A resident Go slice wins these dot-loop comparisons but its data loading can spend most of the CLI budget on every invocation at the upper bound. Prefer a persistent SQL probe first, or benchmark a single validated matrix with a memory-mapped reader if the SQL path becomes material. For vectors alone, actual model dimension and chunk count dominate storage. Compare longer-term model runtime and time-to-first-query before using an ANN structure. Vec1 is an ANN extension with different construction and tuning needs than sqlite-vec. Revisit either if exact scanning at target scale misses its budget after sizing and data-transfer fixes. **Recommendation.** Use modernc SQLite as the first persistent-storage experiment, with bundled `vec0` for exact scoring and optional FTS5 for candidate retrieval. Keep a plain Go scan test oracle and the option to score prefiltered vectors in Go if the SQL KNN path underfills document results. Require a real corpus benchmark, cross-platform execution and concurrent-update tests before choosing the shipping dependency and release builds.
