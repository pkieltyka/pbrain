## Chrome DevTools MCP

**Connection modes.** `--autoConnect` selects the running local Chrome profile after the Chrome UI consent step. `--browser-url` and `--ws-endpoint` choose an explicitly configured endpoint. Without attachment, the tool can launch Chrome with its own persistent profile. `--isolated` creates a temporary profile in launch mode. The docs warn that some services restrict sign-in in automation-launched browsers. A person can use a permitted, manually launched dedicated Chrome profile, or export directly if sign-in policy blocks automation. [Chrome consent guide](https://developer.chrome.com/docs/devtools/agents/use-cases/auto-connect) · [Tagged advanced usage](https://github.com/ChromeDevTools/chrome-devtools-mcp/blob/chrome-devtools-mcp-v1.13.0/docs/advanced-usage.md) · [Tagged troubleshooting](https://github.com/ChromeDevTools/chrome-devtools-mcp/blob/chrome-devtools-mcp-v1.13.0/docs/troubleshooting.md)

**Agent interface.** List pages, select by ID, and use `take_snapshot` to locate evidence that the expected content loaded. The snapshot is an accessibility outline. A targeted `evaluate_script` can inspect a selected rendered element when approved. Avoid exposing broad script execution when the native download can do the job. A filesystem workspace limits paths for supported filesystem tools. Keep performance traces out of a content import and set `--no-usage-statistics` and `--no-performance-crux` if opting out of usage statistics and trace-URL queries. Those options say nothing about the model host's data handling. [v1.13.0 tool reference](https://github.com/ChromeDevTools/chrome-devtools-mcp/blob/chrome-devtools-mcp-v1.13.0/docs/tool-reference.md) · [v1.13.0 configuration](https://github.com/ChromeDevTools/chrome-devtools-mcp/blob/chrome-devtools-mcp-v1.13.0/docs/configuration.md) · [Chrome privacy notes](https://developer.chrome.com/docs/devtools/agents/use-cases/auto-connect)

## Agent Browser

- `--cdp` connects to the named endpoint, for example the dedicated loopback Chrome instance. `--auto-connect` supports the Chrome 144+ consent flow and also probes common debugging ports when discovery fails. Verify the browser, account and page before acting. Use a dedicated named session with `--pin-tab` where appropriate. With no prior binding it can create a fresh tab. Bind or select the intended tab explicitly. An unpinned `open` can navigate a shared active tab. [v0.43.0 CDP mode](https://github.com/vercel-labs/agent-browser/blob/v0.43.0/docs/content/docs/cdp-mode.mdx)
- `tab list` and `snapshot` let the agent find the target. `get html <sel>` returns inner HTML for a known element. `read` without a URL reads the active rendered DOM. `read <url>` is an HTTP fetch with Markdown negotiation and possible documentation probes, so it will not use the already-open page's live state. Likewise, `--llms` and `--require-md` need HTTP resources even when the URL argument is omitted. Check the result before using it as Markdown, and never import a context-truncated response as the full source. [v0.43.0 command reference](https://github.com/vercel-labs/agent-browser/blob/v0.43.0/docs/content/docs/commands.mdx)
- The client can restrict actions, wrap page output in boundary markers and limit output size. The domain allowlist refuses attachment to an existing browser and several reused-auth modes in this release. In CDP attachment `download <sel> <path>` and `wait --download <path>` are rejected. A pathless wait can report the browser's own file location. Use the site's browser-managed download, a file supplied by the person, or a scoped local DOM save. [v0.43.0 security](https://github.com/vercel-labs/agent-browser/blob/v0.43.0/docs/content/docs/security.mdx) · [v0.43.0 commands](https://github.com/vercel-labs/agent-browser/blob/v0.43.0/docs/content/docs/commands.mdx)
- The 0.43.0 release on November 12, 2026 includes fixes for responsiveness on large snapshots and for closing tabs. I verified the installed tool's version and help, without running its daemon or opening a browser. This is evidence of available commands and current maintenance. Existing-session reliability on the intended sites remains unmeasured. [Release notes](https://github.com/vercel-labs/agent-browser/releases/tag/v0.43.0)

## OpenCode Browse

At tag 0.1.5 the CLI and MCP clients talk to a Rust relay. A Manifest V3 extension connects to that relay and issues CDP through `chrome.debugger`. Release notes clarify that the project has used its own transport since 0.1.0. Some APIs still have a Playwright-style shape. The relay defaults to loopback and has a local token and an authenticated extension pairing flow. The tagged README lists Chrome, Edge, Brave, Arc, Helium, Vivaldi, Opera, and Chromium. The extension manifest requires Chromium 125+ and declares `debugger`, `scripting` and `<all_urls>` among its permissions. [v0.1.5 release](https://github.com/anomalyco/browse/releases/tag/v0.1.5) · [Tagged README](https://github.com/anomalyco/browse/blob/v0.1.5/README.md) · [Manifest](https://github.com/anomalyco/browse/blob/v0.1.5/public/manifest.json) · [Chrome extension debugger API](https://developer.chrome.com/docs/extensions/reference/api/debugger/)

The person can lend an existing tab using the toolbar control and click again to take it back. An agent can also open its own tab and address it by ID. OpenCode's MCP client sees individual tools, while other MCP clients default to an `execute` interface plus `status` and `tabs`. The CLI can address the same tabs. For an import, use one authorized tab, keep the relay local, and avoid broad `execute`, network capture, or access to cookies. Browser-provided sign-in handoff lets the person perform the human steps. [Tagged usage and tools](https://github.com/anomalyco/browse/blob/v0.1.5/README.md#using-it)

**Where scoping stops.** `allowedOrigins` limits navigation, top-level documents and agent tabs and popups. It does not filter page-generated subresources such as frames and XHR. `readOnly` blocks ordinary interaction commands, but allows `eval` and WebMCP, which can still act through page JavaScript. The tab handoff is a practical control. Treat installed extension permissions, relay trust, and returned page data as separate decisions. Chrome's original stricter Chrome 155 debugger policy got a November rollback. Managed-browser behavior can vary with policy and update channel, and needs verification in the user's environment. [Tagged security model](https://github.com/anomalyco/browse/blob/v0.1.5/README.md#security) · [Chrome November 2026 rollback notice](https://developer.chrome.com/blog/debugger-enterprise-policy-restrictions)

**Maturity.** The reviewed 0.1.5 release is from November 17, 2026, one day after 0.1.0. Its installation can update client configuration and the relay checks for updates. That makes Browse an opt-in alternative when the per-tab workflow is worth a persistent extension and relay. Keep it outside pbrain's required installation. No extension install, pairing, or upload was tested. [Releases](https://github.com/anomalyco/browse/releases) · [Tagged installation and update behavior](https://github.com/anomalyco/browse/blob/v0.1.5/README.md)

## Claude in Chrome as a comparison

Claude in Chrome is a first-party browser extension with site permissions, confirmations and restrictions for downloads and sensitive operations. It gives users a way to approve particular sites in that product's workflow. Its permissions and tool availability are specific to Claude. They illustrate a human-control pattern for browser capture. [Claude in Chrome permissions](https://support.claude.com/en/articles/12902446-claude-in-chrome-permissions-guide) · [Safety guidance](https://support.claude.com/en/articles/12902428-use-claude-in-chrome-safely)
