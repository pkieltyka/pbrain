# Browser automation over CDP

## Bottom Line

Keep Chrome outside pbrain and hand it a local Markdown or scoped HTML file with `pbrain import <file> --source <url>`. Prefer a site's download or copy feature, especially for Google Docs and Claude artifacts. When automation is needed, Chrome 144+ provides a supported user-approved attachment to the existing browser, and Chrome DevTools MCP is the most portable documented starting point for agents already equipped to use it. A dedicated signed-in profile reduces exposure for recurring captures because ordinary Chrome attachment grants access to the whole selected profile. Agent Browser and OpenCode Browse are optional tools, with different setup and tab controls. [pbrain functional spec §§8.4 and 12](../../../functional_spec.md) · [Chrome auto-connect](https://developer.chrome.com/docs/devtools/agents/use-cases/auto-connect) · [Google Docs export](https://support.google.com/docs/answer/12014036?hl=en) · [Claude artifact export](https://support.claude.com/en/articles/17153992-what-are-artifacts-and-how-do-i-use-them)

## Key Findings

- **Two different Chrome attachment mechanisms.** Chrome 136 disabled the legacy port and pipe switches on the default user-data directory. Chrome 144+ has a separate in-browser consent flow for a running session. Use DevTools MCP's `--autoConnect`. Playwright 1.65.1 documents local channel-name attachment such as `connectOverCDP('chrome')` alongside ordinary HTTP or WebSocket endpoints. Use an explicitly configured loopback endpoint for a dedicated browser instance. The consent flow uses different discovery and may return 404 from the usual HTTP discovery URLs. [Chrome 136 change](https://developer.chrome.com/blog/remote-debugging-port) · [Chrome 144+ auto-connect](https://developer.chrome.com/docs/devtools/agents/use-cases/auto-connect) · [Playwright API](https://playwright.dev/docs/api/class-browsertype#browser-type-connect-over-cdp) · [HTTP discovery issue](https://github.com/ChromeDevTools/chrome-devtools-mcp/issues/2283)
- **Agent Browser is a shell-first option.** Version 0.43.0 is a native CLI with CDP support. Pin and verify the selected tab. `read` without a URL reads the active rendered DOM, whereas `read <url>` performs an HTTP fetch. Tab pinning avoids targeting mistakes. The domain allowlist does not work with existing browser attachment, and download helpers that override the local destination are unavailable in that mode. [Release v0.43.0](https://github.com/vercel-labs/agent-browser/releases/tag/v0.43.0) · [CDP mode](https://github.com/vercel-labs/agent-browser/blob/v0.43.0/docs/content/docs/cdp-mode.mdx) · [Commands](https://github.com/vercel-labs/agent-browser/blob/v0.43.0/docs/content/docs/commands.mdx) · [Security](https://github.com/vercel-labs/agent-browser/blob/v0.43.0/docs/content/docs/security.mdx)
- **OpenCode Browse offers explicit tab handoff at the cost of another install.** Version 0.1.5 uses a Chromium extension and paired local relay on macOS, Linux and Windows. A person can lend one tab from the toolbar and take it back. Its origin and read-only settings constrain some actions, while evaluation and page-initiated requests retain capabilities. It is a young optional tool. Claude in Chrome provides a separate example of site-specific approvals. [Browse release v0.1.5](https://github.com/anomalyco/browse/releases/tag/v0.1.5) · [Browse security and tabs](https://github.com/anomalyco/browse/blob/v0.1.5/README.md) · [Claude in Chrome permissions](https://support.claude.com/en/articles/12902446-claude-in-chrome-permissions-guide)
- **Capture the document surface.** Readability yields article HTML and text, and Defuddle can emit Markdown. In offline fixtures, both selected chat text from a shell and only returned the intended artifact when it was supplied as a scoped article. Both could return toolbar text for an empty canvas shell. Google Docs' canvas rendering makes its native Markdown export preferable. Claude artifact formats and permissions vary, so check the export controls and account before capturing a panel or frame. [Fixture results](./rendered-content-handoff.md#offline-fixture-check) · [Google Docs canvas update](https://workspaceupdates.googleblog.com/2021/05/Google-Docs-Canvas-Based-Rendering-Update.html) · [Claude exports](https://support.claude.com/en/articles/17153992-what-are-artifacts-and-how-do-i-use-them) · [Claude artifact permissions](https://support.claude.com/en/articles/9547008-share-artifacts)
- **Authorize access, retention and audience.** Verify the account and intended tab, let the person handle login and MFA, reject page-supplied instructions, and keep credentials and private material out of tool logs and external model context. Save only permitted content locally. Use `--personal` when authorized retention is local-only and confirm the repository audience before a shared import. Section 8.4 keeps the input bytes, including anything conversion removes. Close the temporary attachment when done. ## Open Questions / Gaps

- I checked published Chrome workflows, tagged implementations and issue notes. No browser was launched, and no profile, session, Chrome setting or extension was accessed or changed. I did not test the live consent dialog, target profile selection on machines with multiple profiles, or managed-device and sandbox restrictions.
- I verified Agent Browser 0.43.0's version and help and used an offline DOM fixture. I did not test live output fidelity on Claude artifact variants, Docs, Slack, or an enterprise app. Native download availability depends on app and viewer permissions.
- Browse's tab handoff and guardrails are documented in v0.1.5. I found a recent release history and did not run the extension or establish production reliability. Tool output confidentiality also depends on the user's actual harness and logging configuration.
