# From an authorized browser page to a pbrain file

Reviewed 2026-11-19. The browser loads and renders the source under the person's session. The import consumes one local file, with the exact material to retain and a separate source URL. Browser capture and native export have different fidelity, so confirm the file matches the requested scope before handing it off. [pbrain functional spec §§8.4, 12 and scenario 22](../../../functional_spec.md)

## Capture routes

| Page | First route | If a browser capture is needed |
| --- | --- | --- |
| Google Docs | Use File → Download → Markdown (.md). Google also documents Copy as Markdown for a selected portion. Respect any copy/download restriction and request an authorized export where necessary. | The editor uses canvas rendering. The DOM can contain controls and accessibility scaffolding without a reliable document body. Use the site's export and avoid generic Readability on the editor. [Google Docs Markdown help](https://support.google.com/docs/answer/12014036?hl=en) · [Google's canvas rollout](https://workspaceupdates.googleblog.com/2021/05/Google-Docs-Canvas-Based-Rendering-Update.html) |
| Claude artifact | Use a Markdown export if offered, the legacy artifact's copy/download controls when available, or standalone HTML suitable for capture. Claude's help lists HTML as an export for Designs and Markdown as an export for Docs. Capabilities depend on artifact type and access level. | Where permitted, isolate the rendered artifact panel or the specific frame that contains the artifact. An outer page can be a chat or app shell. A runtime app, canvas or multi-file artifact may need a user-provided export or an explicitly labeled excerpt. Check the actual artifact URL and permission. Claude supports both restricted and published artifacts. [Claude artifact types and export options](https://support.claude.com/en/articles/17153992-what-are-artifacts-and-how-do-i-use-them) · [Artifact access levels](https://support.claude.com/en/articles/9547008-share-artifacts) |
| Ordinary JS-rendered document | Use a site download or Markdown copy where available. Otherwise wait for the requested document to render and isolate its article surface. | Extract semantic headings, paragraphs, lists, links, tables and code from the scoped region. Wait for a content-specific element and check that the expected sections are present. Virtualized rows, embedded frames and canvas can leave the capture partial. [Playwright frame locators](https://playwright.dev/docs/frames) · [Mozilla Readability inputs](https://github.com/mozilla/readability/tree/0.6.0#usage) |

A browser snapshot makes it easier to identify the correct target and visible structure. It is designed for navigation and accessibility, and it may lack link destinations, rendered code or table structure. Capture data from a named UI region or use a site export for a durable file. Save a minimal HTML fragment in a standalone document if using HTML import. Include only the requested content and safe link destinations. Keep scope and final document-load checks distinct from the 200-character HTML conversion floor. A long conversation shell can clear the floor. [DevTools MCP tool reference](https://github.com/ChromeDevTools/chrome-devtools-mcp/blob/chrome-devtools-mcp-v1.13.0/docs/tool-reference.md) · [pbrain HTML conversion contract](../../../functional_spec.md)

## Local extraction and fidelity

- **Mozilla Readability 0.6.0.** Takes a DOM and uses heuristics to select article content. Run on a clone because the parser mutates the tree. It emits article HTML and plain text alongside metadata. A separate step is needed for Markdown. Supply the document's base URL for relative links. The project explicitly says it is not a sanitizer. Treat the capture as untrusted and process it offline without running scripts or loading resources. [Tagged README](https://github.com/mozilla/readability/tree/0.6.0)
- **Defuddle 0.19.7.** Can take an existing DOM and output Markdown and metadata, with a separate base URL. It is a candidate for semantic markup and standard article pages. Scope first on app pages. Previous pbrain fixtures found that the output can drop a body heading even when it keeps code and tables. Inspect output rather than assuming serializer fidelity. [Package 0.19.7](https://www.npmjs.com/package/defuddle/v/0.19.7) · [Defuddle DOM API](https://github.com/kepano/defuddle#nodejs) · [Earlier pbrain converter fixtures](../../knowledge-memory-landscape/source-ingestion/converters-and-fidelity.md)
- **Small direct capture.** If the exact region is clear, save scoped HTML and let pbrain do its standard conversion. For short plain text or a Markdown export, use that format directly. When a frame has a different origin or path, preserve its intended relative links by resolving them against the frame document base during capture and retain the stable user-facing URL as provenance. Verify rewritten links are safe to retain. Avoid including hydration state, editable fields, unrelated chrome, comments outside scope, and embedded scripts. [Playwright frame access](https://playwright.dev/docs/frames) · [Readability URI guidance](https://github.com/mozilla/readability/tree/0.6.0#usage) · [pbrain file rules](../../../functional_spec.md)

### Offline fixture check

With Node 26.13.1, JSDOM 31.0.1, Readability 0.6.0 and Defuddle 0.19.7, I ran the same extraction on three synthetic HTML inputs. JSDOM used `https://example.test/docs/item` as the base, with default script and resource loading disabled. The two text samples used a distinct sentinel followed by repeated prose. This exercises extraction after markup has been supplied. It does not measure live app extraction, canvas access, CDP attachment or pbrain's Go converter. ## Local handoff to pbrain

1. Confirm the exact source, the permitted material and the intended readers. Use a site-supported export first. For a browser capture, the person explicitly authorizes the connection and opens the target. Scope the operation to that tab, check the origin, and keep all sign-in steps with the person. [Chrome auto-connect](https://developer.chrome.com/docs/devtools/agents/use-cases/auto-connect) · [Claude artifact sharing and permissions](https://support.claude.com/en/articles/9547008-share-artifacts)
2. Save just the authorized content as a UTF-8 `.md`, `.markdown`, `.txt`, `.html` or `.htm` file in a private temporary location. Favor a deterministic local export when the material has to stay on this machine. Check title, relevant sections and links, missing content, unexpected empty state, and truncation before import. The spec limits the input file to 5 MiB and the cleaned body to 512,000 characters. HTML has a 200-character extraction floor and the conversion performs no network request. Prefer Markdown if a valid article is shorter than the floor. [pbrain file and conversion limits](../../../functional_spec.md)
3. Pass the file with a stable source URL. For authorized local-only retention, use `pbrain import capture.md --source 'https://example.test/notes/rollout' --personal`. The current spec defaults to shared. Use a shared copy only when the person confirms the repository audience may read it. `--source` records provenance, and for HTML it supplies a base for relative links. Import writes one `kind: source`, `origin: file` item and caches the input bytes locally. The original can still contain content stripped during conversion, so reduce the file before import. A subsequent capture can be a fresh import with `--replaces`. [pbrain import and personal-data rules](../../../functional_spec.md)
4. Disconnect the tool and release the tab once the file is saved and checked. Remove the temporary staging copy when appropriate. If export is unavailable, restricted, or fails the quality check, ask for an authorized file or retain only a permitted stable URL as a link. When a partial capture is authorized and useful, mark it as an excerpt. [Chrome consent flow](https://developer.chrome.com/docs/devtools/agents/use-cases/auto-connect) · [pbrain link-only contract](../../../functional_spec.md)

## Spec implications

Scenario 22 tests the right boundary for pbrain itself. Input is local captured HTML, and output includes its URL, exact original, and Markdown without a network call. Give that fixture text above the HTML floor and at least one relative link. A separate manual browser acceptance case could verify the source file contains the intended artifact and no adjacent conversation. Claude's public and restricted sharing modes also support narrowing §8.4's sign-in premise to **permission-gated** artifacts. None of the browser findings requires pbrain to implement authentication, attach to CDP or choose a specific client.
