# Session priming in Beads and Gas Town

## Beads 1.3.4

Beads exposes a distinct knowledge interface beside its issue tracker. `bd remember "<insight>" --key <key>` writes or replaces a key in the Dolt-backed memory plane. `bd memories [search]` lists or finds entries by keyword, `bd recall <key>` reads one in full and `bd forget <key>` removes it. The storage-facing renderer sees a map from keys to text, with no timestamps for ranking. A simple explicit key is useful for retrieval, while overwrite-in-place and no provenance make this an incomplete model for pbrain decisions. [Memory CLI](https://github.com/gastownhall/beads/blob/v1.3.4/cmd/bd/memory.go) · [Prime renderer](https://github.com/gastownhall/beads/blob/v1.3.4/cmd/bd/prime.go#L521-L587)

`bd prime` emits startup workflow Markdown. The CLI estimates roughly 1,000–2,000 tokens for the full workflow reference and roughly 50 tokens for the MCP-mode reminder, before memory. Hook JSON wraps the Markdown in `hookSpecificOutput.additionalContext` under the SessionStart event. A workspace's `.beads/PRIME.md` can override the workflow text, with persistent memories appended. `--memories-only` or `--no-memories` switches the memory section on independently of workflow help. Claude Code, Gemini CLI and Codex are named in the hook implementation. The fallback skill stays short and tells an agent to rerun prime when it needs current context. [Prime command and hook format](https://github.com/gastownhall/beads/blob/v1.3.4/cmd/bd/prime.go#L85-L145) · [Hook envelope](https://github.com/gastownhall/beads/blob/v1.3.4/cmd/bd/prime.go#L260-L280) · [Installed skill](https://github.com/gastownhall/beads/blob/v1.3.4/internal/templates/skills/beads/SKILL.md)

The configurable `--max-memories` and `--max-memory-chars` default to zero, meaning unlimited. The latter counts rendered memory-entry bytes, excluding headings and the elision banner. It selects an alphabetical prefix at whole-entry boundaries and always includes the first entry even when it exceeds the budget. The compact renderer flattens newlines and truncates each value at about 150 characters. A banner reports omitted entries and points to lookup, and the current code distinguishes an unavailable memory store from an empty one. A Linux package smoke test with two stored entries and a byte cap of one emitted the full first entry and the omission banner. Explicit recall read the omitted entry. Take the elision and follow-up pattern for pbrain, with an actual upper bound over the complete rendered payload. ## Gas Town 1.2.1

Steve Yegge's Gas Town builds persistent agent and work coordination on Beads. A rig wraps a project checkout. A polecat has a durable work identity with a replaceable session. On startup, `gt prime --hook` reloads role instructions, assigned work, handoff and molecule context. A legacy agent bead's `hook_bead` can still point at the assignment. The tagged code says new dispatch usually resolves work by assignee and hooked or in-progress status in the rig or town database. The recovery path on compaction or resume is lighter and skips the retry-heavy work lookup. A real lookup error is surfaced separately from a successful empty result, after an earlier failure mode where agents could treat unavailable assignments as completed or absent. [Launch motivation](https://steve-yegge.medium.com/welcome-to-gas-town-4f25ee16dd04) · [Roles and rigs](https://github.com/gastownhall/gastown/blob/v1.2.1/README.md#core-concepts) · [Prime startup](https://github.com/gastownhall/gastown/blob/v1.2.1/internal/cmd/prime.go#L145-L245) · [Recovery branch](https://github.com/gastownhall/gastown/blob/v1.2.1/internal/cmd/prime.go#L263-L303) · [Hook lookup](https://github.com/gastownhall/gastown/blob/v1.2.1/internal/cmd/prime.go#L800-L885)

Gas Town also offers `gt remember --type … --key …`, backed by Beads key/value rows with a type prefix. Full prime reads them via `bd kv list --json` and renders Markdown in feedback, user, project, reference and general order, with alphabetic keys inside each group. The tagged renderer emits every value it reads. Its external tool has a timeout, while the shown renderer has no byte/token cap and silently skips a failed memory read. The town template instructs agents to use this command and labels feedback as behavioral rules. pbrain's project notes and imported references need their own data role, with workflow instructions coming separately from the authorized skill. [Gas Town writer and type priority](https://github.com/gastownhall/gastown/blob/v1.2.1/internal/cmd/remember.go#L16-L100) · [Memory read and render](https://github.com/gastownhall/gastown/blob/v1.2.1/internal/cmd/prime.go#L540-L657) · [Agent instructions](https://github.com/gastownhall/gastown/blob/v1.2.1/internal/templates/townroot/claude.md#L70-L90) · [pbrain data boundary](https://github.com/pkieltyka/factory/issues/62)

A mixed-version call failed in the local Beads 1.3.4 fixture. Gas Town 1.2.1 invokes `bd kv set` with a `memory.` key, which Beads 1.3.4 rejects as reserved for `bd remember`. After storing an equivalent key through `bd remember`, `bd kv list --json` also returned a numeric `schema_version` beside the string entries. Gas Town 1.2.1 decodes that response into `map[string]string`; the observed numeric field is incompatible with that code. This check exercised the exact external Beads calls and response, with no full Gas Town launch. It argues for versioned adapter contracts when integrating sibling CLIs. [Gas Town write and list calls](https://github.com/gastownhall/gastown/blob/v1.2.1/internal/cmd/remember.go#L193-L233) · [Gas Town prime list decoder](https://github.com/gastownhall/gastown/blob/v1.2.1/internal/cmd/prime.go#L649-L661) · [Beads key guard and formatter](https://github.com/gastownhall/beads/blob/v1.3.4/cmd/bd/kv.go#L26-L128)

Gas Town's formulas define multi-step workflows. Cheap short-lived steps can come from the formula at read time, with a single root wisp in the store and an inline prime checklist. Expensive workflows can use persisted sub-wisps so restarting retains completed checkpoints. Its docs give an internal workload example of row growth falling from over 6,000 to about 400 per day after switching high-frequency workflows to root-only. The transferable pattern is to persist the durable assignment and references, then render just the task-relevant context. [Gas Town molecules](https://github.com/gastownhall/gastown/blob/v1.2.1/docs/concepts/molecules.md)

## Implications for factory and pbrain

A short skill can link an assigned note or spec id, explain exact retrieval plus bounded search, and give one recovery path on resume. An optional future startup slice can select authoritative items or explicit task links, include a concise source per item and announce omitted records. Apply the result cap to the full rendered payload and make store unavailability visible. Continue to keep task routing, handoff scheduling and workflow messages in factory.
