## Issue identity, links and the ready queue

A bead holds a stable, prefixed work ID, issue type, priority, status, assignee, owner, description, notes, optional spec ID and lifecycle timestamps. Beads documents generated IDs as hash-derived at creation with collision handling and optional hierarchical child IDs. Dependencies are directed, typed records with a source and target. The Go implementation counts only `blocks`, `parent-child`, `conditional-blocks` and `waits-for` toward readiness. `discovered-from`, `related`, `relates-to`, `supersedes` and `validates` can express context without altering readiness. `bd dep list` can filter by direction and type, and the docs describe cycle checks for dependency writes. [Core concepts](https://github.com/gastownhall/beads/blob/v1.3.4/docs/core-concepts/index.md) · [Dependency commands](https://github.com/gastownhall/beads/blob/v1.3.4/docs/core-concepts/dependencies.md) · [Issue and edge types](https://github.com/gastownhall/beads/blob/v1.3.4/internal/types/types.go#L1243-L1352)

`bd ready --json` answers which open issues are claimable under current blockers. Deferred, hooked and in-progress work is excluded. `bd ready --claim --json` claims one atomically, and a workflow can depend on a gate representing a merge, CI result, timer or human approval. The repo's AGENTS.md and installed skill show agents a small command loop around ready, show, create, claim/update and close. They encourage JSON for automation and `discovered-from` for follow-up work. The published plugin's skill itself directs newer clients to the CLI's `bd prime` for current guidance. [Ready command](https://github.com/gastownhall/beads/blob/v1.3.4/cmd/bd/ready.go#L20-L39) · [Gate behavior](https://github.com/gastownhall/beads/blob/v1.3.4/docs/core-concepts/dependencies.md#gates) · [AGENTS.md](https://github.com/gastownhall/beads/blob/v1.3.4/AGENTS.md#L169-L250) · [Installed skill](https://github.com/gastownhall/beads/blob/v1.3.4/internal/templates/skills/beads/SKILL.md) · [Plugin skill](https://github.com/gastownhall/beads/blob/v1.3.4/plugins/beads/skills/beads/SKILL.md)

`bd supersede OLD --with NEW` records an old-to-new edge called `supersedes` and separately closes OLD. The stored direction is worth spelling out because the verb alone could be read the other way. Closure and the link happen in two storage calls, so a failure after the edge write can leave an unfinished lifecycle transition. For pbrain, use an unambiguous directional relation, derive effective status from authoritative links, and preserve old note and source references. [Supersede implementation](https://github.com/gastownhall/beads/blob/v1.3.4/cmd/bd/duplicate.go#L130-L194) · [pbrain acceptance fixture](https://github.com/pkieltyka/factory/issues/62)

A temporary embedded Beads 1.3.4 Linux fixture produced `Prerequisite, Related` in the ready queue when both `Dependent` and `Related` had edges to the prerequisite, one blocking and one informational. After closing it, the result was `Dependent, Related`. Initialization also installed local Claude Code and Codex hooks/instructions plus the skill in the temporary checkout. The prerequisite test demonstrates the operational meaning of link types. ## Storage transition and operational trade-offs

| Period | Storage and sync |
| --- | --- |
| Classic | Local SQLite operational state with Git-tracked JSONL synchronization. The older changelog records locking, stale exports, incremental JSONL and merge handling. |
| February to March 2026 | 0.50 switched the default to Dolt while documenting SQLite compatibility. The 0.51 and 0.56 cleanup entries cover removal of legacy SQLite/JSONL machinery, and the 0.58 entry and March 2 removal commit explicitly drop remaining Classic SQLite support. The changelog records temporary removal and later return of embedded Dolt. |
| Beads 1.3.4 | Dolt is canonical. Standalone defaults to embedded Dolt, with external `dolt sql-server` for multi-process writers. Dolt commits, remotes and backups carry structured history. Git can host Dolt data through its separate refs. `bd export` creates JSONL for interchange. Export refresh and Git staging are opt-in as of 1.0.5. |

The rationale is database-level version control, cell-level merging, isolated branches and concurrent writers. This pays off for a live task graph but adds schema migration, server and history-maintenance failure modes. The earlier Git-file path could co-commit issue and code changes. A Dolt-backed issue can close before the code lands, which motivates external gates. - **Cross-clone upgrades.** A May 2026 user report showed independently migrated clones failing to merge a rebased dependency schema. Later notes document deterministic edge ids and a guarded single-migrator flow. The 1.3.4 release still carries separate upstream advice to avoid history rewrite on some clones adopting migration 0062 because their pre-upgrade audit history can differ. ## What memory decay does

Beads describes semantic compaction as decay of old closed issues. In 1.3.4 it is `bd admin compact`, with analyze/apply and provider-backed auto modes. The implemented CLI tier defaults to 30 days after closure, and checks status, age and prior compaction. The live issue's description is replaced by a summary and secondary text fields are cleared. Although help text still describes permanent loss, tagged Tier 1 code snapshots the original first, aborts on snapshot failure, and `bd restore` can read or apply the saved text. Direct server access is required for normal semantic mutations and the proxied mode only supports the admin command's Dolt-GC route. Separately, top-level `bd compact` squashes old Dolt commits and `bd purge` handles ephemeral issue retention. The knowledge key/value store injected by prime is another distinct feature. [Admin command](https://github.com/gastownhall/beads/blob/v1.3.4/cmd/bd/compact.go#L39-L148) · [Eligibility and snapshots](https://github.com/gastownhall/beads/blob/v1.3.4/internal/storage/issueops/compaction.go#L15-L155) · [Tier 1 write](https://github.com/gastownhall/beads/blob/v1.3.4/internal/compact/compactor.go#L86-L150) · [Restore](https://github.com/gastownhall/beads/blob/v1.3.4/cmd/bd/restore.go) · [History maintenance](https://github.com/gastownhall/beads/blob/v1.3.4/docs/cli-reference/compact.md)
