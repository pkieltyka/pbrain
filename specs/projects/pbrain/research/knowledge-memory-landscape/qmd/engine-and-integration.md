## Collections and index ownership

A collection is a named filesystem root plus a glob, normally `**/*.md`. The YAML also accepts ignore globs and path-prefix descriptions inherited by descendants and returned as context. `collection add` indexes immediately. Run `update` after edits and `embed` to compute missing vectors. In 2.9.0 scans reuse unchanged modification-time/size pairs, normally deactivate missing files and skip files over 10 MB. A missing collection root preserves existing rows, so search can return stale text after a worktree or mount disappears. Named indexes and project-local `.qmd/index.yml` can isolate a checkout. [Configuration and commands](https://github.com/tobi/qmd/blob/v2.9.0/README.md#configuring-indexyml) · [Scan implementation](https://github.com/tobi/qmd/blob/v2.9.0/src/cli/qmd.ts#L2216-L2353) · [2.9.0 changes](https://github.com/tobi/qmd/releases/tag/v2.9.0)

qmd stores document text and file mappings, title, metadata, FTS5 tables, chunk records, per-collection sqlite-vec rows and model response caches in SQLite. The default database is `~/.cache/qmd/index.sqlite`; project-local configuration places a database beside its YAML. Git can carry the collection configuration if desired, with database, sidecars and model artifacts out of Git. The index is derived from the files and configuration, and it holds text readable independently of those files. Project-local config can gate update commands, out-of-project roots, custom models and processors on trust approval. A 2.9.0 processor can generate stable-key virtual Markdown and projected metadata inside the database from original inputs, but the processor is another executable or callback to maintain. ## Retrieval and model costs

| Route | Pipeline | Model requirements |
| --- | --- | --- |
| `search` or SDK `searchLex` | SQLite FTS5 BM25, with path/title/body weighting. Supports exact phrases and exclusions. | None. |
| `vsearch` | Uses the original query and expanded semantic/HyDE variants, merges by best vector score. | Embedding and local query expansion. |
| Free-text `query` | Expansion, BM25 and vector retrieval, reciprocal rank fusion and by default reranking. `--no-rerank` skips the final stage. | Generation, embedding and reranking by default for the full pipeline. |
| Typed `query` | Caller supplies `lex:`, `vec:` and/or `hyde:` lines. Typed clauses bypass generation. `vec:` with `--no-rerank` is an embedding-only query. | Depends on clause types and rerank option. Use `search` for a direct lexical call. |

The default GGUF downloads are about 300 MB for embedding, 640 MB for reranking and 1.1 GB for expansion, approximately 2 GB total. They are cached locally after download. The full path's wall time depends on hardware, model warmness and candidate count. Upstream's February 2026 0.9.0 changelog reported a warm HTTP daemon improvement from roughly 16 s to 10 s in its historical setup. A February CPU-only issue reported more than 120 s for reranking before the skip option was added. A September 2.8.3 Windows report describes a hang when downloads were missing or corrupted, with model cache diagnostics in `qmd doctor`. Treat all three as dated observations, and measure pbrain's workloads before opting into model-backed retrieval. [Algorithms and default model sizes](https://github.com/tobi/qmd/blob/v2.9.0/README.md#search-commands) · [Default models](https://github.com/tobi/qmd/blob/v2.9.0/README.md#gguf-models-via-node-llama-cpp) · [Vector and typed-query implementation](https://github.com/tobi/qmd/blob/v2.9.0/src/store.ts#L7288-L7444) · [Changelog](https://github.com/tobi/qmd/blob/v2.9.0/CHANGELOG.md) · [CPU report](https://github.com/tobi/qmd/issues/231) · [Model-load report](https://github.com/tobi/qmd/issues/977)

2.9.0 adds OpenAI-compatible remote embeddings and a fixed TypeSafe remote reranker. Remote embeddings send formatted document chunks during embedding and formatted queries during vector search. TypeSafe receives the query, candidate text and title if supplied. The remote reranker omits qmd file identifiers from requests. Using either provider crosses a process boundary on loopback and a machine boundary when hosted elsewhere. Local expansion is a separate choice. Changing embedding spaces can require re-embedding. qmd's HTTP/MCP server is another boundary: it binds to loopback by default, checks Origin and Host and exposes unauthenticated endpoints. ## Agent calls, fields and budgets

- The CLI returns human output, JSON, CSV, Markdown, XML or file lists. JSON defaults to 20 results per the help, and supports `-n` and `--min-score`. The JSON implementation passes 300 characters to snippet extraction, with the returned title, path, optional context and metadata outside that window. `--full` emits document text instead. The MCP `query` defaults to 10 results and accepts a result limit, a rerank candidate limit, collection names, typed clauses or free text, and a metadata filter. MCP also exposes `get`, `multi_get`, `status` and `metadata`, with stdio and HTTP transports. These knobs constrain parts of a response, so pbrain needs a separate budget for its whole payload. [CLI options](https://github.com/tobi/qmd/blob/v2.9.0/README.md#options) · [JSON output code](https://github.com/tobi/qmd/blob/v2.9.0/src/cli/qmd.ts#L2836-L2863) · [MCP tool schema](https://github.com/tobi/qmd/blob/v2.9.0/src/mcp/server.ts#L394-L432)
- CLI and MCP `get` accept virtual paths or short ids and line windows. The short id is the first six hex characters of the content hash. An edit can change it and identical content or a hash-prefix collision resolves to the first active match. Path lookup also has a suffix fallback. A pbrain-facing adapter should retain pbrain's stable id and exact lookup against current source files. [Docid resolution](https://github.com/tobi/qmd/blob/v2.9.0/src/store.ts#L4493-L4521) · [Path resolution](https://github.com/tobi/qmd/blob/v2.9.0/src/store.ts#L6242-L6329) · [Get examples](https://github.com/tobi/qmd/blob/v2.9.0/README.md#retrieving-documents)
- Folder scope comes from the collection root and configured globs, selectable by collection name. Path contexts are descriptions. Excluding a collection from default search leaves it selectable by explicitly naming it, so a private collection in a shared DB is reachable. qmd indexing uses its own glob and ignore configuration. A smoke test below confirms Git ignore rules alone leave matching files indexable. [Collection scope](https://github.com/tobi/qmd/blob/v2.9.0/README.md#collection-filtering) · [Glob implementation](https://github.com/tobi/qmd/blob/v2.9.0/src/cli/qmd.ts#L2216-L2229)
- Release 2.9.0 indexes typed `qmd.metadata` within YAML front matter and exposes the same predicate tree through CLI, SDK, MCP and HTTP. Ordinary fields are still searchable as text. Scalar and homogeneous flat array types are supported, including an explicit existence predicate. Old indexes need `update` to backfill. Invalid opt-in metadata keeps the document lexically searchable without a filter but excludes it from filtered search. qmd has no pbrain-specific interpretation of ordinary `status`, authority or supersession links. [Filtering docs](https://github.com/tobi/qmd/blob/v2.9.0/README.md#metadata-filtering) · [Extractor](https://github.com/tobi/qmd/blob/v2.9.0/src/metadata.ts) · [Release](https://github.com/tobi/qmd/releases/tag/v2.9.0)

The tagged README still describes post-filtered global top-K for collections and a 20,000-vector cutoff for exact metadata scope. The tagged implementation materializes the full scoped FTS match set before applying the limit and passes metadata eligibility into the sqlite-vec scan. Vector scan targets merge at the document level. Structured and hybrid search still bound each leg and the fusion candidate window, and the search body cap can displace a snippet for a hit past the first 262,144 characters. Use the release and tagged implementation for these guarantees. The README diagrams also show 30 rerank candidates, while the code's default is 40. ## Implication for pbrain

Recommendation: expose a pbrain-owned lexical search and exact lookup by default. qmd can already serve as an optional local reader over a dedicated public corpus with zero model downloads. Keep pbrain ids, authority, supersession, provenance and byte or token budgets in pbrain. If qmd later becomes a candidate backend, authorize its collection root before indexing, use dedicated shared cache files, resolve hits against live pbrain items, apply lifecycle policy before the final limit, and render a bounded payload. A bounded overfetch followed by filtering can underfill even when eligible results exist. For filter pushdown without changing legacy notes, evaluate a generated allowlisted corpus or a 2.9.0 processor projecting pbrain's effective status into `qmd.metadata`, then test update ordering and stale-index failure. Keep private material out of the shared qmd cache and out of remote provider requests. Features like raw `get`, metadata discovery and wider qmd config make exposing qmd directly a different interface from exposing pbrain.
