# Converter capabilities and fidelity

Checked 2026-11-19. The decision is which adapter to use for each source class and where conversion happens. For pbrain, fetching and conversion should be separate operations so it can record the exact source bytes, cap inputs and choose an offline parser. [pbrain ingestion proposal](https://github.com/pkieltyka/factory/issues/62)

| Converter | Trade-off for pbrain |
| --- | --- |
| [Trafilatura 2.3.1](https://github.com/adbar/trafilatura/releases/tag/v2.3.1) | Python/lxml article extractor. Accepts already-fetched HTML and emits Markdown with configurable links, tables, comments, metadata and precision/recall preferences. Its rules fall back to readability and jusText. Good candidate when Python fits and article extraction is the priority. |
| [Defuddle 0.19.7](https://www.npmjs.com/package/defuddle/v/0.19.7) | Node or browser DOM extractor. The Node entry accepts a DOM from JSDOM or linkedom with a base URL, and can emit Markdown plus extracted metadata. The CLI handles URLs, files or stdin. Good candidate when JavaScript fits and retaining structured content matters. |
| [Mozilla Readability 0.6.0](https://github.com/mozilla/readability/tree/0.6.0) | Article extraction built for Firefox Reader View. Returns cleaned HTML, text and article metadata. A server-side caller supplies a DOM with scripts and resource loading disabled, plus an HTML-to-Markdown writer. The project recommends a sanitizer for untrusted HTML when rendering output. |
| [MarkItDown 0.1.9](https://github.com/microsoft/markitdown/tree/v0.1.9) | Python and optional format extras, including PDF and common Office types. It aims to preserve useful structure for text analysis. Local streams or files work without a cloud provider for supported local converters. Image captioning, speech transcription and several Azure paths use external services. Its widest import method accepts local and remote URIs, so use the narrow stream or local method with explicit options. |
| [Pandoc](https://pandoc.org/MANUAL.html) | General CLI for structural HTML, DOCX and many markup formats. Reads stdin, writes chosen Markdown dialects and documents lossy structure such as complex tables. It does not promise main-content extraction and PDF is an output format. Its security guide recommends sandbox mode for untrusted HTML and warns that separate filters and PDF engines have their own privilege boundaries. |
| [Jina Reader](https://github.com/jina-ai/reader/blob/1574bfd380d249c86c82db4dace0d9c8fe17e2b1/README.md) | Hosted URL-to-Markdown API, with browser and lightweight fetch engines, cache policy, selector waiting and optional heading/block splitting. The URL is sent to Jina. Optional image descriptions are model-generated, and the response need not expose the origin bytes. The open-source self-host route trades that exposure for operating a browser and document-conversion stack. Optional use for public pages only would keep it outside pbrain's baseline. |

The tools handle different layers. A parser can serialize a static document while losing article content or page context. A content extractor can remove navigation while also removing a meaningful section. Markdown itself cannot faithfully represent every layout. Compare candidate outputs on the actual pages pbrain users want and record converter name and version. [Trafilatura extraction options](https://trafilatura.readthedocs.io/en/latest/usage-python.html) · [Defuddle input/output](https://github.com/kepano/defuddle#nodejs) · [Pandoc conversion model](https://pandoc.org/MANUAL.html#description)

## Observed on synthetic local fixtures

A short static HTML article contained a title, heading, relative link, code block, two-column table, and distinct navigation/footer markers. A second HTML input contained a loading placeholder and a script that would replace it in a browser. Tested against Node 26.13.1, Python 3.13 and Pandoc 3.7.0.2 on Linux using local input. Comparison used the same page base directory when each API supported passing it. This is a fixture comparison and leaves production quality open. [Readability DOM usage](https://github.com/mozilla/readability#usage) · [Defuddle Node usage](https://github.com/kepano/defuddle#nodejs) · [Trafilatura Python API](https://trafilatura.readthedocs.io/en/latest/usage-python.html)

| Tool | Static article | JS shell |
| --- | --- | --- |
| Defuddle 0.19.7 with JSDOM | Dropped nav/footer and body H1, retained subheading, fenced code and table. Resolved the relative link beneath the page's directory. | Loading text. |
| Mozilla Readability 0.6.0 with JSDOM | Dropped nav/footer and body H1 in its HTML result, retained table and code and correctly expanded the relative link. Markdown requires a separate writer. | Loading text in HTML. |
| Trafilatura 2.3.1 | Dropped nav/footer, kept headings and table, rendered the one-line code as inline code. For this input it expanded the relative link at origin root instead of the page directory. Verify or normalize links before extraction. | Loading text. |
| Pandoc 3.7.0.2, HTML to GFM in sandbox | Dropped the fixture's nav/footer, kept headings and table, rendered indented code, and left the link relative. Its behavior on other page furniture was outside the test. | Loading text inside a div. |
| MarkItDown 0.1.9 | Kept the fixture's nav/footer, headings, fenced code and table, and left the link relative. Its ONNX dependency initially failed to load on this Nix host until the installed C++ runtime was added to the process library path. | Loading text. |

A public Jina Reader request for example.com succeeded and emitted Markdown plus a source URL and reported publication time. No origin bytes came back in that response. This confirms the interface only. Use pbrain's actual acquisition time and distinguish provider-returned content from a direct original. The API docs describe cache controls and optional browser rendering. ## Authenticated and rendered pages

Use a provider export or an explicit user-supplied file first. A browser is justified when needed content exists only after rendering or requires interaction in a user-approved session. Playwright can drive a separately provisioned browser, wait for specific content and capture a download or a rendered DOM. Its authentication state can contain impersonating cookies and headers. Keep it outside the project, use a dedicated context, hand only the selected artifact to the normalizer and preserve the acquisition method. Agent browser tools can help the owner acquire a file manually, but should remain optional and carry the same data boundary. An empty/static loading shell is a conversion failure for this use case. [Playwright browser provisioning](https://playwright.dev/docs/browsers) · [Authentication state](https://playwright.dev/docs/auth#core-concepts) · [Downloads](https://playwright.dev/docs/downloads)

## PDF and transcripts

Try a separate text-PDF adapter only when a real corpus requires it. Poppler's `pdftotext` supports page ranges and a layout option. On Poppler 26.11.0, a synthetic one-page text PDF yielded the expected text and a form feed. A drawn page with no text layer yielded only a form feed with a successful process exit. Check for meaningful output and preserve page locators. Column ordering, tables, footnotes and ligatures need representative fixtures. OCRmyPDF can add an OCR layer to scans and needs its own dependencies, language selection and quality validation. Markdown shortcuts do not recover layout or establish fidelity. [Poppler CLI manual](https://manpages.debian.org/unstable/poppler-utils/pdftotext.1.en.html) · [OCRmyPDF](https://github.com/ocrmypdf/OCRmyPDF) · [MarkItDown format extras](https://github.com/microsoft/markitdown/tree/v0.1.9)

For local text transcripts, preserve speaker names, time ranges and natural turn boundaries when already present. Keep source labels for auto-transcription and generated notes, and leave audio transcription to a later adapter. If a transcript exceeds the first importer limit, return a size error suggesting an excerpt. A later sectioning adapter can split by heading, speaker turn, timestamp or page while preserving a common source/version id and locators.
