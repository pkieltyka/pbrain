# Provenance and the first importer

Recommendation for the first ingestion release, which can follow the draft's initial Markdown-store milestone. Start with explicit local Markdown and plain-text files, including Google Docs Markdown exports and transcripts. If the first ingestion release needs URLs, add direct public HTTPS responses with a local, stack-appropriate static HTML extractor. This covers common sourced references without running a browser or an authentication broker inside pbrain. Use the same normalized representation across input types and accept a link-only reference for unsupported pages or material that cannot be retained. [Draft project overview](../../../project_overview.md) · [Initial milestone and import proposal](https://github.com/pkieltyka/factory/issues/62) · [Docs Markdown export](https://support.google.com/docs/answer/12014036?hl=en)

## Import transaction and record

1. The owner explicitly identifies a source and its destination audience. Accept a local regular file or a direct supported public URL. Acquire a single bounded artifact. For URLs, validate the destination and each redirect, use no ambient browser cookies or credentials, and disallow private-network or loopback destinations on the public fetch path. Keep DNS and connection checks together. For types or encodings outside the supported set, return a clear action such as exporting as UTF-8 Markdown. [OWASP request boundary guidance](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html) · [Project privacy proposal](https://github.com/pkieltyka/factory/issues/62)
2. Record the user-supplied source locator and final fetch locator when different, acquisition time in UTC, source media type and byte length, the byte digest of the exact acquired input, and how it was acquired or converted. An original hash should cover the bytes passed to the converter, after HTTP transport/content decoding if that is what the client supplies. Identify this policy so repeat hashes have the same meaning. Optionally record a separate normalized-body digest for change detection, source title/author or license if known, and exposed validators or provider document/version ids. A local export can keep its origin URL and an operator-supplied export time, while the importer records its own import time. Avoid putting local absolute paths, signed URLs, sensitive identifiers, cookies or bearer tokens into durable shared provenance. [HTTP selected representations and validators](https://www.rfc-editor.org/rfc/rfc9110.html#section-8.8) · [Drive version and checksum fields](https://developers.google.com/workspace/drive/api/reference/rest/v3/files) · [Factory privacy boundary](https://github.com/pkieltyka/factory/issues/62)
3. Normalize deterministically to UTF-8 Markdown, retaining useful headings, links and transcript or page locators. Resolve relative links against the actual fetched URL before losing that context and strip or neutralize active markup, embedded remote resources and unsafe URL schemes as appropriate to the renderer. Generate pbrain metadata separately. An external YAML header, downloaded title or converter output cannot assign pbrain status, privacy or authority. Treat the body as a reference from an external source throughout. [Readability and base URL](https://github.com/mozilla/readability#usage) · [Pandoc input/output security](https://pandoc.org/MANUAL.html#a-note-on-security) · [OWASP guidance on remote document content](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html#remoteindirect-prompt-injection)
4. After a successful conversion, publish one reference atomically. Preserve the previous reference on a missing, denied, unsupported or failed refresh. If original-byte retention is enabled, store the blob first by content digest in a separate local cache with the same audience boundary. A failed publish can leave an unreferenced cache object eligible for cleanup. Shared Markdown remains readable without that cache. Where the source or permission does not allow retention, record the link or an authorized excerpt and avoid retaining the body. [Factory import and cache proposal](https://github.com/pkieltyka/factory/issues/62) · [Git history and external copies](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository#about-sensitive-data-exposure) · [Google API Terms §5(e)](https://developers.google.com/terms#e-prohibitions-on-content)

## Refresh and change detection

Use explicit refresh. If practical, conditional GET can avoid downloading unchanged material. Pair the saved HTTP validators with the same representation, final origin and request profile. Send `If-None-Match` with a known ETag, otherwise `If-Modified-Since` with known Last-Modified. A 304 updates the check log or metadata without overwriting the body or its acquisition timestamp. A successful body with the same raw digest is another unchanged result for a fixed converter version. Changed raw bytes may be presentation churn with a stable normalized digest. Do not advertise a content change or rewrite the note's body just because the site changed layout. Converter changes warrant deliberate reprocessing from the cached bytes or a new authorized fetch. Google Docs export uses file metadata as a hint and compares exported bytes. Omit background refresh and scheduled crawling until users need them. [RFC 9110 conditional requests](https://www.rfc-editor.org/rfc/rfc9110.html#section-13) · [RFC 9111 validation](https://www.rfc-editor.org/rfc/rfc9111.html#section-4.3) · [Drive file metadata](https://developers.google.com/workspace/drive/api/reference/rest/v3/files)

A retrieval error and a verified change have different meaning. Leave the last successful version available with its original source date and surface the latest refresh error. Never silently switch between a direct origin payload, a remote extractor's response and an authenticated export under the same method label. [HTTP caching and validation model](https://www.rfc-editor.org/rfc/rfc9111.html#section-4.3) · [Jina cache and engine options](https://github.com/jina-ai/reader/blob/1574bfd380d249c86c82db4dace0d9c8fe17e2b1/README.md)

## Limits, trust and retention

- **Size and segmentation.** Put independent limits on network bytes, decoded input, converter time and normalized output. Example first-pass product defaults for fixture evaluation are 5 MiB decoded input and 512 KiB normalized Markdown, with a bounded total request time. These are proposals and should be checked against meeting lengths and real docs. Fail clearly rather than silently truncating. One successful add writes one reference. Defer automatic splitting. When needed, preserve common source/version identity and split at headings, pages or speaker turns with explicit locators. [Drive export limit](https://developers.google.com/workspace/drive/api/reference/rest/v3/files/export) · [Reader segmentation options](https://github.com/jina-ai/reader/blob/1574bfd380d249c86c82db4dace0d9c8fe17e2b1/README.md)
- **Handling untrusted content.** Use offline deterministic parsing with narrow input types. Content can contain malicious prose even after stripping scripts and unsafe markup. Present imported text as quoted or typed source data, and derive pbrain rules from the trusted command and repository policy. Imported prose cannot authorize tool calls or promotion to a decision. Keep converter credentials and any browser or API auth out of its subprocess environment, caches and output. [OWASP indirect injection and structured separation](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html) · [MarkItDown narrow conversion guidance](https://github.com/microsoft/markitdown/tree/v0.1.9)
- **Original caching.** A public URL or ability to open a document establishes access. Consider the source's license, sharing grant, confidentiality and terms before retaining original bytes or publishing normalized copies. Creative Commons licenses may impose attribution and other terms, and statutory exceptions differ by jurisdiction and purpose. Retain source attribution and license evidence when available. Treat `Cache-Control: no-store` as a reason to avoid automatic raw HTTP caching, with durable editorial copies governed by the source's policy and authorization. Private source caches should be local and excluded from Git, subject to explicit retention or purge. Git history may survive in clones after removal. [Creative Commons licenses](https://creativecommons.org/cc-licenses/) · [U.S. Copyright Office factors](https://www.copyright.gov/fair-use/) · [Canada Copyright Act fair dealing](https://laws-lois.justice.gc.ca/eng/acts/C-42/page-6.html#h-103169) · [HTTP no-store](https://www.rfc-editor.org/rfc/rfc9111.html#section-5.2.2.5) · [GitHub history guidance](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository#about-sensitive-data-exposure)

## Decisions for the spec

- Prioritize the local-file path and a documented Google Docs manual export. If public URL import is part of the first ingestion release, keep it direct and static. Pick a converter with measured article, code, link and table behavior once pbrain's runtime is chosen. [Converter comparison](./converters-and-fidelity.md)
- Adopt an optional, local cache for allowed original copies. Default to retaining only authorized normalized material and provenance until the owner decides the cache retention and permissions. Provide a reference-only option for material unsuitable for copying. [Factory open cache decision](https://github.com/pkieltyka/factory/issues/62) · [Source rights and policy](https://developers.google.com/terms#e-prohibitions-on-content)
- Defer managed Google OAuth, Meet event/discovery calls, browser automation, hosted extractors, image/audio models, OCR, bulk refresh and automatic sectioning. Test the first agreed adapter with changed and unchanged source bodies, broken conversion, size limits, access denial and a reference containing instructions addressed to an agent. [Google scope options](https://developers.google.com/workspace/drive/api/guides/api-specific-auth) · [Playwright browser and auth requirements](https://playwright.dev/docs/auth) · [Open questions in the draft](../../../project_overview.md)
