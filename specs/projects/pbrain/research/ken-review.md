# What pbrain can learn from ken

**Keep ken as a separate tool for finding code. Borrow its way of testing whether the agent actually sees the evidence.** An agent could use pbrain to find the decision to retry a job, then use ken to locate the implementation and its callers. That workflow needs no integration. Neither ken’s index nor its ranking supplies pbrain’s knowledge or privacy semantics.

## What was reviewed

Francis Townsend-Merino’s MIT-licensed ken is a pure-Go code-search CLI, MCP server and Go library. It began as a port of Semble. At the reviewed commit, `2d21e3d` (19 November 2026), Git showed 765 commits since 20 May, 715 under the author’s name and 50 from Dependabot. The newest of 52 tags was v1.20.0, tagged 18 November. It has CI, tagged releases and published retrieval evaluations. It is actively maintained, with six months of history and concentrated human maintenance. I cloned the repository into scratch and read the source and benchmark reports. I did not build ken, start its server, download models or reproduce its measurements. [Reviewed source](https://github.com/townsendmerino/ken/blob/2d21e3d44ad3d3d114562ba031d0029cee669b70/engine/engine.go) · [Licence](https://github.com/townsendmerino/ken/blob/2d21e3d44ad3d3d114562ba031d0029cee669b70/LICENSE) · [Release](https://github.com/townsendmerino/ken/releases/tag/v1.20.0)

The module is `github.com/townsendmerino/ken`, with a Go 1.27.4 minimum. It directly requires aikit v1.77.0, the separate aikit tree-sitter chunker and modernc SQLite, among other dependencies. Its hybrid search actually calls aikit’s BM25 and fusion packages. There is no goinfer dependency in its module manifest or checksums. The shared author and toolkit do not make ken an EmbeddingGemma 2 or BERT runtime. Ken’s default semantic path uses the small, code-trained Model2Vec model; pbrain already has its direct aikit and goinfer adapter designs. ## Where the designs differ

| Question | Ken | Consequence for pbrain |
|---|---|---|
| What is stored and cited? | A workspace indexes chunks of repository files, supports persisted snapshots and refresh/watch, and can cache embeddings by content in SQLite. A hit carries source lines, a text hash and, for Markdown, a heading path. | Git-tracked Markdown items carry author, standing, source and replacement history. A linked item may disclose only a pointer and short summary. A search scope or ignore file cannot substitute for the personal exposure guard. Keep lexical reads live and build each section’s derived semantic index explicitly. [Workspace](https://github.com/townsendmerino/ken/blob/2d21e3d44ad3d3d114562ba031d0029cee669b70/engine/engine.go) · [Vector cache](https://github.com/townsendmerino/ken/blob/2d21e3d44ad3d3d114562ba031d0029cee669b70/internal/embedcache/embedcache.go) · [pbrain §§2–5, 9.4](../functional_spec.md) |
| What makes a result important? | Ken combines semantic and BM25 ranks using weighted reciprocal-rank fusion, then applies code-specific signals such as path penalties and same-file saturation. Its related lookup finds similar chunks. | A similar note cannot establish that a decision is in force. Keep exact results and decision promotion first, followed on request by semantic and marked partial results. Explicit item links convey relationships; each enabled search mode has to demonstrate abstention. [Fusion and boosts](https://github.com/townsendmerino/ken/blob/2d21e3d44ad3d3d114562ba031d0029cee669b70/internal/search/hybrid.go) · [Related hits](https://github.com/townsendmerino/ken/blob/2d21e3d44ad3d3d114562ba031d0029cee669b70/engine/search.go) · [pbrain §§4.5, 7.1, 16](../functional_spec.md) |
| What fits in the agent’s context? | Ken’s library returns top-*k* chunks. Its benchmark token packer always keeps the first chunk, even when that chunk exceeds the budget. This is a benchmark rule. | Pbrain counts the complete rendered answer, including citations and paging. A too-small budget returns the minimum that works. Keep the strict cap and measure the cost through the follow-up `get`. ## Proposals for the owner

- **Adopt for evaluation.** On long-document fixture questions, record both “correct item retrieved” and “supporting passage actually visible.” Report the fraction reaching evidence and the tokens through first evidence, including follow-up reads. Show misses separately so a faster average on successful queries cannot conceal them. In ken’s published 500-task run at 8,192 tokens, hybrid reached a relevant line on 252 tasks versus 217 for BM25, yet averaged **15.9% line coverage versus 18.5%**. Finding the file and covering the evidence can move in opposite directions. Those figures describe code retrieval. They justify a measurement for pbrain, not a ranking change. [Ken benchmark and caveats](https://github.com/townsendmerino/ken/blob/2d21e3d44ad3d3d114562ba031d0029cee669b70/docs/BENCH.md#lite-results-n--500-mbp2-2026-10-2930) · [pbrain architecture §14](../architecture.md)
- **Borrow a test.** Ken checks that a Markdown chunk and its reported section agree even around fences and ambiguous headings. Give a pbrain fixture repeated heading names, a fenced pseudo-heading and multibyte text. Assert that a returned passage offset opens the same supporting text with `get` and falls inside the intended outline section. Use pbrain’s existing outline parser and code-point offsets. [Ken section tests](https://github.com/townsendmerino/ken/blob/2d21e3d44ad3d3d114562ba031d0029cee669b70/engine/sections_test.go) · [pbrain architecture §§7.4, 8.4, 8.7, 14](../architecture.md)
- **Ignore as a product dependency.** A watched MCP code index, similarity-based related items and fused ranking would duplicate the existing adapters while changing freshness, authority and output behavior. Keep ken available independently to agents that need symbol navigation. No pbrain command, configuration key or new model is needed. [Ken public API](https://github.com/townsendmerino/ken/blob/2d21e3d44ad3d3d114562ba031d0029cee669b70/engine/engine.go) · [pbrain §§7, 9, 12, 17](../functional_spec.md)
